# 多方式登录配置

企业管理员进入 **系统管理 → 登录方式设置**，按企业分别配置手机短信、邮箱验证码和微信扫码。M9 的页面和保存接口要求 `tenant:login_settings`。权限在角色权限矩阵的 **系统管理 / 登录方式设置** 下，可由已拥有对应权限的管理员授予。0.9.0 本机部署包仍使用 `role:assign_permission`。三种方式默认关闭，账号密码始终可用。

## 服务端准备

| 环境变量 | 配置方法 |
| --- | --- |
| `ERP_LOGIN_SETTINGS_KEY` | 用密码学安全随机数生成 32 字节，再编码为标准 Base64。所有连接同一环境数据库和 Redis 的 API 实例使用同一个值，开发、测试、生产各用独立的值。应用用它加密渠道凭据并保护验证码校验数据。 |
| `ERP_LOGIN_SMTP_ALLOWED_HOSTS` | 运维填写允许连接的 SMTP 主机名，以英文逗号分隔，例如 `smtp.example.com,smtp-backup.example.com`。按完整主机名匹配，端口另在后台填写。仅启用邮箱登录时需要。 |

本机开发可将变量放在项目根目录的私有 `.env`。在项目根目录用 PowerShell 7 执行以下命令可首次添加随机密钥，命令本身不会输出密钥。运行前按[部署说明](../运维/部署说明.md)准备好 `.env`。

```powershell
$loginEnv = [IO.File]::ReadAllLines((Resolve-Path -LiteralPath .env))
if (-not ($loginEnv -match '^ERP_LOGIN_SETTINGS_KEY=\s*\S')) {
    $loginSettingsKey = [Convert]::ToBase64String([System.Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
    $loginEnv = @($loginEnv -notmatch '^ERP_LOGIN_SETTINGS_KEY=') + "ERP_LOGIN_SETTINGS_KEY=$loginSettingsKey"
    Set-Content -LiteralPath .env -Encoding utf8NoBOM -Value $loginEnv
    Remove-Variable loginSettingsKey
}
Remove-Variable loginEnv
```

生产使用服务端的密钥管理或进程私有环境配置。使用随部署包提供的 Compose 模板时，在 `deploy/private/api.env` 配置变量后重新创建 API 容器。直接运行 JAR 的部署在注入变量后重启 API 进程。将加密密钥存入受限备份，以便恢复数据库时一并恢复对应的密钥。请勿在前端环境、截图、日志或 Git 中保存实际密钥。其他部署步骤见[运维手册](../运维/运维手册.md)。

有出站限制的环境需按启用渠道放行 API 到 `dysmsapi.aliyuncs.com:443`、微信换取令牌的 `api.weixin.qq.com:443` 或所选 SMTP 主机和端口。扫码授权页面 `open.weixin.qq.com` 由员工浏览器访问。使用 Redis ACL 时，在现有 Spring Session 权限基础上，给 API 账号增加 `erp:session:<APP_ENV>:login-code:*` 和 `erp:session:<APP_ENV>:wechat-state:*` 的键权限及对应的 `GET/SET/DEL/EXPIRE/INCR/HGET/HSET/HINCRBY/EVAL/EVALSHA` 操作。Spring Session 默认使用 `spring:session:*`，如部署已经自定义会话命名空间，沿用该命名空间的权限。

## 管理员配置渠道

在 **登录方式设置** 填写所需渠道，打开对应开关，再点击 **保存设置**。保存会校验必填项和格式，实际投递和授权结果在绑定环节核验。

### 手机短信

1. 在阿里云短信服务申请适用于国内短信的资质、签名和验证码模板。签名和模板都需审核通过，模板变量使用 `${code}`，并能接收 6 位数字字符串。准备同一阿里云账号下有 `dysms:SendSms` 调用权限的 RAM AccessKey。[阿里云验证码模板规范](https://help.aliyun.com/zh/sms/user-guide/verification-code-template-specifications/)、[SendSms 接口与 RAM 权限](https://help.aliyun.com/zh/sms/developer-reference/api-dysmsapi-2017-05-25-sendsms)
2. 在 **手机短信** 填写 **访问密钥 ID**、**访问密钥 Secret**、**短信签名** 和 **模板编号**。模板编号形如 `SMS_123456789`。当前渠道用于中国大陆手机号。

### 邮箱验证码

1. 运维将邮件服务商提供的 SMTP 主机名加入 `ERP_LOGIN_SMTP_ALLOWED_HOSTS`。确认 API 实例能访问该主机和所选端口，并信任其 TLS 证书。
2. 在 **邮箱验证码** 填写 **SMTP 服务器**、**端口**、**加密方式**、**发件邮箱**、**SMTP 用户名** 和 **SMTP 密码或授权码**。按服务商提供的参数填写。常见组合为 `587` + `STARTTLS`（页面默认）或 `465` + `TLS`（连接时直接启用 TLS）。发件地址须经 SMTP 账号授权。[SMTP 邮件提交的 TLS 规范](https://www.rfc-editor.org/rfc/rfc8314.html)、[Angus Mail SMTP 参数](https://eclipse-ee4j.github.io/angus-mail/docs/api/org.eclipse.angus.mail/org/eclipse/angus/mail/smtp/package-summary.html)

### 微信扫码

1. 在微信开放平台创建网站应用，完成应用审核并开通微信登录，取得网站应用的 `AppID` 和 `AppSecret`。在平台的授权回调域中登记 ERP 的公开站点域名。[微信开放平台网站应用微信登录指南](https://developers.weixin.qq.com/doc/oplatform/Website_App/WeChat_Login/Wechat_Login.html)
2. 在 **微信扫码** 填写 **微信 AppID**、**微信 AppSecret** 和 **授权回调地址**。如果 ERP 站点为 `https://erp.example.com`，填 `https://erp.example.com/api/v1/auth/wechat/callback`。回调使用与登录页同域名、同端口的 HTTPS 地址，路径固定为 `/api/v1/auth/wechat/callback`，末尾无需斜杠或附加参数。反向代理须保留对外站点的 `Host`，并将该路径转发到 API。

## 员工绑定与登录验收

1. 使用已有账号和密码登录，打开右上角账户菜单中的 **我的登录方式**。三种方式均从已有账户绑定开始，员工仍由管理员创建账号。原员工资料中的手机号需要在此重新完成验证码验证，才可用于登录。
2. 点击需要的 **绑定**。手机短信或邮箱须输入当前密码及本人控制的号码或邮箱，点击 **发送验证码**，收到后填写 6 位验证码并确认绑定。验证码有效期为 5 分钟，同企业、同渠道、同接收地址两次发送至少间隔 60 秒。微信须输入当前密码，点击 **前往微信扫码**，用手机微信扫码并确认授权，返回原浏览器查看绑定结果。
3. 退出登录，输入同一企业编码，选用刚绑定的方式。短信和邮箱应收到新的登录验证码，微信应扫码并回到 ERP。进入后核对显示的是原账户和原企业。随后可在 **我的登录方式** 使用当前密码更换或解除绑定，其中更换绑定仍需验证新手机、邮箱或微信身份。
4. 验收时可先用专用试运行账号逐个启用渠道。逐项确认能收到验证码或完成微信授权，并确认关闭渠道后登录页不再提供该选项。当前尚未使用真实阿里云、SMTP 或微信凭据完成外部联调，真实到达与授权回跳以此验收结果为准。

## 凭据更换

M10 使用 HKDF-SHA256 从原 `ERP_LOGIN_SETTINGS_KEY` 派生加密与验证码两把子密钥。配置密文前缀为 `2.`，历史 `1.` 密文仍可解密，成功使用后按原密文和版本条件转存为新密文。存储格式迁移保持管理员配置版本，管理员并发保存优先。停用的旧配置在后续成功使用时迁移，主密钥继续纳入私有备份。派生算法依据 RFC 5869，测试使用其中的公开向量。[HKDF 规范](https://www.rfc-editor.org/rfc/rfc5869)

同一环境的 API 节点在同一维护窗口升级，以便统一验证码摘要算法。升级前已发送的短信、邮箱验证码需重新获取，原有 60 秒发送间隔继续生效。回退到旧代码前恢复升级前数据库中的渠道密文，当前应用已经转存的 `2.` 密文需要使用新版本读取。

- 渠道密钥在页面上只显示配置状态。留空保存会保留原凭据。更换阿里云 AccessKey、SMTP 密码或微信 AppSecret 时，在相应栏输入新凭据，必要时同步更改 ID 或用户名，再保存并重做实际绑定或登录验收。切换到新的微信网站应用（`AppID` 改变）后，员工需重新扫码绑定。
- `ERP_LOGIN_SETTINGS_KEY` 用于读取数据库里所有已加密的渠道凭据，系统只有一个有效密钥。需要更换时先保留旧密钥、准备各企业的渠道凭据，并安排维护窗口。先关闭各企业的短信、邮箱和微信渠道，再统一更新所有 API 实例的密钥并重新加载。管理员用账号密码登录，逐项重新输入渠道凭据并启用。旧密钥对应的短信和邮箱验证码须重新获取。
