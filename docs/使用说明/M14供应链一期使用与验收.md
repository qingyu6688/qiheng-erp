# M14 供应链一期使用与验收

计划版本为 1.7.0。升级在 MySQL 8.0.46 上追加 Flyway V65 至 V78。先备份主库和私有附件，再升级 API 与 Worker。对外发布需单独确认版本号、迁移窗口及数电服务商。

## 从来料到发货

1. 在「基础资料 → 库区库位」选择仓库，建收货、发货和待检库区与库位。设置默认收货、发货库位后启用库位管理。首次启用会把已有存量登记到默认收货库位，仓级数量与成本不变。有未结预留或待检冻结时，先完成对应业务。
2. 在「基础资料 → 品牌」维护品牌，从 SKU 列表打开「供应链设置」，配置品牌、重量、批次、序列号、保质期、临期提前量和出库策略。变更跟踪开关前须清空该 SKU 在本企业各仓的库存及预留，并处理在途序列号及借出未还。
3. 在「库存 → 来料质检」建检验项目、模板和 SKU 规则。可指定供应商规则，也可设置全部供应商的缺省规则。采购收货行登记同一批次的批号及生产日期，若需要质检，过账后在待检库位形成在库及等额冻结。
4. 检验员录入采样值、合格、让步与不合格数量并提交。由另一人审核。合格和经批准让步的数量解除质检冻结，不合格数量仍冻结，可生成采购退货或报废草稿，也可发起复检。
5. 销售订单仍按仓库与 SKU 预留。发货单提交时占用实物批次及库位。默认按收货顺序或近效期选择，也可显式选择满足要求的批次。过期批次不能用于普通出库。逐个序列号记录去向。客户签收后，可从「批次与序列号」按批次、序列号或客户回查。

复测近效期策略时，先收效期远的批次，再收临期批次，确认发货先用临期的可用批次。端到端来料样例使用同批次的两笔收货。对第一笔做部分合格、部分退货，核对第二笔仍保持冻结。正向核对供应商、采购收货、质检、入库库位、发货、客户，反向从客户查签收的批号与序列号。

### 库存处理口径

- 批次和库位只改变实物坐标。仓库与 SKU 的汇总用来预留和查询，过账流水按实际坐标只写一笔。成本继续按仓库与 SKU 移动加权。
- 一条发货行对应一个批次与库位。相同订单行跨多个批次发货时拆为多张发货单。序列号管理的收货行应按同一检验结论分行或分单，审核时只放行已确认的序列号。
- 近效期提醒通过站内信发送。自动冻结追加来源为 `batch_expiry` 的库存流水及冻结原因明细。期间关闭时待重新开放后补记，出库命令仍会直接检查效期。
- 已有仓库可批量生成库位并打印 Code 128 标签。库位配置限制容量、混放和启停。实时库存提供按批次、按库位入口，库存、采购、销售、毛利报表提供品牌汇总。
- 其他出入库使用独立单据和复核流程，可登记赠品、样品、借出、归还及内部领用，过账后用单据冲销纠正。借出未归还的数据从其他出库查询。

## 权限与对账

批次、库位、检验单及出入库业务由服务端核对当前企业、公司、仓库及相关单据的部门范围。品牌和 SKU 跟踪配置为企业主数据。为自定义角色分别授权查阅、维护、提交、审核与过账。只读角色通过打印与追溯入口仍须满足资源的数据范围。

「财务期间 → 供应链对账」使用已有对账任务，覆盖批次及序列号数量、冻结原因和库位余额。操作人需要整家公司仓库与部门权限。启用库位前的实际库存由库位期初记录提供对账起点。三项检查也参与关账校验。期末待审核或已审核未过账的其他出入库会阻止关账。

## 数电发票

「资金与往来 → 数电发票」从已签收应收创建请求，使用购买方信息与 SKU 税收分类编码。Worker 处理结果查询、补偿、版式文件及进项同步。红字结果由服务商返回后冲红原登记，进项匹配由财务复核确认。[数电发票服务商对接说明](数电发票服务商对接说明.md)

本机测试使用受控服务商替身。生产部署需要指定合作服务商、接通网关并验证票号及版式文件、红字开具、进项同步和失败恢复。

## 本机复测命令

在仓库根目录通过 `ERP_PROJECT_SETTINGS_FILE` 指向私有测试配置，运行 `pwsh -File scripts/project.ps1 verify`。在 `erp-web` 运行 `npm test`、`npm run lint` 和 `npm run build`。浏览器验收回到仓库根目录执行 `pwsh -File scripts/project.ps1 e2e`，脚本使用隔离测试库及随机企业。
