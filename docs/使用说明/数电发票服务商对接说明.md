# 数电发票服务商对接说明

## 部署与权限

ERP 通过运维配置的 HTTPS 网关调用具备资质的数电发票服务商。部署环境设置 `ERP_EINVOICE_GATEWAY_URL` 为固定网关地址，并沿用 `ERP_LOGIN_SETTINGS_KEY` 加密各公司的网关密钥。地址适用于整个应用，销方识别号、启用状态和访问密钥按企业与公司单独保存。网关应验证密钥所绑定的销方识别号。配置页面保存后可立即测试连接，凭据更新可留空保留原值。

本地启动时从项目根目录 `.env` 加载该变量。Docker Compose 部署从 `deploy/private/api.env` 和 `deploy/private/worker.env` 分别加载，systemd 部署从相应的私有环境文件加载。参照 `deploy/production.env.example` 为 API 与 Worker 写入相同网关地址和主密钥。默认空地址会停用网关调用。

| 权限 | 用途 |
| --- | --- |
| `einv:view` | 进入数电发票和查看范围内申请 |
| `einv:create` | 查询符合条件的应收并创建开具申请 |
| `einv:submit` | 复核并提交其他人员创建的开具申请 |
| `einv:red_issue` | 在已开具发票上申请红冲 |
| `einv:download` | 下载范围内已归档的原票和红字版式 |
| `einv:inbound` | 同步、查看进项和确认采购应付关联，要求当前公司全仓库及全组织范围 |
| `einv:manage` | 维护与测试服务商配置，要求当前公司全仓库及全组织范围。查询或编辑企业共享商品的税码还需 `sku:view` 或 `sku:update` |

## ERP 操作

1. 在财务的数电发票页面维护商品税码，选择客户和已签收、尚未开票的应收。申请的价税金额取应收确认值，商品单位取发货单，税率取订单行快照。
2. 由另一位有确认权限的人员提交，系统登记待处理开票关联并预占对应应收开票额度。服务商确认失败时释放额度。请求超时或结果待定时继续查询，等待期间保留额度。
3. 开具成功后，登记写回实际发票号码和发票日期，版式文件由后台任务存入私有对象仓。已开具发票需提交红字原因，收到红字开具成功结果后，ERP 作废原登记并释放原开票额度。
4. 进项台账每天按上海时间滚动同步最近三十天，可手工补同步其他日期，每次最多三十天、两千张。匹配候选为同一公司下税号、价税合计和税额均一致的已过账收货应付。财务人工确认一对一关联，勾选状态读取服务商结果。

## HTTPS 网关协议

请求包含 `Authorization: Bearer <按公司配置的访问密钥>` 和 `X-Seller-Tax-No: <销方纳税人识别号>`。JSON 请求使用 `Content-Type: application/json`，完整响应上限为 4 MiB。开具请求期限为 8 秒，超时按待确认处理。网关需要在转发开票动作前持久化且按销方去重相同的请求键，支持查询已受理的相同请求，避免网络中断或进程重启后重复开票。

| 方法及网关路径 | 请求与响应 |
| --- | --- |
| `GET /health` | 用当前公司的鉴权头测试连接，返回 HTTP 200 |
| `GET /requests/{requestKey}` | 查询请求。未知时用 HTTP 200 返回 `status=NOT_FOUND` |
| `POST /issue/{requestKey}` | 发票类型 `invoiceKind`、购方 `buyerName` 和 `buyerTaxNo`、`amount`、`taxAmount`、`lines`。明细包含 `goodsName`、`taxCategoryCode`、`spec`、`unitName`、`quantity`、`untaxedAmount`、`taxAmount`、`taxRate`、`unitPrice` |
| `POST /red-issue/{requestKey}` | 提交原票 `invoiceNo` 和红字 `reason` |
| `GET /files/{invoiceNo}/{format}` | PDF、OFD 或 XML 的文件字节。HTTP 404 表示服务商不提供该版式，尚在生成时返回暂不可用状态供 ERP 重试 |
| `GET /inbound?from=YYYY-MM-DD&to=YYYY-MM-DD` | 进项 JSON 数组，字段为 `invoiceNo`、`sellerName`、`sellerTaxNo`、`invoiceDate`、`amount`、`taxAmount`、`status`、`checked`。状态取 `normal`、`voided` 或 `red_issued` |

开具与红字响应的 `status` 取 `PENDING`、`ISSUED` 或 `FAILED`。`ISSUED` 必须带 `invoiceNo` 和 `issuedDate`。`FAILED` 仅用于服务商明确拒绝且该请求键不会再开具发票的情况。网关查询必须明确区分未知请求和暂时不可用。

上线前应用合同选定的网关或适配器接入服务商沙箱，用对应销方账号验证普通发票、专用发票、红字申请、版式和进项同步。仓库内的集成测试使用受控服务商替身验证响应丢失、拒绝、两人确认、跨租户访问和红冲后的状态一致性。
