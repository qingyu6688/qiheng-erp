# M15 智能查数使用与验收

本轮交付 A-02，计划版本为 1.8.0。助手按当前公司的登录权限查询 ERP。单据解释和 AI 录单按后续迭代实施。

## 配置

1. 同时部署 ERP API 和 AI 服务。AI 库执行 V4 评测迁移。ERP API 与 AI 服务使用同一份私有 `ERP_AI_SIGNING_KEY`，AI 服务的 `ERP_AI_ERP_ORIGIN` 指向可信 ERP 内网地址。
2. 在「AI 与知识 → AI 管理」选择已有的对话模型并配置 `kb_chat` 路由。在运行环境设置允许的模型端点。查数只向模型提供问题、上海时区日期以及当前可用的工具定义。
3. 在助手配置中显式选中允许的只读工具。员工需要 `ai:use`、助手的角色授权以及该工具对应的 ERP 查询权限。仓库范围与部门范围在 ERP 端实时计算，成本按原权限显示。
4. 员工打开顶栏 AI 助手，选择「智能查数」，输入业务对象和日期。多个候选时用编码补充问题。金额及数量以 ERP 提供的字符串显示，来源链接保留报表筛选条件。

## 可查询内容

| 工具 | 查询条件及口径 |
| --- | --- |
| 应收余额、应付余额 | 客户或供应商名称、编码及截止日，取对应账龄报表。 |
| 实时可用库存 | 商品名称、SKU 编码或条码，可限仓。返回当前可用量。 |
| 销售订单进度、采购订单进度 | 精确单号，或供应商、客户与日期组合。来源是原单据筛选和详情。 |
| 销售汇总、毛利 | 日期范围，可按客户、商品、业务员或部门汇总。毛利需成本权限。 |
| 资金余额 | 资金账户和截止日，对应资金日记账期末余额，包括仅有期初的日期。 |
| 单据查询 | 现有单据类型、关键字、状态和日期区间，复用单据浏览的权限。 |

应收、应付和资金账户报表要求整家公司仓库范围。部门受限时，账龄按原报表的单据归属筛选。为避免旧结果泄露，业务结果只展示在本次会话流中。重新打开历史时，可看到本次查询发生过，原始数据需再次查询。

## 接口和审计

- AI 消息保持 `POST /ai/v1/conversations/{id}/messages`。查数发送 `{ "content": "…", "toolCode": "auto" }`，服务端审核最多五个工具调用。流式响应通过独立的 `tool_result` 事件提供 ERP 查询结果。
- ERP 内部入口采用 `POST /api/v1/ai-tools/query/{toolCode}`。签名绑定方法、路径、原会话、公司、一次性随机值及请求体摘要，仍验证 CSRF。工具参数只接受已登记的类型和字段。请求体无法指定企业、公司、接口、SQL 或写入动作。
- 每个查询再按业务权限和范围执行。发送结果前重新验证会话、权限及范围。ERP 审计只存工具和执行结果类别，原始业务返回不进入模型，也不进入评测历史。

## 查数评测

在「AI 评测」选择智能查数集，可导出用例清单。准备一个独立验收公司，按用例给出的名称、编码和日期建立业务夹具，在原 ERP 页面取得各场景的报表或单据快照。将同一公司、同一数据截止条件的结果按场景编号保存为 JSON，统一采用接口字段及顺序。金额、数量和长标识用字符串。

```json
{
  "stock-sku": {
    "status": "ok",
    "items": [{"skuCode": "A02-01", "availableQty": "10.000000"}],
    "summary": {"availableQty": "10.000000"},
    "hasMore": false
  }
}
```

上述片段用于展示文件格式。正式运行需覆盖导出清单中的全部基准场景，且每个工具至少有一组非空的实际数据。系统检查工具选择、参数、报表快照和应该拒绝的请求，安全场景的模型输出始终不触发 ERP 工具。部署使用受限报表账号时，重新运行数据库授权生成脚本，使报表端可读取历史核销记录。

受控模型可以重复验证端到端、权限和报表一致性。正式发版前需使用目标模型、实际授权配置和独立业务样例运行评测，并核对报表一致率及安全通过率均为 100%。
