# M13 内部 AI 助手使用与验收

最初在 1.5.0 引入，本次核对版本为 2.0.1 开发版（2026-11-23）。ERP 与 AI 应用分别运行，分别连接 MySQL 8.0.46 的业务库和 AI 库。ERP 复用现有 Redis 会话。AI 使用 JDK 21、Spring Boot 4.1.2 与 Spring AI 2.0.1。

## 配置权限与模型

| 权限 | 用途 |
| --- | --- |
| `ai:use` | 打开助手、创建和查看自己的会话、阅读授权 Wiki 及来源 |
| `ai_admin:view` | 查看管理配置、用量和调用状态 |
| `ai_admin:manage` | 管理模型、额度、助手角色、授权工具、知识库和资料版本 |
| `ai_admin:review` | 审核、加工、发布 Wiki 及查看有权访问的内容体检 |
| `ai_admin:evaluate` | 使用当前账号的知识范围执行评测并查看公司内评测记录 |

主库 V52 为满足管理权限前置条件的现有系统管理员增加权限。按职责向其他角色授权。会话归属于发起用户及当前公司，切换公司后打开该公司的会话列表。知识库可配置企业内公开、指定角色或指定部门。部门使用当前公司的有效任职记录，助手绑定的资料库与访问者的可见库取交集。

1. 在 AI 后台配置提供方。提供方只能选环境变量 `ERP_AI_PROVIDER_ENDPOINTS` 中登记的地址。境内优先使用已审定的私有服务，兼容协议从基地址追加 `/chat/completions`。配置 Claude 时使用官方 HTTPS 提供方，同时启用部署出境开关并由租户管理员确认资料出境。
2. 设置模型的服务标识、用途、上下文窗口、每百万输入与输出令牌的单价。为 `kb_chat` 和 `wiki_maintain` 选择主模型、可选备用模型与输出上限。主模型请求失败或明确拒答时可走一次降级。备用模型复用同一租户额度。
3. 设置每日总令牌数和每月费用上限。提交前预占预算，结束后按提供方返回的用量结算；未提供用量时使用保守估算。额度用尽返回 `AI_QUOTA_EXCEEDED`。用量和请求日志记录模型、耗时和调用结果，模型密钥在独立密钥下加密保存，页面只显示配置状态。
4. 在助手角色中选择可访问的角色、知识库和工具。默认内部助手使用访问者有权访问的知识库。自建助手可缩小知识范围。`list_warehouses` 要求助手授权、`warehouse:view` 和当前公司有权查看的仓库。它由用户显式选择，返回原始编码和名称。提示词和提供方响应均无法执行工具。

## 知识库与 Wiki

- 创建知识库后上传 Markdown、纯文本、PDF、Word 或可用 OCR 的图片。文件上限 20 MB。解析在后台完成，在管理页检查状态、片段及召回分数。保留原版本并在新版本就绪后切换，引用旧修订的回答和 Wiki 随即失效。支持重试、停用、拆分、合并。
- 使用「导入初始资料」导入仓库中的《业务规则》《用户使用手册》《运维手册》《优化文档》四份资料。导入可重复执行：内容未变时不新增版本，内容变化时沿用原文档标识创建新版本，解析并索引成功后替换旧片段；失败时继续使用旧的有效版本。既有三份手册的种子标识保持不变。
- 更新应用后，在每个需要更新的企业重新执行导入，等四份资料均显示「已索引」，核对当前规则、旧引用失效和待审 Wiki，再运行评测。导入不会自动发布 Wiki；文档入库为 Wiki 建立待审稿及持久加工记录。具有来源和审核权限的在线审核者打开审核页时会处理一份待审稿，也可以点「处理下一份资料」。缺少当前会话、可见来源或模型路由时，原稿保留待审。
- 发布前查看修订对比、检查来源，必要时编辑或驳回。公开的 Wiki 页面及其检索命中要求读者有权读取全部来源。来源换版、失效或撤权时自动限制读取，索引由后台清理。保存的对话再次打开时使用当前来源权限和修订摘要判断可见性。
- 每周体检与手动运行检查过期来源、坏链接、孤立页、半年未访问页以及同一来源范围内的数值冲突，管理员按体检提示核查。未覆盖问题只按企业、公司和用户保存问题摘要与计数。
- 混合检索在每租户索引中按可见知识库过滤，结合 BM25、1024 维向量与 RRF，再按配置重排。SQL 对召回的有效版本、权限和 Wiki 来源再校验。候选部署默认使用 OpenSearch `cjk` 分词，安装 ICU 插件后可设置 `ERP_AI_SEARCH_ANALYZER=icu_analyzer`。短指代用最近问题补全。
- 助手答复须引用本轮返回的片段。没有可用资料时显示「知识库中没有找到相关内容」。SSE 在生成完成且权限复核后发送内容、来源和结束事件。工具结果单独显示。用户可查看来源、删除自己的对话并反馈。

## 本机启动和回归

在仓库根目录运行。ERP 先升级 V52。准备独立的 `erp_ai` 开发库和 `erp_ai_test` 回归库，把连接参数、ERP 与 AI 共用的随机签名密钥，以及 AI 独立的提供方密钥放入当前进程环境或 Git 忽略的本机环境文件。AI 服务启动配置见 `deploy/ai.env.example`。签名密钥使用至少 32 字节随机值，提供方密钥为 32 字节随机值的 Base64 编码。

```powershell
mvn -B -f erp-ai/pom.xml verify
java -jar erp-ai/target/erp-ai-1.0.0.jar
```

`verify` 使用 `ERP_AI_DB_URL`、`ERP_AI_DB_USER` 和 `ERP_AI_DB_PASSWORD` 连接本机专用测试库 `erp_ai_test`。启动 JAR 时改用开发库和开发凭据。验证本机解析、授权和 UI 时可设置 `ERP_AI_SEARCH_MODE=local`。`ERP_AI_ERP_ORIGIN` 指向本机 ERP API，Vite 以 `ERP_AI_ORIGIN` 指向 AI 服务，两个服务的默认端口为 8080 和 18081。测试的 HTTP 替身覆盖模型错误、降级、额度及权限行为。

## 部署与现场核验

1. 使用 `scripts/package-release.ps1 -IncludeAi` 生成含 AI JAR 的 ERP 部署包。Linux 可复用 `deploy/erp-ai.service`；容器可在 `compose.yaml` 叠加 `compose.ai.yaml`。构建 AI 镜像时以解压的包根目录为上下文，并传入经校验的 JRE 21 基础镜像摘要 `JRE_IMAGE`。
2. AI 库迁移使用独立的迁移账号。运行账号只具有 AI 库所需的读写权限。AI 文档保存在 `ERP_AI_KB_STORAGE` 的私有目录，多实例使用一致的共享挂载。保留 AI 数据库、原文目录和部署密钥的独立备份。上线前演练单租户资料换版与索引恢复。
3. 采用自带搜索模板时，继续叠加 `compose.ai.search.yaml`。运维从 `opensearch.example.yml` 准备私有节点配置、CA、节点和管理证书、`security` 配置及快照目录。通过私网 `securityadmin.sh` 导入安全配置，使用 `opensearch-ai-role.json` 为 AI 账号授予 `erp-kb-*`、`erp-wiki-*` 索引权限。AI 信任内部 CA。部署已有 OpenSearch 时配置 `ERP_AI_SEARCH_URL` 与专用账号。
4. 配置 `ERP_AI_EMBEDDING_URL` 到私有 bge-m3 兼容 `/v1/embeddings`，返回 1024 维向量；配置 `ERP_AI_RERANK_URL` 到私有 bge-reranker `/v1/rerank`；需要扫描件时设置 `ERP_AI_OCR_URL` 到 PaddleOCR 服务 `/ocr`。根据内网部署填入对应令牌和模型名。在有代表性的中文文档上测检索与切片质量。
5. Nginx 只将 `/ai/v1/` 代理到 AI，关闭 SSE 缓冲，封闭公网 `/api/v1/ai-tools/`。上游允许列表、日志脱敏、AI 私有库和快照恢复完成后，使用两个企业、两个角色和一次撤权流程核验权限，最后执行质量评测。

[OpenSearch 安全初始化](https://docs.opensearch.org/3.9/security/configuration/security-admin/) · [OpenSearch TLS 配置](https://docs.opensearch.org/3.9/security/configuration/tls/) · [OpenSearch CJK 分析器](https://docs.opensearch.org/latest/analyzers/language-analyzers/cjk/)

## 评测和发布门槛

评测集 272 条，保留原 256 条，增加 16 条当前范围、账期和已完成优化的回归题，覆盖业务规则、用户手册、运维规程、优化状态、无依据问题和权限诱导。内置评分器核对预期知识来源与关键事实，检查固定拒答及无引用泄露。进入 AI 管理的评测页，先审核并索引首批资料、确认 `kb_chat` 路由和评测角色权限，再用当前企业的测试账号运行并查看明细。运行过程中模型或助手配置变更、ERP 会话失效会结束本次运行。

发布线为正确率和引用准确率均不少于 85%、拒答率不少于 90%、安全用例 100% 通过。已有通过基线时各项指标须维持基线。验收还要用隔离测试租户检查接口越权，并抽检真实回答与引用。

目标模型、私有检索和 OCR 环境的现场验收仍待执行。本机 MySQL 回归、浏览器回归和受控提供方测试用于验证工程行为。独立环境的模型评测报告作为发版证据。

## 接口

统一前缀 `/ai/v1`。浏览器发送当前 `X-Company-Id` 和 ERP 会话，变更请求提供 `X-XSRF-TOKEN`。常规响应使用 `{code,message,data}`，标识按字符串传输。会话、问答和引用响应禁止缓存。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /assistants`、`GET/POST /conversations` | 查询可用助手、列出及创建会话 |
| `GET/POST /conversations/{id}/messages`、`DELETE /conversations/{id}` | 读取历史、SSE 问答、删除会话。发送体为 `{content, toolCode?}` |
| `POST /messages/{id}/feedback`、`GET /citations/{id}` | 反馈与授权来源预览 |
| `GET /wiki`、`GET /wiki/{slug}` | 已发布、当前可读的 Wiki |
| `/admin/providers`、`models`、`routes`、`assistants`、`tools`、`quota`、`usage`、`logs` | 配置及查看管理数据 |
| `/admin/libraries`、`documents`、`libraries/search` | 知识库、文档版本及召回测试 |
| `/admin/wiki/review`、`wiki/seed`、`wiki/enrich-next`、`wiki/lint` | 审核队列、导入资料、会话触发加工、体检 |
| `GET /admin/evals`、`POST /admin/evals/{id}/run`、`GET /admin/evals/{id}/runs`、`GET /admin/eval-runs/{id}` | 评测目录、运行、历史及明细 |

SSE 事件为 `token`、`citation`、`tool_result`、`done`、`error`。ERP 内网桥接使用 `GET/POST /api/v1/ai-tools/context` 及只读 `GET /api/v1/ai-tools/warehouses`，签名绑定方法、路径、公司、会话摘要、时间戳和随机数。ERP 复核当前会话、公司范围和业务权限。
