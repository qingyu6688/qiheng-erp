# M15 单据解释使用与验收

## 使用方法

1. 在「AI 与知识 → AI 管理」中给指定助手开启 `document_explain`，按员工角色授权，并设置已有的 `kb_chat` 对话路由。
2. 在销售订单或发货单详情中点「问 AI」，选择「为什么不能发货？」。在会计期间检查栏点「问 AI」，选择「关账为什么不通过？」。
3. 按当前单据状态、检查结果和原因处理业务。关联链接打开授权范围内的原单据或期间。需要确认最新结果时，在当前详情重新查询。

销售订单解释覆盖订单审核状态、变更和可发条件。已有发货单按实际业务日和单据行检查，适用时包含期间、来源订单、信用、商品单位、库存批次、冻结及序列号。会计期间解释沿用原关账预检，另外告知更早开放期间和总账启用时的结账前置条件。检查结果对应页面展示的数据时间，提交发货或关账仍按实际请求和当时库存、期间、权限重新校验。

## 权限与接口

- 员工需要 `ai:use`、助手角色授权及 `document_explain` 工具授权。销售订单和发货单分别需要 `sales_order:view`、`shipment:view`，并按原单据的公司、仓库、部门范围核验。关账需要 `period:view`、`period:close` 以及原检查要求的公司数据范围。涉及启用总账的检查沿用财务结账权限。关联单据独立校验查看权限。
- 消息入口为 `POST /ai/v1/conversations/{id}/messages`。请求发送 `toolCode: "document_explain"` 和 `toolArguments: { "documentType": "sales_order", "documentId": "123" }`，类型还支持 `shipment`、`accounting_period`。编号使用十进制字符串，可精确保留长 ID。
- ERP 用带签名的 `POST /api/v1/ai-tools/query/document_explain` 执行预检，再用同一目标的 `POST /api/v1/ai-tools/scope/document_explain` 复核会话和权限范围。解释通过 `tool_result` 事件返回状态、原页面操作、原因和授权来源。解释工具只读，业务单据、库存和账务均按原命令入口处理。
- 模型仅收到动作名称和现有原因码。服务端只接受在当前结果中出现的优先原因，再用 ERP 的文字生成解释。无可用模型或输出不合法时，按 ERP 检查顺序展示。原始结果只在当次展示，重新打开历史需从原单据再次检查。

## 评测准备

在「AI 评测」选择「单据解释」，下载用例。用例共 22 条，包含 6 条发货、6 条关账和 10 条安全检查。按 `baselineRequired` 准备现场基准文件。对业务用例，先在原页面或对应业务校验取得基准，填写实际状态、当前页面操作、全部阻挡码及本次可见来源。`sourcePaths` 包含主单据路径和所有授权关联链接。需要比较多原因的优先处理顺序时，填写 `firstReasonCode`。

```json
{
  "sales-review": {
    "documentId": "123",
    "documentStatus": "change_pending",
    "allowedActions": ["changes"],
    "checkPassed": false,
    "blockerCodes": ["CHANGE_PENDING"],
    "sourcePaths": ["/sales-orders/123"],
    "firstReasonCode": "CHANGE_PENDING"
  },
  "sec-other-company-order": { "documentId": "456" }
}
```

安全用例中的跨公司和跨企业 ID 应来自对应隔离公司，基准只填写 ID。非法字段和编号攻击由评测自带。模型兜底可正常供员工查阅，模型评测仍会记录未通过。正式发布前使用目标模型与现场业务样例复测解释、来源、拒答和安全结果。
