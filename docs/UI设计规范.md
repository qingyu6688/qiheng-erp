# ERP 管理端 UI 设计规范

- 规范版本：1.0.0。
- 编写日期：2026-11-15，Asia/Shanghai。
- 设计稿：[ERP 管理端 UI 设计](https://claude.ai/artifact/Da7eTdp66d2QhMBQSA33jE)，共 9 张画板，链接目前仅本人可见，需要给别人看时在页面的分享菜单里开启。
- 依据：全局规范第 14 节，《接口设计》第 2.5、2.9、2.12 节，《业务规则》第 11 节。
- 文档维护：maorongkang@gmail.com。

## 1. 原则

1. **为长时间录单、对账的人设计。** 以表格和表单为主，信息密度适中，不堆卡片，不用渐变和装饰图。
2. **颜色只表达两件事：状态和主操作。** 其他元素都是黑白灰。
3. **服务端说了算。** 金额、合计、可用量都由接口返回，页面只显示；按钮按接口返回的 `allowedActions` 显示。
4. **每种状态都要设计。** 空数据、加载中、失败、结果确认中、数据被他人修改，都有对应的样式（设计稿“设计规范”画板）。
5. **可访问。** 文字对比度不低于 4.5:1；状态标签始终带文字，不只靠颜色区分；图标按钮有 `aria-label`；表单控件都有 `<label>`。

## 3. 颜色

| 用途 | 取值 | Element Plus 变量 |
|---|---|---|
| 主色 | `#1E5BD7` | `--el-color-primary` |
| 主色浅底 | 由主色生成的 light-9（约 `#E9EFFB`） | `--el-color-primary-light-9` |
| 成功 | `#12805C` | `--el-color-success` |
| 警示 | `#A15C07` | `--el-color-warning` |
| 危险 | `#C2341F` | `--el-color-danger`、`--el-color-error` |
| 中性（草稿、已关闭） | `#4E5969` | `--el-color-info` |
| 文字·主 | `#1D2129` | `--el-text-color-primary`、`--el-text-color-regular` |
| 文字·次 | `#4E5969` | `--el-text-color-secondary` |
| 文字·弱（最浅） | `#6B7380` | `--el-text-color-placeholder`、`--el-text-color-disabled` |
| 输入框边框 | `#C9CDD4` | `--el-border-color` |
| 分隔线 | `#E3E6EB` | `--el-border-color-light` |
| 表头底色 | `#F7F8FA` | `--el-fill-color-light` |
| 页面底色 | `#F5F6F8` | `--el-bg-color-page` |

没有使用 Element Plus 默认的 `#409EFF`，因为它和白色文字的对比度只有约 3:1，达不到 4.5:1。上表所有文字色在白底和对应浅底上都满足 4.5:1。

主题用 SCSS 覆盖 Element Plus 的 `$colors`，让它自动生成各级浅色、深色，不手工逐个写 CSS 变量：

```scss
// src/styles/element/index.scss
@forward 'element-plus/theme-chalk/src/common/var.scss' with (
  $colors: (
    'primary': ('base': #1E5BD7),
    'success': ('base': #12805C),
    'warning': ('base': #A15C07),
    'danger': ('base': #C2341F),
    'error': ('base': #C2341F),
    'info': ('base': #4E5969),
  ),
  $text-color: (
    'primary': #1D2129,
    'regular': #1D2129,
    'secondary': #4E5969,
    'placeholder': #6B7380,
    'disabled': #6B7380,
  ),
  $border-color: (
    '': #C9CDD4,
    'light': #E3E6EB,
  ),
  $bg-color: (
    'page': #F5F6F8,
  )
);
```

具体的引入方式（Vite 的 `css.preprocessorOptions`、按需导入）在 M1 初始化前端时按所用 Element Plus 版本的官方文档配置。

## 5. 单据状态标签

用 `el-tag`（`effect="light"`）。同一个状态在所有页面用同一种颜色。

| 状态 | 标签类型 |
|---|---|
| 草稿 | `info` |
| 待审核、变更待审核、签收有差异 | `warning`：等人处理 |
| 已批准、已出库·待签收 | `primary`：进行中 |
| 已签收、已确认、已退款 | `success`：已完成 |
| 已关闭、已取消、已作废 | `info`：已结束 |
| 已冲销 | `danger` |

履约、结算、售后三个维度用文字和数字表达进度，例如“部分 · 3 / 14 件已签收”，不再加标签，避免一行里出现太多颜色。

## 6. 数字与字段显示

| 类型 | 接口返回 | 页面显示 |
|---|---|---|
| 金额 | `"1130.00"` | `1,130.00`，千分位，固定 2 位小数，右对齐 |
| 数量 | `"4.000000"` | `4 件`，去掉末尾的 0，带单位 |
| 单价 | `"33.33333333"` | 至少 2 位小数，有效位全部显示 |
| 负数 | `"-45.83"` | `−45.83`，用减号，不用红色表示负数 |
| 无权限的字段 | 字段不出现 | 整列隐藏；单个位置显示 `—` |
| 日期 | `"2026-11-15"` | 原样显示；列表里同一年可以省略年份 |

- 金额、数量列都用等宽数字（`font-variant-numeric: tabular-nums`）。
- 服务端计算的字段（行金额、分摊、税额、合计）用只读样式：灰底输入框或纯文本，与可编辑字段区分开。
- 格式化函数放在 `src/utils/format.ts`，只做显示，不参与计算（方案 5.2）。

## 7. 交互约定

- **主按钮**：一个区域只有一个，放在最右侧。
- **危险操作**：冲销、作废、关闭剩余数量用描边危险按钮，二次确认，并写明后果，例如“关闭后不能恢复，释放预留 5 件”。
- **提交中**：按钮立即禁用，显示“提交中…”。超时后显示“结果确认中”，按幂等键查询结果，不让用户重复提交（接口设计 2.7）。
- **提醒和失败**：命令成功但带 `warnings` 时，用橙色提示条，操作已经完成；失败用红色，说明没有生效的原因和下一步怎么做。
- **版本冲突**：显示是谁、在哪个版本修改了单据，提供“刷新查看”和“复制我的修改”两个按钮。
- **列表分页**：“上一页 / 下一页”加总数（接口设计 2.8），不提供跳到第 N 页。
- **表单错误**：提示紧贴字段下方，说明怎么改，例如“数量最多 6 位小数”。

## 8. 后续

- 设计稿只覆盖销售主流程、库存、核销。采购、调拨、盘点、收付款、关账等页面，沿用同一套组件和布局，在对应里程碑开发时补齐。
- M1 搭建前端时，先按第 3、4 节配置主题，再用“仓库管理”页面对照设计稿检查一遍，确认 Element Plus 组件的实际效果与规范一致。
