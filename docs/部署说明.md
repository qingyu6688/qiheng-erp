# 本地部署与使用

当前版本 0.5.0，M5 采购闭环、付款与期初已验收，原有销售闭环回归通过。后端使用 JDK 21 和 Maven，前端使用 Node.js 24 和 npm。本机项目根目录为 `F:\桌面\ERP`，`F:\projects\erp` 是指向同一目录的 Windows 联接。下列终端命令在 PowerShell 7 中运行。

## 当前电脑启动

首次运行已完成环境准备。电脑重启后，在项目根目录执行：

```powershell
pwsh -File .\scripts\prepare-local.ps1
pwsh -File .\scripts\project.ps1 server
```

在第二个终端的项目根目录执行：

```powershell
pwsh -File .\scripts\project.ps1 web
```

打开 [ERP 工作台](http://127.0.0.1:5173)。企业编码是 `DEMO`，用户名是 `admin`。初始密码保存在本机根目录 `.env` 中的 `ERP_DEV_ADMIN_PASSWORD` 项。账号页可改密，初始化脚本只在开发企业首次创建时使用初始密码。后台使用 [健康检查](http://127.0.0.1:8080/actuator/health)，开发配置下登录后可获取 `GET /v3/api-docs`。

进入仓库管理，选择公司，再新建仓库，填写编码和名称并保存。点击名称查看详情，点击编辑修改资料。停用和启用会保留资料及操作记录。切换公司后列表重新加载。

## 首次准备或换机

1. 确认 MySQL 8.0.46 在本机 3306 端口运行，JDK 和 Redis 程序路径可通过准备脚本参数指定。
2. 全新安装时，在当前终端通过本机凭据管理方式设置 `DB_USERNAME`、`DB_PASSWORD`。脚本使用该账号准备独立的 `erp_dev`、`erp_test` 库和各自的项目账号。已有配置可按 `.env.example` 填写项目凭据。
3. 在仓库根目录执行 `pwsh -File .\scripts\prepare-local.ps1`。本机使用现有 Redis 程序在回环地址 6380 启动独立进程。准备脚本生成的凭据、Redis 配置及本机日志分别保存在 `.env` 和 `.local/`。
4. 在 `erp-web` 目录执行 `npm ci`，然后按前一节启动。本地服务用回环地址提供 HTTP。生产配置使用 HTTPS 会话 Cookie，数据库迁移由 Flyway 在启动时运行。生产部署与恢复演练属于 M8。

开发库与测试库的账号只获授各自库内权限。实际服务部署多实例时，每个实例使用不同的 `ERP_NODE_ID`（0 至 1023）。本地默认节点为 0，浏览器测试实例使用节点 1。

## 构建与验收

在项目根目录执行后端单元测试、集成测试和打包：

```powershell
pwsh -File .\scripts\project.ps1 verify
```

在 `erp-web` 的实际工作目录执行前端检查（本机为 `F:\桌面\ERP\erp-web`）：

```powershell
npm run lint
npm test
npm run build
```

浏览器验收每次在独立测试库创建随机编码的测试企业和临时口令，自动启动测试后端（18080）和测试前端（15173）。首次在 `erp-web` 目录执行 `npx playwright install --only-shell chromium`，再在项目根目录执行 `pwsh -File .\scripts\project.ps1 e2e`。使用已安装的 Edge 时可先在当前终端设置 `$env:ERP_BROWSER_CHANNEL = 'msedge'`。仓库验收样例只写入测试库。

## M2 升级与基础资料使用

0.2.0 启动时 Flyway 会执行 V4—V8，目录中的旧迁移继续保留。开发配置下首次升级 M1 演示角色会补齐新增权限。后续在页面修改授权后，按页面保存的权限执行。正式环境的角色由管理员显式分配权限。

先在组织与权限中维护公司参数、角色权限和用户，再分配用户可访问的公司或仓库。基础资料中维护客户、供应商、联系人、结算账户和收支项目。商品中依次创建单位、分类、商品与 SKU，随后设置单位换算及条码。账户创建后余额为零，资金业务将在后续阶段接入。会计期间从所选年月起逐月开启。

按用户要求，本机开发企业 `DEMO`、账号 `admin` 已同步根目录 `.env` 的开发默认密码。本地登录页自动预填，生产构建为空。修改账号密码后，如需继续预填，应同步更新本机 `.env` 并重启前端。


## M3 核心服务与任务

0.3.0 启动时 Flyway 执行 V9—V14。后台轮询处理 Outbox 和到期预留。通过 `ERP_WORKER_ENABLED=false` 可将 API 实例的后台任务关闭，另一实例开启后继续消费。测试配置关闭定时轮询，由测试显式领取任务，数据库和 Redis 配置沿用既有实例。

价格接口返回 `pricingVersion=2`。后续订单应保存头版本及行、费用的含税快照。库存和账务公开方法由业务用例在同一事务中调用，固定锁顺序及可恢复错误见《数据库设计》。SQL 锁竞争通过可重试的 503 响应提示，客户端使用原幂等键重试。核心服务不把 Redis 作为库存或资金额度的事实来源。

账本投影只累计已消费事件，并处理乱序提交及跨期迟到事件。公司级对账为异步任务，查看任务状态与差异时仍验证当前用户范围。M4 销售审批、发货签收与退货退款已经调用这些服务。

## M4 升级与销售验收

本机M4升级前的开发库备份位于未提交的 `.local/erp_dev-before-m4-*.sql`。0.4.0 启动追加 V15、V16、V18、V19：销售退役标记、销售业务权限与退款额度来源。保留现有 JDK 21、MySQL 8.0.46 和 Redis 配置。升级前备份开发数据库，启动后检查 Flyway 校验和迁移日志；不要修改已应用迁移。生产角色需由管理员明确授予各业务操作，开发演示账号的首次升级授权仍按既有初始化规则执行。

销售使用前，先创建有效客户角色、SKU、换算单位、公司仓库、结算账户和当前业务日期所在的开放期间，并录入合法期初库存。销售订单审批与收款确认默认由另一名操作人完成；退款审核始终要求另一名操作人。销售操作说明见[用户使用手册](用户使用手册.md)。

浏览器销售闭环夹具 `SalesBrowserFixture` 位于 `src/test/java`，只在测试 classpath、`dev,e2e` 本地验收启动组合下使用。它还限制随机 `E2E-` 企业、临时口令和本机 `erp_test` 隔离库；生产 Jar 不包含该夹具。夹具按上海时区当天创建开放期间、测试库存和期初分录，避免固定月份过期导致验收失败。常规开发启动不写入这组验收商品和库存。

继续使用项目根目录 `pwsh -File .\scripts\project.ps1 e2e` 运行浏览器验收。脚本使用 `spring-boot:test-run` 加入测试类目录，常规开发服务仍用 `spring-boot:run`。临时企业和口令由脚本生成，不写入文档或版本库。验收覆盖双账号复核、订单到签收、收款核销、开票、退货退款及页面运行错误；最终通过数量以[测试报告](测试报告.md)为准。

订单和各销售命令的超时不能靠新建另一张单据处理。页面保留原幂等键，先查询结果；查询尚无结果时用原请求重试。库存预留到期释放依赖 Worker 正常运行，资金到账和退款支付仍由财务手工确认，当前不对接银行、支付或税控渠道。

## M5 升级与采购、期初准备

本机 M5 升级前开发库备份位于未提交的 `.local/erp_dev-before-m5-*.sql`。0.5.0 启动追加 V20—V23：采购与请购退役标记、采购审批容差快照、收货成本税身份快照、付款关联采购订单外键及索引，以及采购、收货退货、付款转账和期初操作权限。升级前备份开发数据库，启动后检查 Flyway 校验与迁移日志；已应用迁移不得编辑。升级继续使用现有 JDK 21、MySQL 8.0.46 和 Redis，不增加外部服务或银行配置。

管理员按职责授予 `purchase_requisition:*`、`purchase_order:*`、`goods_receipt:*`、`purchase_return:*`、`payment:*`、`account_transfer:*`、`stock_adjustment:*`、`opening_entry:*` 的具体动作。应付核销沿用 `settlement:view/allocate/revoke`，供应商退款沿用 `receipt:*`；查看成本另需 `cost:view`，改税率另需 `document:change_tax_rate`。正式环境显式授权，不能依赖演示账号的开发初始化授权。

采购前准备供应商角色、SKU、单位换算、有效公司仓库和开放期间。付款与转账需要有效结算账户和足够余额，其他支出还需有效支出项目。库存期初在“库存期初”页面创建，写入 `stock_adjustment` 的 `opening` 类型，数量按所选单位输入，总成本按整行填写；换算不允许静默损失精度。往来及资金期初从“往来与资金期初”录入，由另一名人员审核后过账。客户与供应商往来可录欠款或预收预付，资金期初只录借方余额，具体方向见《用户使用手册》。

单据过账使用业务日期对应开放期间；历史日期补录仍按实际过账顺序维护移动加权成本，不重算已出库历史成本。收货成本税身份在过账时冻结，后改公司纳税人参数不回写原入库或退货。采购容差在订单审批时冻结，后改参数不扩大旧订单上限。

验证命令继续使用前文的 `verify`、前端 lint/测试/构建和 `e2e`。M5 浏览器流程复用随机测试企业与隔离测试库，覆盖期初、请购、采购、收货、付款、应付核销、退货和供应商退款。最终后端 241 项、前端 48 项、浏览器 4 项全部通过，采购、期初与资金样例八类对账零差异，详见《测试报告》。确认付款、供应商退款和账户转账只登记财务已经执行的操作，不向银行发送指令。
