# 本地部署与使用

当前版本 0.2.0。后端使用 JDK 21 和 Maven，前端使用 Node.js 24 和 npm。本机项目根目录为 `F:\桌面\ERP`，`F:\projects\erp` 是指向同一目录的 Windows 联接。下列终端命令在 PowerShell 7 中运行。

## 当前电脑启动

首次运行已完成环境准备。电脑重启后，在项目根目录执行：

```powershell
pwsh -File .\scripts\prepare-local.ps1
pwsh -File .\scripts\project.ps1 server
```

在第二个终端的项目根目录执行：

```powershell
pwsh -File .\scripts\project.ps1 web
```

打开 [ERP 工作台](http://127.0.0.1:5173)。企业编码是 `DEMO`，用户名是 `admin`。初始密码保存在本机根目录 `.env` 中的 `ERP_DEV_ADMIN_PASSWORD` 项。账号页可改密，初始化脚本只在开发企业首次创建时使用初始密码。后台使用 [健康检查](http://127.0.0.1:8080/actuator/health)，开发配置下登录后可获取 `GET /v3/api-docs`。

进入仓库管理，选择公司，再新建仓库，填写编码和名称并保存。点击名称查看详情，点击编辑修改资料。停用和启用会保留资料及操作记录。切换公司后列表重新加载。

## 首次准备或换机

1. 确认 MySQL 8.0.46 在本机 3306 端口运行，JDK 和 Redis 程序路径可通过准备脚本参数指定。
2. 全新安装时，在当前终端通过本机凭据管理方式设置 `DB_USERNAME`、`DB_PASSWORD`。脚本使用该账号准备独立的 `erp_dev`、`erp_test` 库和各自的项目账号。已有配置可按 `.env.example` 填写项目凭据。
3. 在仓库根目录执行 `pwsh -File .\scripts\prepare-local.ps1`。本机使用现有 Redis 程序在回环地址 6380 启动独立进程。准备脚本生成的凭据、Redis 配置及本机日志分别保存在 `.env` 和 `.local/`。
4. 在 `erp-web` 目录执行 `npm ci`，然后按前一节启动。本地服务用回环地址提供 HTTP。生产配置使用 HTTPS 会话 Cookie，数据库迁移由 Flyway 在启动时运行。生产部署与恢复演练属于 M8。

开发库与测试库的账号只获授各自库内权限。实际服务部署多实例时，每个实例使用不同的 `ERP_NODE_ID`（0 至 1023）。本地默认节点为 0，浏览器测试实例使用节点 1。

## 构建与验收

在项目根目录执行后端单元测试、集成测试和打包：

```powershell
pwsh -File .\scripts\project.ps1 verify
```

在 `erp-web` 的实际工作目录执行前端检查（本机为 `F:\桌面\ERP\erp-web`）：

```powershell
npm run lint
npm test
npm run build
```

浏览器验收每次在独立测试库创建随机编码的测试企业和临时口令，自动启动测试后端（18080）和测试前端（15173）。首次在 `erp-web` 目录执行 `npx playwright install --only-shell chromium`，再在项目根目录执行 `pwsh -File .\scripts\project.ps1 e2e`。使用已安装的 Edge 时可先在当前终端设置 `$env:ERP_BROWSER_CHANNEL = 'msedge'`。仓库验收样例只写入测试库。

## M2 升级与基础资料使用

0.2.0 启动时 Flyway 会执行 V4—V8，目录中的旧迁移继续保留。开发配置下首次升级 M1 演示角色会补齐新增权限。后续在页面修改授权后，按页面保存的权限执行。正式环境的角色由管理员显式分配权限。

先在组织与权限中维护公司参数、角色权限和用户，再分配用户可访问的公司或仓库。基础资料中维护客户、供应商、联系人、结算账户和收支项目。商品中依次创建单位、分类、商品与 SKU，随后设置单位换算及条码。账户创建后余额为零，资金业务将在后续阶段接入。会计期间从所选年月起逐月开启。

本机 `.env` 的 `ERP_DEV_ADMIN_PASSWORD` 与现有开发库 `admin` 的密码不匹配。该变量用于首次创建演示账号。现有账号登录使用数据库中已设置的实际密码，后续可以由有重置权限的用户在页面重置。
