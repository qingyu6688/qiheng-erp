# 06 供应链一期（1.7.0）

> 对应：《功能扩展方案》X-02、X-04、第 9 节（品牌、库区库位）；《企业级演进规划》S-01、S-03、F-07。
> 包：批次、序列号、其它出入库放在现有 `inventory`；新增 `quality`、`wms`（本版只含库区库位主数据和按库位记账）、`einvoice`；品牌放在 `catalog`。

---

## 1. 现有基础

`inventory_balance` 的维度已经是 `(tenant_id, company_id, warehouse_id, sku_id, location_key, lot_key)`，`location_key` 和 `lot_key` 首期固定为空串；数量列有 `on_hand_qty`、`reserved_qty`、`blocked_qty`（冻结：待检、隔离、盘点）。本版**启用这两个预留维度**，不新增维度列。

- 可用量公式不变：`可用 = 在库 − 预留 − 冻结`。
- 没有启用批次 / 库位的 SKU 和仓库，`lot_key`、`location_key` 继续为空串，现有行为完全不变。

## 2. 保质期、批次、序列号（X-04、S-01）

### 2.1 SKU 设置

`sku` 扩展字段如下，`spec` 已在 V1 和现有接口中实现，复用原列，不重复增加：

| 列 | 说明 |
|---|---|
| `spec` | 已有规格字段，沿用现有长度和校验（X-04） |
| `weight_kg` `DECIMAL(24,6)` | 重量 |
| `brand_id` | 品牌（第 5 节） |
| `batch_managed` `TINYINT(1)` | 批次管理 |
| `serial_managed` `TINYINT(1)` | 序列号管理（序列号管理的 SKU 基础单位必须是“个 / 台”这类整数单位） |
| `shelf_life_days` `INT` | 保质期天数，0 表示不管理 |
| `near_expiry_days` `INT` | 临期预警天数 |
| `issue_strategy` | 批次出库策略：fifo（先进先出）/ fefo（近效期先出）/ manual |

开启批次或序列号管理时，该 SKU 必须在所有仓库库存为 0，或者执行“期初转换”：把现有库存整体登记为一个默认批次 `INIT-{日期}`。

### 2.2 数据模型

| 表 | 关键字段 |
|---|---|
| `inv_batch` | `id`、`tenant_id`、`company_id`、`sku_id`、`batch_no`、`production_date`、`expiry_date`、`supplier_id`、`source_type`、`source_id`、`status`（normal / frozen / expired）、`created_at` |
| `inv_serial` | `id`、`tenant_id`、`company_id`、`sku_id`、`serial_no`、`batch_id`、`warehouse_id`、`location_key`、`status`（in_stock / reserved / shipped / returned / scrapped）、`last_movement_id`、`version` |
| `inv_movement_serial` | `movement_id`、`serial_id`，记录每笔库存移动涉及的序列号 |

- 唯一键：`inv_batch (tenant_id, company_id, sku_id, batch_no)`；`inv_serial (tenant_id, company_id, sku_id, serial_no)`。
- `lot_key` 取值为 `inv_batch.id` 的字符串形式；批次号允许改名而不影响余额键。
- 到期日：有保质期的 SKU，`expiry_date = production_date + shelf_life_days`，也可手工录入。

### 2.3 单据行变化

收货、发货、销售退货、采购退货、调拨、盘点、库存调整、其它出入库的明细行增加：

| 列 | 说明 |
|---|---|
| `batch_id` `BIGINT NOT NULL DEFAULT 0` | 批次 |
| `location_key` `VARCHAR(64) NOT NULL DEFAULT ''` | 库位（第 6 节） |

序列号不放在行上，单独的明细表 `*_line_serial(line_id, serial_id)`（每类单据一张，或通用表 `doc_line_serial(doc_type, line_id, serial_id)`，推荐通用表）。

规则：

- 入库（收货、销售退货、其它入库、盘盈）：批次管理的 SKU 必须指定批次（已有或新建）；序列号管理的 SKU 必须录入与数量相同个数的序列号，且序列号在本公司内不能“在库”。
- 出库（发货、采购退货、其它出库、盘亏、报废）：必须指定批次和序列号；系统按 `issue_strategy` 推荐批次，用户可改。已过期批次默认不推荐，选择时提示。
- 销售退货、采购退货默认带出原单的批次和序列号。
- 调拨：批次和序列号随货转移，在途期间序列号状态为 `in_transit`（新增状态值）。
- **预留**：订单审批时的预留仍按“仓库 + SKU”，不锁定具体批次；发货单提交时才占用具体批次（在现有“发货占用”的位置执行）。

### 2.4 成本

- 成本仍按“仓库 + SKU”移动加权（现有规则），**不按批次核算成本**。批次只用于追溯和效期管理。
- 先进先出成本（原二期候选 S04）不在本版范围。

### 2.5 追溯

| 接口 | 说明 |
|---|---|
| `GET /api/v1/batches?skuId=&expiringWithinDays=` | 批次列表，含各仓余额、到期日 |
| `GET /api/v1/batches/{id}/trace` | 正向追溯：该批次从哪张收货单进、发给了哪些客户、剩余在哪 |
| `GET /api/v1/serials/{serialNo}/trace?skuId=` | 序列号全生命周期 |
| `GET /api/v1/trace/customer?partnerId=&skuId=` | 反向追溯：某客户收到过哪些批次 / 序列号 |

- 临期预警：每日任务扫描 `expiry_date − near_expiry_days <= 今天` 且有余额的批次，发站内信给仓库负责人（2.0 并入预警中心）。
- 过期批次自动标记 `expired`，余额转入冻结（生成一张系统库存调整单，类型 `block`，原因“批次过期”）。

### 2.6 前端

- 单据明细行：批次管理 SKU 显示“批次”列（下拉 + 新建批次弹窗：批次号、生产日期、到期日），序列号 SKU 显示“序列号”按钮（弹窗中可扫码连续录入、粘贴多行、按区间生成）。
- 实时库存：增加“按批次”视图，临期标黄、过期标红。
- 新页面：库存 → 批次与序列号（查询、追溯图）。

## 3. 来料检（S-03）

### 3.1 数据模型

| 表 | 关键字段 |
|---|---|
| `qc_item` | `id`、`tenant_id`、`code`、`name`、`type`（quantitative / qualitative）、`unit`、`method` |
| `qc_template` | `id`、`tenant_id`、`name`、`sampling`（full / fixed_qty / percent）、`sampling_value`、`status` |
| `qc_template_item` | `template_id`、`item_id`、`standard_value`、`upper_limit`、`lower_limit`、`required` |
| `qc_sku_rule` | `tenant_id`、`company_id`、`sku_id`（或 `category_id`）、`supplier_id`（0 表示全部）、`template_id`、`inspection_required` |
| `qc_inspection` | `id`、`tenant_id`、`company_id`、`no`、`type`（iqc）、`source_type`（goods_receipt）、`source_id`、`source_line_id`、`sku_id`、`batch_id`、`warehouse_id`、`location_key`、`received_qty`、`sample_qty`、`qualified_qty`、`unqualified_qty`、`concession_qty`（让步接收）、`result`（pending / passed / failed / partial）、`inspector_id`、`status`（draft / submitted / approved）、`version` |
| `qc_inspection_value` | `inspection_id`、`item_id`、`measured_value`、`judgement`（ok / ng） |
| `qc_defect` | `inspection_id`、`defect_code`（字典）、`qty`、`remark` |

### 3.2 流程

```text
采购收货过账
  └─ 对需要检验的行：入库数量计入 on_hand，同时计入 blocked（冻结原因 quality_hold）
     并自动生成来料检单（pending）
来料检审核
  ├─ 合格数量：解除冻结（blocked − 合格数）
  ├─ 让步接收：同合格，单据上记录让步原因和批准人
  └─ 不合格数量：保持冻结，生成“不合格品处理”待办：
        ├─ 退货给供应商 → 生成采购退货草稿（带批次）
        ├─ 报废        → 生成库存调整草稿（scrap）
        └─ 返工 / 挑选 → 改判后重新检验
```

- 冻结原因明细：新增表 `inv_block_detail(balance_key…, reason, source_type, source_id, qty)`，便于区分质检冻结、过期冻结、手工冻结；`blocked_qty` 总数仍在 `inventory_balance`，两者在同一事务更新，并纳入对账（冻结明细合计 = `blocked_qty`）。
- 来料检审核需要两人：检验员提交、质量主管审核（经办复核分离）。
- 检验结果影响供应商评分（为 SRM 预留：`qc_supplier_score_monthly`）。

### 3.3 接口与页面

| 接口 | 权限 |
|---|---|
| `/api/v1/qc/items`、`/templates`、`/sku-rules` | `qc_setting:*` |
| `/api/v1/qc/inspections`、`/{id}/{submit\|approve\|reject}` | `qc_inspection:*` |
| `/api/v1/qc/nonconforming/{id}/dispose` | `qc_inspection:dispose` |

菜单“质量”：检验项目、检验模板、检验规则、来料检单（待检列表默认打开）、不合格品处理。

## 4. 其它入库、其它出库（X-02）

### 4.1 数据模型

| 表 | 关键字段 |
|---|---|
| `stock_misc_doc` | `id`、`tenant_id`、`company_id`、`no`、`direction`（in / out）、`purpose`（字典：赠品入库、样品领用、借出、借入归还、内部领用、其他）、`warehouse_id`、`partner_id`（可空 0）、`income_expense_item_id`、`business_date`、`owner_department_id`、`owner_user_id`、`status`（draft / pending / approved / posted / reversed）、`approver_id`、`poster_id`、`remark`、`version` |
| `stock_misc_line` | `id`、`doc_id`、`line_no`、`sku_id`、`unit_id`、`qty`、`base_qty`、`unit_cost`（入库时录入；出库时过账回填）、`amount`、`batch_id`、`location_key` |

### 4.2 规则

- 状态流转与现有库存调整一致：草稿 → 提交 → 另一人审核 → 过账；错误通过冲销更正（在现有冲销框架中增加 `stock_misc_doc` 来源类型）。
- 入库成本：必须录入单位成本（可以为 0，例如供应商赠品；为 0 时需要选择原因）；按现有移动加权更新成本。
- 出库成本：按过账时的移动加权单位成本。
- 运营账本：库存账户 ↔ 对方账户。对方账户由收支项目决定：新增两个运营账户码 `MISC_STOCK_IN`（其他入库对方）和 `MISC_STOCK_OUT`（其他出库对方），总账映射时按收支项目映射到“营业外收入 / 销售费用 / 管理费用”等科目。
- “借出”类出库：记录预计归还日期，归还时用“借入归还”入库并关联原单，报表“借出未还”。
- 与现有六类库存调整的区别：调整用于盘盈盘亏、冻结报废等内部原因；其它出入库用于有业务对象的进出（赠品、样品、借出）。两者并列，互不替代。

### 4.3 接口与页面

- `/api/v1/stock-misc-docs`（`?direction=in|out`），命令 `submit|approve|reject|post`，权限 `stock_misc:*`。
- 菜单：库存 → 其它入库、其它出库；列表、编辑沿用 `DocumentBrowserPanel` 和 `StockDocumentEditor` 模式。

## 6. 库区与库位

### 6.1 数据模型

| 表 | 关键字段 |
|---|---|
| `wms_zone` | `id`、`tenant_id`、`company_id`、`warehouse_id`、`code`、`name`、`type`（storage / receiving / shipping / quarantine / return）、`status` |
| `wms_location` | `id`、`tenant_id`、`company_id`、`warehouse_id`、`zone_id`、`code`（如 `A-01-02-03`）、`aisle`、`shelf`、`layer`、`position`、`capacity_qty`、`mixed_sku_allowed`、`mixed_batch_allowed`、`pick_sequence`、`status` |

- `warehouse` 增加 `location_managed TINYINT(1)`、`default_receiving_location_id`、`default_shipping_location_id`。
- `location_key` 取 `wms_location.id` 的字符串形式。

### 6.2 规则

- 仓库开启库位管理前，库存全部在 `location_key=''`；开启时把空串余额转到“默认收货库位”（系统生成一张移库记录，不影响成本）。
- 开启后，所有出入库行必须有库位：收货默认收货库位、发货默认发货库位、来料检冻结的货物默认在待检区。
- 本版（1.7.0）只做库位主数据、按库位记账和查询、单据上选择库位；**上架、拣货任务和移库单在 2.0.0**（见 08）。
- 库位批量生成：按“巷道 × 货架 × 层 × 位”规则批量创建，库位码标签可打印（ZXing 生成条码）。

### 6.3 页面

基础资料 → 仓库：增加“库区库位”页签（树形：库区 → 库位，批量生成、启停、打印标签）；实时库存增加“按库位”视图。

## 7. 数电发票（F-07）

### 7.1 方案

通过**数电发票服务商**（具备税务数字账户接口资质的第三方）对接，不直接对接税务局接口。服务商接口差异由适配器隔离：

```text
einvoice 包
  ├─ EInvoiceProvider（接口）：issue / redIssue / query / download / downloadInbound
  ├─ 具体服务商适配器（按合同选定后实现，配置存 einv_provider_config）
  └─ EInvoiceService：与现有“开票登记”衔接
```

### 7.2 数据模型

| 表 | 关键字段 |
|---|---|
| `einv_provider_config` | `tenant_id`、`company_id`、`provider`、`tax_no`、`credentials_cipher`、`status` |
| `einv_issue_request` | `id`、`tenant_id`、`company_id`、`invoice_registration_id`、`invoice_kind`（special / normal，数电专票 / 普票）、`buyer_name`、`buyer_tax_no`、`amount`、`tax_amount`、`status`（draft / submitted / issued / failed / red_issued）、`provider_request_id`、`invoice_no`、`issued_at`、`error`、`version` |
| `einv_issue_line` | 商品名称、税收分类编码、规格、单位、数量、单价、金额、税率、税额 |
| `einv_file` | `request_id`、`format`（pdf / ofd / xml）、`attachment_id` |
| `einv_inbound` | 进项发票台账：销售方、发票号码、日期、金额、税额、状态（正常 / 作废 / 红冲）、勾选状态（只记录，不代替税务端操作） |

- `sku` 增加 `tax_category_code`（税收分类编码）。

### 7.3 流程

1. 现有“开票登记”选择待开票的签收应收行 → 生成开具请求（金额、税额来自已确认应收，**不重新计算**）。
2. 财务确认后提交服务商；异步轮询结果（Worker），成功后写回发票号码，下载版式文件存为附件，开票登记状态改为已开具。
3. 红字发票：按服务商流程提交红字确认信息，成功后对原开票登记做冲销（沿用现有冲销）。
4. 进项：每日从服务商同步进项发票到 `einv_inbound`，可与采购收货的应付匹配（建议匹配，人工确认）。

### 7.4 页面

财务 → 数电发票：开具申请、开具记录（下载 PDF / OFD）、红字发票、进项台账；设置 → 服务商配置（测试连接）。

## 9. 对账扩展

现有八类对账增加：

- 批次余额：`inventory_balance` 按 `lot_key` 汇总 = 不分批次的总余额；序列号“在库”数量 = 对应余额。
- 冻结明细：`inv_block_detail` 合计 = `blocked_qty`。
- 库位余额：开启库位的仓库，`location_key=''` 的余额为 0。

## 10. 测试要点

1. 批次 SKU：收货必须填批次；发货按 FEFO 推荐；过期批次自动冻结。
2. 序列号：同一序列号不能重复入库；发货后状态为 `shipped`；销售退货后为 `returned` 并可再次入库。
3. 并发发货同一批次的最后 1 件，只有一张成功。
4. 来料检：收货后可用量不增加；审核合格后增加；不合格生成采购退货草稿。
5. 其它入库成本为 0 时移动加权正确；冲销后余额和成本恢复。
6. 仓库开启库位后，未指定库位的单据提交被拒绝。
7. 数电发票：服务商超时后轮询补偿；红字发票后开票登记被冲销。

## 11. 验收

一个批次商品：来料检（部分不合格 → 退货）→ 合格入库到指定库位 → 销售按近效期先出 → 客户收货；从批次号可以查到供应商、收货单、检验单、发货单和客户，从客户也能反查批次。
