# 10 驾驶舱、打印设计器、预警中心与 2.0 升级（2.0.0）

> 对应：《功能扩展方案》第 11 节；《企业级演进规划》E-07、E-10；《开发计划》4.11 节 2.0.0 的不兼容变更与企业级加固。
> 新增包：`dashboard`、`printdesign`、`alert`。

M19 三个功能使用 V95 至 V97。布局采用原生拖拽与键盘排序按钮。HTML 预览和后台 PDF 共用服务端排版数据，PDFBox 与 ZXing 分别输出纸面内容和条码。公司可维护独立安全库存覆盖；原批次冻结与预警投递各自执行。 [本机验收](../测试报告.md#m19-经营驾驶舱打印与预警本机验收2026-11-17)

## 1. 经营驾驶舱

### 1.1 内容

| 区块 | 指标 | 数据来源 |
|---|---|---|
| 销售 | 本月 / 本年销售额、同比、环比、按月趋势、客户 Top 10、品类占比 | 销售汇总报表口径 |
| 毛利 | 毛利额、毛利率、按品类 / 客户 / 业务员 | 毛利报表口径 |
| 回款 | 本月回款、回款率、应收余额、逾期金额 | 收款、应收账龄 |
| 库存 | 库存金额、周转天数、呆滞（90 天无出库）金额、临期批次 | 库存汇总、批次 |
| 采购 | 本月采购额、到货及时率、来料合格率 | 采购汇总、来料检 |
| 财务 | 资产负债率、流动比率、现金余额 | 总账财务指标（1.4.0） |
| 生产 | 在制工单数、完工率、用料差异率 | 生产报表（如启用） |
| CRM | 商机金额、赢单率、业绩完成率 | CRM 统计（1.9.0） |

### 1.2 设计

- 指标定义在代码中（`DashboardMetric` 接口：编码、名称、所需权限、计算方法），**口径与现有报表复用同一查询**，避免驾驶舱和报表数字不一致。
- 布局可配置：`dash_layout(tenant_id, user_id 或 role_id, layout_json)`，用户可在允许的指标中拖拽排列（vue-draggable-plus），默认布局按角色预置（老板、销售经理、财务、仓库）。
- 数据：只读备库查询；每个指标结果在 Redis 缓存 10 分钟，页面显示“数据截至 xx:xx”，可手动刷新（每用户每分钟限 2 次）。
- 权限：每个指标声明所需权限（如成本类需要 `cost:view`），没有权限的指标不能加入布局。
- 大屏模式：全屏深色主题、自动轮播、每 5 分钟刷新，适合会议室电视。

### 1.3 接口与页面

- `GET /api/v1/dashboard/metrics`（可用指标清单）、`GET /api/v1/dashboard/data?metrics=a,b&period=`、`GET|PUT /api/v1/dashboard/layout`。
- 页面 `pages/dashboard/DashboardPage.vue`（菜单：报表与数据 → 经营驾驶舱），`EChart.vue` 组件渲染。

## 2. 打印模板设计器（E-07）

### 2.1 现状

现有 17 类单据的固定 A4 打印（`PrintPage.vue` + `PrintService` 返回打印数据）。本版**保留现有固定模板作为“系统默认模板”**，新增可设计的自定义模板。

### 2.2 模板模型

| 表 | 关键字段 |
|---|---|
| `print_template` | `id`、`tenant_id`、`company_id`（0 为全公司）、`document_type`、`name`、`paper`（A4 / A5 / 241×93 三等分 / 自定义宽高）、`orientation`、`margins`、`layout_json`、`is_default`、`status`、`version` |
| `print_log` | `tenant_id`、`document_type`、`document_id`、`template_id`、`printed_by`、`printed_at`、`copies` |

`layout_json` 结构：

```json
{
  "header": [ {"type": "text", "x": 0, "y": 0, "w": 190, "h": 10, "text": "销 售 发 货 单", "style": {"fontSize": 18, "align": "center", "bold": true}},
              {"type": "field", "x": 0, "y": 14, "w": 60, "h": 6, "label": "单号", "field": "documentNo"} ],
  "table":  {"y": 40, "columns": [ {"field": "lines.skuCode", "title": "编码", "w": 25},
                                   {"field": "lines.qty", "title": "数量", "w": 15, "format": "quantity"} ],
             "rowsPerPage": 10, "repeatHeader": true, "showTotalRow": true},
  "footer": [ {"type": "field", "field": "printedAt", "format": "datetime"},
              {"type": "barcode", "field": "documentNo", "symbology": "code128"},
              {"type": "image", "source": "companyLogo"} ]
}
```

- 元素类型：文本、字段、表格、条码、二维码、图片（公司 Logo、签章图片）、线条、矩形、页码。
- 坐标单位毫米；字段从**打印数据字段白名单**中选择（每类单据由 `PrintSources` 声明可用字段及是否敏感），成本、银行账号等敏感字段只有持有相应权限时才会被填充。
- 自定义字段（05）自动出现在可选字段中。

### 2.3 渲染

- 前端渲染：同一份 `layout_json` 在设计器和打印预览中用同一个渲染组件（HTML + CSS 绝对定位，`@page` 设置纸张），浏览器打印；套打（预印纸）支持背景图对位，背景图不打印。
- 批量打印：后端用同一布局生成 PDF（选用开源 HTML 转 PDF 库，选型时确认许可证可商用），走现有后台导出任务。
- 数字和时间格式复用 `format.ts` 的规则；后端 PDF 渲染实现同样的格式化并用同一组测试用例校验。

### 2.4 设计器页面

`pages/print/TemplateDesignPage.vue`：左侧元素和字段面板（拖拽）、中间纸张画布（标尺、网格、吸附、对齐线）、右侧属性面板；顶部预览（选择一张真实单据预览）。参照开源打印设计器的交互，如复制代码需确认许可证并在 `THIRD_PARTY_NOTICES.md` 中记录。

## 3. 预警中心（E-10）

### 3.1 规则

| 表 | 关键字段 |
|---|---|
| `alert_rule` | `id`、`tenant_id`、`company_id`、`code`（预置规则编码）、`name`、`params`（JSON 阈值）、`schedule`（实时 / 每小时 / 每日 8 点）、`receivers`（角色、用户、单据负责人、部门负责人）、`channels`（站内信 / 邮件 / 短信）、`enabled`、`version` |
| `alert_event` | `id`、`tenant_id`、`company_id`、`rule_code`、`target_type`、`target_id`、`level`（info / warning / critical）、`title`、`detail`、`status`（open / acknowledged / resolved / ignored）、`fingerprint`（去重）、`first_seen_at`、`last_seen_at`、`handled_by` |

预置规则：

| 编码 | 触发 | 来源 |
|---|---|---|
| `credit_exceeded` | 客户占用超过信用额度 | 1.4.0 |
| `receivable_overdue` | 应收逾期超过 N 天 | 未清项 |
| `negative_margin` | 签收确认的订单行毛利为负 | 销售履约 |
| `stock_below_safety` | 可用量低于安全库存 | 库存（SKU 增加 `safety_stock`） |
| `stock_slow_moving` | N 天无出库且有库存 | 库存流水 |
| `batch_near_expiry` / `batch_expired` | 批次临期 / 过期 | 1.7.0 |
| `qc_failed` | 来料检不合格 | 1.7.0 |
| `price_deviation` | 采购单价偏离近 3 次均价超过 N% | 采购 |
| `frequent_reversal` | 同一用户 7 天内冲销超过 N 次 | 冲销 |
| `duplicate_payment` | 同一供应商同金额 24 小时内多次付款 | 付款 |
| `workflow_overdue` | 审批超时 | 1.3.0 |
| `job_failed` | 定时任务或后台任务失败 | 1.2.0 |

### 3.2 运行

- 实时类规则通过 Outbox 事件触发；定时类规则由定时任务（Z-02）按计划扫描。
- `fingerprint`（规则 + 对象）去重：同一对象的同一问题在解决前只产生一条事件，`last_seen_at` 更新；状态从 resolved 再次触发时重新打开。
- 通知走消息中心（01）；`critical` 级别同时发短信（如已配置）。
- 现有 1.7.0 的批次临期提醒、1.4.0 的催收提醒并入预警中心，原独立任务停用。

### 3.3 页面

菜单：报表与数据 → 预警中心。列表（按级别、规则、状态筛选）、处理（确认、忽略并填原因、跳转到对象）；规则设置页（启停、阈值、接收人）。工作台增加“未处理预警”块。

## 4. 2.0 不兼容变更与升级

### 4.1 变更清单与执行方式

| 变更 | 公告版本 | 2.0 执行 | 升级脚本 |
|---|---|---|---|
| 移除代码中写死的单级审批 | 1.6.0 | 所有可审批单据统一由工作流处理；没有自定义流程的单据使用系统生成的“默认单级审批流程”（审批人为原有审批权限的角色） | `upgrade-2.0/01-default-workflows`：为每个公司每类单据生成默认流程并绑定；处于 `pending` 且没有流程实例的单据，补发起流程实例 |
| 数据范围统一为组织模型 | 1.6.0 | 旧的“公司 + 仓库”用户范围表并入新模型，权限计算只走一套代码 | `02-data-scope`：把 `sys_user_data_scope` 转换为角色 / 用户的新范围记录，生成转换报告（转换前后每个用户可见单据数对比），管理员确认后生效 |
| 权限码整理 | 1.8.0 | 统一命名：资源单数、下划线；废弃码移除 | `03-permission-codes`：按映射表改写 `sys_role_permission`；开放平台应用的 scopes 同步改写 |
| 移除已废弃接口 | 1.8.0 起管理端提示 | `/api/v1` 中标记 `Deprecated` 的接口下线；开放平台保留 `/open/v1` 稳定版 | 升级前检查：最近 30 天仍有调用的废弃接口列出调用方，未处理时升级检查不通过 |
| 业务科目固定映射 | 1.6.0 | 运营账户与总账科目的映射必须完整，运营分录不再允许“未映射” | 升级前检查：存在未映射的运营账户码时不通过 |

### 4.2 升级工具

- 新增 `scripts/upgrade-2.0.ps1`（同时提供 Linux shell 版本），步骤：
  1. **升级前检查**（只读）：版本 ≥ 最后一个 1.x 版本、Flyway 历史完整、没有运行中的导入导出任务、科目映射完整、废弃接口调用情况、待审批单据数量。输出报告，有阻断项则停止。
  2. 进入维护模式：所有 API 拒绝新写入，Worker 停止领取任务，等待进行中的写事务和租约任务结束；核对其他写入方，记录停写时间与最终 GTID。
  3. 停写确认后执行一致备份，核对备份、binlog 和最终 GTID，验证可恢复后才迁移。采用在线预备份时，须在此补齐并验证到最终 GTID 的 binlog，不能直接用较早快照作为回退点。
  4. 执行 Flyway 迁移（2.0 的迁移文件）和 `upgrade-2.0` 数据脚本，每一步记录到 `upgrade_log` 表。
  5. 升级后校验：八类对账 + 总账试算平衡 + 数据范围转换报告 + 默认流程绑定数量。
  6. 解除维护模式。
- 回退：第 4 步前失败确认旧程序与数据库一致后解除维护；第 4 步后失败恢复第 3 步的停写备份或追平到最终 GTID，再核对账务和权限后恢复 1.x。迁移后的数据核验及回退结束前持续停写，步骤写入《1.x 升级到 2.0 指南》。
- 演练要求：在客户数据副本上完整演练两次，记录耗时，用于确定停写窗口。

### 4.3 版本兼容

- 2.0 的前端只兼容 2.0 后端；移动端 App 启动时检查后端版本，不兼容时提示升级。
- 1.x 最后一个版本在 2.0 发布后继续提供 6 个月安全修复（`release/1.x` 分支）。

## 5. 企业级加固（2.0 发布门槛）

| 项 | 设计 |
|---|---|
| 高可用 | API 至少 2 实例（会话在 Redis，WebSocket 经 Redis 广播）；Worker 至少 2 实例（数据库租约选主，Flowable 异步执行器只在持有租约的 Worker 上运行）；MySQL 主备 + 自动切换（如 Orchestrator 或云数据库高可用）；Redis Sentinel；在目标环境做一次完整故障演练（杀主库、杀 API 实例、杀 Worker、断 Redis），记录恢复时间 |
| 审计防篡改 | `audit_log` 增加 `prev_hash`、`row_hash`：每条记录的哈希包含上一条的哈希（按公司分链）；每日把链尾哈希写入独立存储；提供校验工具 |
| 加密 | 备份文件加密（AES-256，密钥由运维保管）；敏感字段（手机号、身份证、银行账号）加密存储，查询用哈希列 |
| 密钥轮换 | 应用主密钥支持多版本：新数据用新版本加密，旧数据读取时自动重加密；轮换操作写入《运维手册》 |
| 等保 2.0 三级 | 按测评项准备：身份鉴别（MFA、密码策略）、访问控制、安全审计（审计保存 ≥ 6 个月）、入侵防范、数据完整性与保密性、备份恢复；委托测评机构测评 |
| 渗透测试 | 2.0 RC 版本由第三方渗透测试，高危、中危问题清零后发布 |
| 性能 | 按 1.x 期间真实单量的 3 倍复测：主要查询 P95 < 500ms，写入 P95 < 1000ms，零对账差异 |

## 6. 迁移规划

1. `dash_layout`
2. `print_template`、`print_log`
3. `alert_rule`（含预置规则）、`alert_event`；`sku.safety_stock`
4. `audit_log` 增加哈希列及历史数据补算（分批）
5. `upgrade_log`；2.0 数据升级脚本（见 4.2，脚本单独存放，不放进 Flyway）
6. 权限码

## 7. 验收

1. 驾驶舱的销售额、毛利与对应报表同一期间数字一致；没有成本权限的用户看不到毛利指标。
2. 用设计器做一张“三等分发货单”模板，浏览器打印和批量 PDF 输出一致；没有成本权限时成本字段为空。
3. 人为制造一个过期批次和一张逾期应收，预警中心各出现一条事件，重复扫描不重复生成。
4. 在客户数据副本上执行 1.x → 2.0 升级：检查、备份、迁移、校验全部通过，对账零差异；回退演练能恢复到 1.x。
5. 故障演练：主库切换期间写请求失败后可重试成功，切换后对账零差异。
