## 2. 1.1.0 小功能

### 2.1 默认结算账户（X-05）

- `cash_account` 增加 `default_for_receipt TINYINT(1)`、`default_for_payment TINYINT(1)`，默认 0。
- 每家公司每种用途最多一个默认账户：用生成列 `default_receipt_key = IF(default_for_receipt=1, company_id, NULL)` 加唯一索引实现（NULL 不参与唯一约束，这里正是需要的效果）。
- 接口：`POST /api/v1/cash-accounts/{id}/set-default`，请求体 `{purpose: "receipt" | "payment", version}`，权限 `cash_account:update`。同一事务内先清除旧默认再设置新默认。
- 前端：结算账户列表显示“默认收款 / 默认付款”标签；收款、付款登记打开时自动带出默认账户，用户可改。

### 2.2 工作台金额趋势（X-06）

- 接口：`GET /api/v1/workbench/trade-summary?months=12`，返回：

  ```json
  {
    "asOf": "2026-11-16T02:00:00Z",
    "sales":    {"today": "1200.00", "yesterday": "800.00", "month": "35600.00", "year": "402300.00"},
    "purchase": {"today": "0.00",    "yesterday": "500.00", "month": "21000.00", "year": "260000.00"},
    "trend": [{"month": "2025-12", "sales": "30100.00", "purchase": "18000.00"}]
  }
  ```

- 口径：销售取**已签收确认的应收金额**（与销售报表一致），采购取已过账收货金额；按业务日期、北京时间切日；按当前用户的公司、仓库、部门范围过滤。
- 权限：销售块需要 `report:sales_summary`，采购块需要 `report:purchase_summary`（沿用现有报表权限码），没有权限的块不返回。
- 性能：查询走只读备库；结果在 Redis 缓存 5 分钟，键含用户范围摘要。
- 前端：工作台顶部增加两张金额卡和一张双折线图（`EChart.vue`）。

## 3. 部门与岗位（Y-01）

### 3.1 数据模型

| 表 | 关键字段 | 说明 |
|---|---|---|
| `org_department` | `id`、`tenant_id`、`company_id`、`parent_id`（库内根为 NULL，接口为字符串 `"0"`）、`code`、`name`、`leader_user_id`、`sort_no`、`status`、`path`（如 `/1/5/12/`）、`depth`、`version` | 部门树；`(tenant_id, company_id, path)` 建索引 |
| `org_post` | `id`、`tenant_id`、`code`、`name`、`sort_no`、`status`、`version` | 岗位，租户级 |
| `org_user_company` | `tenant_id`、`company_id`、`user_id`、`version`、创建与更新审计字段 | 用户在当前公司的组织配置版本，避免甲公司修改覆盖乙公司；初次配置版本为 0 |
| `org_user_department` | `tenant_id`、`company_id`、`user_id`、`department_id`、`is_primary`、`primary_company_key` | 用户可在每家公司属于多个部门；非空部门集合恰有一个主部门，生成列及唯一索引保证每公司最多一个主部门 |
| `org_user_post` | `tenant_id`、`company_id`、`user_id`、`post_id` | 岗位定义共享，用户任职按公司独立保存 |

规则：

- 部门编码在公司内唯一；有下级部门或有用户时不能停用。
- 移动部门（改上级）时，在同一事务中更新本部门及全部下级的 `path`、`depth`，禁止移到自己的下级。
- 部门负责人用于工作流“部门负责人”审批人和预警通知。

多公司规则：部门上级、负责人、成员须在同一企业及当前公司范围内；岗位定义归企业，任职关系归公司。组织归属不授予公司或仓库权限。负责人须为当前公司可访问且启用的用户；用户失去该公司数据范围时，在分配范围的同一事务内清理该公司部门、岗位关系和负责人引用，增加组织版本并记录审计。停用岗位前须移除所有公司中的任职关系。部门有任何下级或成员时不能停用，先移出下级和成员。

路径由部门 ID 组成，根深度为 1，最多 20 层，每公司最多 1000 个部门。移动禁止跨公司、移入自身或后代；整个子树路径、深度同事务更新，受影响节点版本递增。拖拽移动及排序先确认，失败或取消后重新加载树。Y-01维护组织资料，Y-02在第4节追加业务数据范围。

### 3.2 接口

| 方法 | 路径 | 权限 |
|---|---|---|
| GET | `/api/v1/org/departments/tree` | `org_department:view` |
| POST | `/api/v1/org/departments` | `org_department:create` |
| PUT | `/api/v1/org/departments/{id}` | `org_department:update` |
| POST | `/api/v1/org/departments/{id}/move` | `org_department:update` |
| POST | `/api/v1/org/departments/{id}/{enable\|disable}` | `org_department:update` |
| GET / POST / PUT | `/api/v1/org/posts` … | `org_post:*` |
| GET / PUT | `/api/v1/users/{id}/organization` | 读取需要 `user:view` 或 `user:update`，保存需要 `user:update`；均带 `X-Company-Id`，目标用户须已有该公司范围。请求体 `{departments:[{id, primary}], postIds:[], version}`，版本为当前公司组织版本 |
| GET | `/api/v1/org/company-users` | 当前公司用户候选和姓名，不返回手机号；需要 `org_department:view` 或 `user:update`，游标分页 |
| GET | `/api/v1/org/assignment-options` | 当前公司启用部门和企业启用岗位选项，需要 `user:update` |
| GET | `/api/v1/org/departments/{id}/members` | 当前部门成员，权限 `org_department:view`，游标分页 |

组织写操作带 CSRF 和 `Idempotency-Key`。新建返回 201，其他命令返回 200；编辑、移动、状态及组织分配校验版本，过期返回 409。其他公司或企业的对象、引用返回 404，缺少操作权限返回 403。部门管理需要当前公司范围，岗位定义管理按企业范围。资料变更先取企业行作为管理写入屏障，与现有用户角色及数据范围变更串行，再取公司、部门、组织配置行；不参与业务过账锁链。

### 3.3 页面

树接口返回按 `sort_no,id` 排序的扁平部门数组，前端复制节点组树，最多1000项；成员、岗位和用户候选使用 `items/nextCursor` 分页。所有 ID 序列化为字符串。任职保存使用公司独立的组织版本，不复用 `sys_user.version`。撤销公司范围时即使尚未配置任职，也建立组织版本记录并递增，恢复范围后须重新加载；幂等结果查询仍核对当前用户公司范围。

- 系统管理 → 部门与岗位：左侧部门树（可拖拽调整顺序和上级，拖拽后弹窗确认），右侧部门详情与成员列表；岗位用页签切换。
- 用户管理的权限设置面板、部门页的公司用户任职区：增加“所属部门”（多选树，标记主部门）和“岗位”。切公司清空旧表单，未保存修改需确认；保存期间阻止离开，网络结果不明时使用原键和原内容重试。

Y-01采用V36新增五张组织表及六项权限；Y-02使用V37，不接入工作流审批人或通知发送。V36仅给具备既有用户/授权管理权限的系统管理员及演示企业仓管角色补充权限；自定义角色由管理员明确授予。

## 4. 部门数据范围（Y-02）

### 4.1 模型

现有 `sys_user_data_scope` 表示“公司 + 仓库”范围，**不改**。新增：

| 表 | 关键字段 |
|---|---|
| `org_role_data_scope` | `tenant_id`、`role_id`、`company_id`、`scope_type`（all / dept / dept_and_children / self / custom）、`version` |
| `org_role_data_scope_dept` | `tenant_id`、`role_id`、`company_id`、`department_id`（`scope_type=custom` 时使用） |

- 没有配置的角色等同 `all`，因此现有用户在 1.2.0 上线后行为不变。
- 用户有多个角色时取**并集**；再与现有仓库范围取**交集**。
- 配置主键包含企业、公司及角色，公司之间版本独立。当前公司全部部门范围且具有role:assign_permission的管理员才能保存；至少保留一位全范围有效角色管理员，角色分配、权限及停用入口同时执行保留检查。
- 本部门取当前公司全部启用任职部门，主部门只用于制单。自定义部门不自动包含下级；空集合不授予记录。组织授权从主库读取，单请求复用，下一请求反映移动及撤权。

### 4.2 单据归属

- 新增列：V37在17类单据头增加 `owner_department_id BIGINT UNSIGNED NOT NULL DEFAULT 0`、`owner_user_id BIGINT UNSIGNED NOT NULL DEFAULT 0`，完整表名见《数据库设计》Y-02章节。
- 新建单据时默认取制单人的主部门和制单人；历史单据迁移时按制单人的主部门回填，制单人没有部门的保持 0（只有 `all` 范围可见）。
- 索引：各单据表分别增加tenant/company/owner_department/business_date和tenant/company/owner_user/business_date；开票使用invoice_date。
- 归属由服务端冻结，任职移动不回写；受限用户无有效主部门或主部门不在可写范围时建单422。冲销继承原单归属，历史部门0仅全部范围可见，包括仅本人模式。

### 4.3 实现

- 在 `shared` 增加 `OrgScope`（由 `access.requireCompany` 一并计算并缓存在请求内），提供 `appendOwnerFilter(StringBuilder sql, List<Object> args, String alias)`。
- 统一使用OrgScope与OrgOwnership生成单头及来源条件；列表、计数、候选和报表在分页、汇总前过滤，详情与命令校验单头，核销检查两端来源。SQL仅拼接白名单表及服务端数字ID，不接收客户端SQL片段。
- 详情接口越权访问返回 404（不暴露单据是否存在），与现有跨公司访问一致。
- 打印、附件、旧幂等结果及冲销依赖说明沿用当前范围，隐藏不可见下游标识；对象读取完成后重新读取授权再交付。
- 库存余额与可用量是按公司仓库授权的共享实物快照，库存收发是范围内可追溯事实，页面说明口径。受限用户隐藏资金账户全公司余额，全公司关账、对账、运维和整单审计须全部部门范围。
- 导出快照新增organization，执行取初始与即时范围交集，生成和下载复检；导入org_scope_snapshot逐行约束初始边界。工作台缓存键包含完整部门条件摘要。

接口为GET/PUT `/api/v1/org/roles/{id}/data-scope`，带X-Company-Id。PUT使用CSRF、Idempotency-Key及独立version；GET返回scopeType、departmentIds、version、departments和editable。前端复用角色权限设置面板，具有切公司取消旧请求、未保存提醒、未知结果原键重试及版本冲突重新加载保护。

### 4.4 测试要点

- 本部门、含下级、仅本人、自定义四种范围，各自对列表、详情、报表、导出的可见性。
- 部门移动后，“含下级”范围立即生效。
- 多角色并集、与仓库范围交集。
- 17类详情、来源引用、写命令、分页计数、既有非空报表事实与工作台缓存隔离；无归属历史、跨企业/公司配置、最后全范围管理员保留。
- 附件慢读取撤权、打印、旧幂等结果、导出生成和下载撤权、导入断点后扩大授权不能跨出初始边界，以及原有完整业务回归。

实现细节及本机结果见《部门数据范围实施设计》《M11部门数据范围本机验收报告》。Y-02为未发布功能，后续工作流、消息与业务员功能仍按计划推进。

## 8. 站内信与消息模板（Y-05、Y-06）

### 8.1 数据模型

| 表 | 关键字段 |
|---|---|
| `notify_template` | `id`、`tenant_id`（0 为系统预置）、`code`（如 `workflow.task.assigned`）、`channel`（site / email / sms）、`title`、`content`（`{变量}` 占位）、`params`（JSON：变量名列表）、`sms_template_id`（短信平台模板号）、`status` |
| `notify_message` | `id`、`tenant_id`、`user_id`、`template_code`、`title`、`content`、`link`（前端路由，如 `/sales-orders/123`）、`category`（todo / alert / notice / system）、`read_at`、`created_at` |
| `notify_send_log` | `id`、`tenant_id`、`channel`、`template_code`、`receiver`（脱敏保存）、`status`（pending / sent / failed）、`error`、`attempts`、`created_at` |

- 索引：`notify_message (tenant_id, user_id, read_at, id)`，未读查询走索引。
- 站内信保留 180 天，由定时任务清理。

### 8.2 发送服务

```java
notifyService.send(NotifyRequest.of(scope, "workflow.task.assigned")
    .to(userIds).params(Map.of("documentNo", no, "taskName", name))
    .link("/workflow/todo/" + taskId)
    .channels(SITE, EMAIL));
```

- 业务模块**只调用 `notifyService.send`**，它在业务事务内写一条 Outbox 事件；Worker 消费事件后按渠道发送，失败按 1、5、15 分钟重试 3 次。
- 短信、邮件复用多方式登录已有的渠道配置和加密凭据；渠道未启用时只发站内信。
- 用户可在“个人设置 → 消息订阅”中关闭某类消息的邮件、短信渠道；站内信不能关闭。

### 8.3 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/notify/messages?category=&unread=` | 我的消息，游标分页 |
| GET | `/api/v1/notify/messages/unread-count` | 未读数（按类别） |
| POST | `/api/v1/notify/messages/read` | `{ids:[]}` 或 `{all:true, category}` |
| GET / PUT | `/api/v1/notify/subscriptions` | 消息订阅 |
| CRUD | `/api/v1/sys/notify-templates` | 模板维护，权限 `notify_template:*` |
| GET | `/api/v1/sys/notify-logs` | 发送日志，权限 `notify_log:view` |

### 8.4 页面

- 顶栏铃铛：未读数、最近 10 条，点击跳转 `link`；“查看全部”进入消息中心（待办 / 预警 / 公告 / 系统四个页签）。
- 系统管理 → 消息模板、发送日志。

## 9. WebSocket 推送（Z-04）

- 端点：`/ws/v1/events`；握手时校验会话（或设备令牌）和 `Origin`；每个连接绑定 `tenant_id`、`user_id`。
- 消息格式：`{"type": "notify.message", "data": {"id": "…", "category": "todo"}}`，只推摘要；类型包括 `notify.message`、`workflow.todo.changed`、`file_job.progress`、`session.kicked`。
- 多实例：发送方把事件发布到 Redis 频道 `erp:ws:{tenantId}`，每个实例只推送给本机连接的用户。
- 心跳：客户端每 30 秒 ping；服务端 90 秒无心跳断开。
- 前端 `useRealtime()`：断线后 1、2、4…最长 30 秒重连；重连成功后主动刷新未读数和待办数，防止漏消息。

## 10. 登录日志与在线用户（Y-07）

| 表 | 关键字段 |
|---|---|
| `sys_login_log` | `id`、`tenant_id`、`user_id`（失败时可能为 0）、`username`、`method`（password / sms / email / wechat / sso）、`result`（success / failed / locked / disabled）、`ip`、`user_agent`、`created_at` |

- 在现有登录成功 / 失败的代码路径上**追加**写日志（独立事务，失败不影响登录）；保留 180 天。
- 在线用户：会话创建时在 Redis 维护 `erp:online:{tenantId}` 有序集合（会话号、用户、登录时间、IP、最近访问），会话过期时清理。
- 强制下线：`POST /api/v1/sys/online-users/{sessionId}/kick`，权限 `online_user:kick`；删除 Spring Session 记录并经 WebSocket 推送 `session.kicked`，前端收到后跳登录页。

## 11. 省市区（Y-08）

- 表 `sys_area`：`id`（国家统计局行政区划代码）、`parent_id`、`name`、`level`（1 省 / 2 市 / 3 区县）。数据随迁移导入，全局共享。
- 往来单位地址、收货地址增加 `area_id`；原文本地址字段保留。
- 接口 `GET /api/v1/areas/tree`（前端缓存）；组件 `AreaCascader.vue`。

## 12. 系统参数（Z-01）

- 表 `sys_config`：`tenant_id`（0 为全局）、`config_key`、`value`、`value_type`（string / number / boolean / json）、`sensitive`、`description`、`version`。
- 敏感参数加密保存、列表中掩码显示。
- 读取：`SysConfig.get(tenantId, key, type)`，进程内缓存 60 秒，修改后通过 Redis 广播立即失效。
- 公司级业务参数仍在现有“公司与参数”，**不迁移**。

## 13. 定时任务管理（Z-02）

保留现有数据库租约 Worker，只增加登记和管理。

| 表 | 关键字段 |
|---|---|
| `job_definition` | `code`（如 `reservation.expire`）、`name`、`schedule`（cron 或固定间隔）、`enabled`、`last_run_at`、`next_run_at`、`last_result` |
| `job_run_log` | `id`、`job_code`、`trigger_kind`（schedule / manual）、`operator_id`、`node_id`、`started_at`、`finished_at`、`status`（pending / running / success / failed / skipped）、`message` |

- 现有 Worker 启动时把自己负责的任务登记（或更新）到 `job_definition`；执行前检查 `enabled`；执行后写 `job_run_log`。
- 手动触发：`POST /api/v1/sys/jobs/{code}/run`，写一条触发请求，由持有租约的 Worker 执行，避免多实例重复执行。
- 日志保留 30 天。页面：系统管理 → 定时任务（列表、启停、立即执行、执行日志）。

## 14. API 访问日志与异常日志（Z-03）

- 访问日志：Servlet 过滤器记录方法、路径模板（不含 ID 等参数值）、用户、公司、状态码、耗时、请求编号；**不记录请求体和查询参数值**。异步批量写入 `sys_api_access_log`，保留 30 天。
- 异常日志：全局异常处理器对 5xx 写 `sys_api_error_log`（异常类、消息摘要、堆栈前 20 行、请求编号），可标记“已处理”，保留 90 天。
- 与 O-28 链路追踪用同一请求编号，页面上的请求编号可以直接跳到 Grafana 链路查询。
- 慢请求（> 1 秒）在访问日志中标记，供容量优化使用。

## 16. 验收

1. 部门经理只能看到本部门及下级的单据；仅本人范围的业务员只能看到自己的单据；越权访问详情返回 404。
2. 部门移动后范围立即生效；历史单据回填正确。
3. 导入任务完成、待办到达时，铃铛在 2 秒内更新；断网重连后未读数正确。
4. 强制下线后该会话的下一次请求返回 401，页面跳转登录。
5. 定时任务在两个 Worker 实例下手动触发只执行一次。
6. 访问日志中没有请求体、手机号、密码等敏感数据。
