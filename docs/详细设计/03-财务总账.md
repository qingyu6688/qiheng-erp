# 03 财务总账（M12，目标1.4.0，未发布）

维护：maorongkang@gmail.com。实施记录见[实施设计](../M12财务总账实施设计.md)、[使用说明](../M12财务总账使用说明.md)和[本机验收报告](../M12财务总账本机验收报告.md)。本文件以本轮已实现接口为准。

## 1. 财务口径与边界

用户已确认本机样例采用每公司独立人民币账套，同时提供企业会计准则与小企业会计准则模板；往来按客户、供应商辅助明细列示，三大报表与运营账本核对。生产启用前，财务人员须在账套中确认科目、辅助、映射和公式。

预置模板是通用非金融样例，不代表所有行业及监管主体的完整法定报表。企业科目参考财政部会计准则应用指南及后续科目名称调整，小企业科目参考财会〔2011〕17号附录。企业样例增加6702信用减值损失；小企业增加1406发出商品，两套模板细分进销项税并按实际结算账户建立现金、银行明细。系统扩展项须与实际核算要求一并确认。

小企业准则不计提资产减值准备，实际坏账计入营业外支出。企业准则的账龄比例或个别认定只是估计工具，不代替财务对预期信用损失的判断。2026年新列报准则分主体实施，科目征求意见稿不作为现行正式模板。

依据：[财政部小企业准则附录](https://kjs.mof.gov.cn/zhengcefabu/201111/P020111118325852734144.pdf)、[财政部科目依据说明](https://www.mof.gov.cn/bd/mhwzzxly/hjs/202301/t20230104_3861971.htm)、[税金及附加调整](https://kjs.mof.gov.cn/zhengcefabu/201612/t20161212_2479869.htm)、[新列报实施安排](https://nb.mof.gov.cn/czjg/tongzhitonggao/202608/t20260825_3996069.htm)。

## 2. 模块及依赖

后端新增`gl`和`ar`业务模块，跨模块通过`shared`中的财务、信用、账龄端口协作，不直接注入其他模块内部服务。保留原运营`journal/journal_line`只追加事实及`ledger_balance`投影；新增总账凭证、余额和结账记录，禁止以手工总账凭证反改库存、资金余额或未清项。

原业务发布`journal.posted`。运营投影成功后发布独立`gl.journal.requested`；无启用账套时不生成总账。映射失败记入`gl_sync_error`，原业务不因此回滚；修改映射、财务重新确认后补齐。按原journal唯一生成业务凭证，扫描使用不存在关联凭证的反连接，不使用最大ID跳过迟到提交。

所有财务公司表以`tenant_id/company_id`隔离，关联使用复合外键和公司内唯一约束。全局`gl_standard_preset`只读，创建账套时复制，不共享可编辑配置。总账、信用和坏账整账权限要求明确操作权限、`cost:view`、全部仓库与全部部门范围。催收保留原未清项的部门范围交集并要求全部仓库。

## 3. 数据结构

| 分组 | 表与用途 |
| --- | --- |
| 账套及配置 | `gl_account_book`、`gl_posting_lock`、`gl_subject`、`gl_aux_type`、`gl_aux_item`、`gl_cash_flow_item`、`gl_business_mapping` |
| 凭证资料 | `gl_voucher_word`、`gl_digest`、`gl_voucher_template`、`gl_voucher_seq` |
| 凭证与余额 | `gl_voucher`、`gl_voucher_line`、`gl_opening_balance`、`gl_balance` |
| 期末及输出 | `gl_closing_scheme`、`gl_report_template`、`gl_period_close`、`gl_sync_error`、`gl_export_format` |
| 往来增强 | `ar_aging_config`、`ar_credit_limit`、`credit_increase`、`ar_customer_lock`、`ar_collection_plan`、`ar_collection_followup`、`ar_bad_debt` |

金额为`DECIMAL(24,2)`，数量6位、单价8位；Java使用BigDecimal，JSON中的金额及长编号使用字符串。七个辅助维度固定为customer、supplier、dept、employee、project、sku、custom，未填写内部以0表示。客户/供应商、SKU沿用企业共享主数据；部门、员工任职、自建项目和自定义辅助按当前公司校验。不能只依靠前端选项防越权。

凭证来源为manual/business/closing/opening。状态为draft→pending→approved→posted，红字记账后原凭证成为reversed。草稿允许暂存未平衡，提交必须平衡。审核人与制单人分离；已记账不可编辑或删除。红字沿用原科目、辅助、现金流和同方向负数，须再次经独立复核记账，保留原凭证事实。业务凭证只读，业务冲销从原业务办理。

## 4. 配置、期初与启用

1. 选择公司、准则及开放启用期间，复制科目、辅助类型、现金流项目、运营映射、凭证字、结转方案和报表模板。
2. 配置末级科目及所需辅助；已使用科目不得改核算结构，父科目不能直接录分录。现金及银行分录必须有现金流项目。
3. 期初建议仅从启用前运营分录计算启用期初，不自动保存，也不推测年初与本年累计。按辅助维度补齐年初、本年借贷累计、启用期初和数量，核对三组试算。
4. 财务确认保存配置摘要。任何配置或期初变更都会使确认失效，必须重新核对。启用前历史期间须全部关闭；存在总账记账事实后禁止反启用。
5. 启用时冻结运营映射；启用前原业务在启用后冲销时使用冻结映射和原来源上下文，已生成总账的业务冲销直接复制原凭证映射。

锁顺序：期间共享锁（关账为按期有序排他锁）→账套→公司记账协调行→凭证及余额。公司之间不共享记账锁。幂等命令在执行或读取旧结果时重新校验当前公司、成本权限及数据范围。

## 5. 账簿及公式报表

| 查询 | 实际接口 |
| --- | --- |
| 科目余额表 | `GET /api/v1/gl/ledgers/balance` |
| 总分类账、明细账 | `/gl/ledgers/general`、`/gl/ledgers/detail` |
| 多栏账 | `/gl/ledgers/multi_column`，每张凭证一行，各科目借正贷负横向汇总 |
| 数量金额、辅助余额 | `/gl/ledgers/quantity`、`/gl/ledgers/auxiliary` |
| 序时凭证 | `/gl/vouchers`，按期间、凭证字、状态及来源过滤 |
| 三表 | `/gl/reports/{balance_sheet|income_statement|cash_flow}?periodId=`；兼容`/gl/statements/{type}` |
| 指标 | `/gl/indicators?periodId=` |

账簿参数为periodFrom、periodTo、subjectId、auxType、auxId、dateFrom、dateTo、level、cursor、limit。最多24个月，明细最多10000行；数量账读取凭证数量，不能用它代替运营库存数量账。查询包含posted及reversed原凭证与红字事实。

公式使用受限解析器，支持四则运算、括号、QC/QM期初期末、JF/DF借贷发生、LJ本年累计、XJ现金流项目、R行引用、CAT类别和PL_NET、CASH_QC、CASH_QM等内部取数。函数参数及方向须符合白名单；不执行脚本，检查长度、节点数、深度、引用与循环、除零和数值范围。页面可调整公式及勾稽条件，点击金额查看构成，科目可跳转账簿。

资产负债表按相同辅助组合合并子科目后分借贷列示，不跨客户、供应商抵销；税金进销项在同一辅助下先合并。第二列为年初数。利润表本期、本年累计排除损益结转及反结账结转流水，结账后仍保留实际发生额。现金流项目分经营、投资、筹资及内部转账；现金流净额须等于现金类期末减期初。

年中启用没有启用前现金流分类时，全年现金流累计返回null及yearNotice，本期照常计算并核对。不能以部分月份假称全年数。年初及本年累计准确性以财务录入的期初资料为前提。

指标包括流动、速动、资产负债、毛利、净利比率及应收、存货周转天数。分母为零返回null及说明。流动分类为通用样例，可在资产负债表增加current_assets/current_liabilities公式行覆盖；周转取期间两端平均值。

## 6. 期末六步与反结账

工作台依次展示业务检查、业务凭证、手工凭证、损益结转、对账报表和关闭滚入。实际关闭仍在一个服务器事务内复核最新事实，所有入口含原period.close都强制相同规则：配置已确认、原运营投影及总账业务凭证齐全、无未记账凭证、试算平衡、原业务逐行金额与总账一致、三表勾稽通过。

损益按结转方案转本年利润，以前年度损益按独立方案转利润分配；结账保存本轮报表快照，并滚入下一开放期间。当前月未结束不得提前关闭，先关前期，必须准备下一期。只能重开最近已关闭期间，反结账追加本轮结转的红字，保留历史；重开、回冲失败整体回滚。启用前期间不能通过旧入口重开。

对账任务增加gl_trial及gl_operational，分别核对缓存/事实/辅助及原journal_line与业务凭证逐行映射金额。结果、差异、旧命令及文件都重查即时权限。

## 7. 账龄、信用、催收与坏账

账龄基于原partner_open_item，按公司配置1—10个递增边界及比例；默认30/60/90/180天。原应收应付账龄报表保留旧字段，新增动态区间及业务员、部门汇总，原部门范围继续取交集。

信用暴露=未清应收+待审及已批准/关闭/变更待审订单中未转应收的履约承诺−未核销客户预收，最低0。已出库未签收仍占用，撤回、拒绝和关闭数量自动释放相应承诺。额度及临时调增按当前中国业务日期判断有效期。

公司客户额度行先加锁，再锁单据；提交、批准、变更增加及发货提交/出库均重检。独立主库只读连接读取最新已提交暴露，避免旧事务快照及主连接池嵌套耗尽。warn返回通用提示，不向普通业务人员泄漏欠款总额；block返回409拒绝；approval必须经过销售流程人工creditApproval节点，并具有当日额度/暴露/订单指纹。审批证据失效时不能继续放行。没有绑定或可达信用节点时禁止降为普通单级批准。

发货时暴露变化仍超额，须先办理临时额度调增审批或收款；不新增自动库存过账流程。临时额度独立制单复核，可绑定credit_increase工作流，最长一年，过期不再生效。

催收计划关联未清项，负责人须具有当前权限和原单范围；可记录沟通、承诺日期金额、完成或取消。固定任务ar.collection_remind在到期前3日、当天、逾期每7日创建现有消息中心站内信，按日期键幂等，读取时再次检查原来源权限。

企业准则支持账龄比例/个别认定计提、转回多提准备、实际坏账核销；准备不足拒绝核销。小企业只允许实际损失核销。由另一人复核后追加原运营账本，再生成只读总账凭证。核销使用bad_debt_write_off分配，不改原receivable金额，不允许独立撤销该分配绕过坏账复核。估计和准备余额按认定日期截止。

## 8. 导出、打印及部署

复用现有export_job、后台Worker、私有对象仓、下载票据与24小时过期机制。支持已记账凭证、六种账簿、三表的CSV/XLSX；创建时冻结软件列映射，执行、列表、票据及下载I/O后均复核当前权限。CSV防公式注入且保留合法负数；XLSX编码和长编号写文本单元格。软件列模板可调，需用实际用友/金蝶版本试导，不承诺所有版本直接兼容。

打印接口为`GET /gl/print/{type}`：凭证带id，三表带期间id，账簿带查询条件；独立打印页显示公司、日期、制单复核姓名与辅助名称，浏览器负责分页打印。界面切公司立即清空旧数据并丢弃迟到响应。

新增V47—V51，禁止修改已执行迁移。先备份，在隔离库验证升级、历史事实不变和角色权限，再以迁移账号更新结构、以仅DML运行账号启动API/Worker。运行角色对gl_standard_preset只读；新增财务权限只向既有合格系统管理员补齐，自定义角色须明确分配。生产确认、目标环境容量及恢复演练仍是正式发布前条件，当前候选构建版本保持1.0.0。

## 9. 验证要求

真实MySQL测试覆盖隔离、受限数据范围、撤权与幂等重放、凭证审核分离、并发记账、只读业务凭证、红字、批量原子性、公式拒绝、两准则坏账差异、信用并发/人工审批/失效/临时额度、催收幂等、导出及下载撤权。

验收用真实原业务命令完成存货和资金期初、销售审批、出库签收、收款、十张费用/工资/折旧计提凭证，再通过原期间入口结转、三表核对、业务毛利核对及反结账。浏览器使用独立企业验证创建账套、制单、另一人复核、记账、报表、打印与后台导出。最终结果以本机验收报告及GitHub最终提交CI为准。
