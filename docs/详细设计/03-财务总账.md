# 03 财务总账（1.4.0）

> 对应：《功能扩展方案》第 8 节；《企业级演进规划》F-01、F-02、F-03。
> 新增包：`gl`；应收应付增强放在现有 `salesfinance`、`purchasefinance` 中新增类。

---

## 1. 范围

| 功能 | 说明 |
|---|---|
| 账套 | 每家公司一个账套：会计准则、本位币、启用期间 |
| 科目 | 按准则预置一级科目，可增下级明细科目；余额方向、辅助核算、现金类标记 |
| 辅助核算 | 客户、供应商、部门、员工、项目、存货、自定义 |
| 凭证 | 手工凭证录入、审核、记账、冲销；业务凭证自动生成且只读 |
| 期初 | 科目和辅助核算期初，试算平衡后启用 |
| 账簿 | 总账、明细账、科目余额表、辅助核算余额表、多栏账、序时账 |
| 期末 | 结转损益等结转方案；与业务关账合并的结账流程 |
| 报表 | 资产负债表、利润表、现金流量表（公式可配置）；财务指标 |
| 应收应付增强 | 账龄、信用额度与超额控制、催收计划、坏账准备 |
| 导出 | 凭证导出到常用财务软件的导入格式 |

## 2. 与现有账本的关系

现有系统已经有一套**运营账本**：`ledger_account`（系统固定的业务账户，如 `AR`、`INVENTORY`、`SALES_REVENUE`）、`journal` / `journal_line`（业务过账自动产生的分录）、`ledger_balance`（按期间和维度的余额投影）。这套账本支撑对账和关账，**保持不变**。

总账是在其上的**正式会计账**：

```text
业务单据过账 ──► journal / journal_line（运营账本，已有）
                    │ Outbox 事件 ledger.journal.posted
                    ▼
            gl 模块：按科目映射生成业务凭证（gl_voucher，source=business，只读）
                    +
            财务人员录入手工凭证（gl_voucher，source=manual）
                    ▼
            gl_balance（科目 × 辅助核算 × 期间）──► 账簿、报表
```

- 每张运营分录生成一张业务凭证，凭证上保留来源单据，可点击跳转。
- 映射规则 `gl_business_mapping`：运营账户码 + 条件（如收支项目、结算账户类型）→ 科目 + 辅助核算取值方式。映射不完整时，事件处理失败并进入预警，财务补全映射后重放。
- **启用前的历史分录**：账套启用时，按启用期间之前的运营余额生成期初，不回溯生成凭证。

## 3. 数据模型

### 3.1 账套与科目

| 表 | 关键字段 | 说明 |
|---|---|---|
| `gl_account_book` | `id`、`tenant_id`、`company_id`（唯一）、`standard`（enterprise / small_enterprise）、`currency`（CNY）、`start_period_id`、`status`（setup / active）、`version` | 账套 |
| `gl_subject` | `id`、`tenant_id`、`company_id`、`code`（如 `1122`、`112201`）、`name`、`parent_id`、`level`、`category`（asset / liability / equity / cost / income_expense / common）、`direction`（D / C）、`is_cash`、`is_bank`、`is_leaf`、`aux_types`（JSON：如 `["customer","dept"]`）、`quantity_unit`（数量核算单位，可空串）、`status`、`version` | 唯一键 `(tenant_id, company_id, code)`；有余额或已被凭证使用的科目只能停用 |
| `gl_aux_type` | `id`、`tenant_id`、`code`、`name`、`source`（customer / supplier / dept / employee / project / sku / custom） | 内置六种 + 自定义 |
| `gl_aux_item` | `id`、`tenant_id`、`aux_type_id`、`code`、`name`、`status` | 自定义核算项目（项目、自定义）；客户、供应商、部门、员工、存货直接引用现有主数据 ID |
| `gl_cash_flow_item` | `id`、`tenant_id`、`code`、`name`、`direction`（in / out）、`category`（operating / investing / financing） | 现金流量项目，预置 |
| `gl_business_mapping` | `id`、`tenant_id`、`company_id`、`ledger_account_code`、`condition_json`、`subject_id`、`aux_rules`（JSON）、`cash_flow_item_id`、`priority` | 运营账户 → 科目映射 |

预置科目：随迁移导入《企业会计准则》和《小企业会计准则》两套一级科目及常用二级科目，账套创建时按所选准则复制到公司。

### 3.2 凭证

| 表 | 关键字段 |
|---|---|
| `gl_voucher_word` | `id`、`tenant_id`、`company_id`、`code`（记 / 收 / 付 / 转）、`print_title`、`is_default` |
| `gl_voucher` | `id`、`tenant_id`、`company_id`、`period_id`、`word_id`、`number`（期间内按凭证字连续）、`voucher_date`、`source`（manual / business / closing / opening）、`source_type`、`source_id`、`source_no`、`attachment_count`、`debit_total`、`credit_total`、`status`（draft / pending / approved / posted / reversed）、`maker_id`、`approver_id`、`poster_id`、`reversal_of_id`、`remark`、`version` |
| `gl_voucher_line` | `id`、`voucher_id`、`line_no`、`digest`（摘要）、`subject_id`、`direction`、`amount`、`quantity`、`unit_price`、`aux_customer_id`、`aux_supplier_id`、`aux_dept_id`、`aux_employee_id`、`aux_project_id`、`aux_sku_id`、`aux_custom_id`、`cash_flow_item_id` |
| `gl_digest` | 常用摘要 |
| `gl_voucher_template` | 常用凭证模板（分录结构，不含金额或含默认金额） |

- 辅助核算列都用 `BIGINT NOT NULL DEFAULT 0`，便于唯一键和汇总。
- 约束：`debit_total = credit_total` 在审核时校验；每行金额 > 0；科目必须是末级；科目要求的辅助核算必须填写。
- 凭证号：表 `gl_voucher_seq(company_id, period_id, word_id, next_no)`，取号时 `SELECT … FOR UPDATE`；断号允许（删除草稿不回收），提供“整理凭证号”功能在期间结账前重新编号（只对未记账凭证）。

### 3.3 状态机

```text
手工凭证：draft ──提交──► pending ──审核──► approved ──记账──► posted
              ▲              │驳回                          │
              └──────────────┘                              └─冲销──► reversed（生成红字冲销凭证）
业务凭证：生成即 posted（只读，只能通过冲销原业务单据更正）
结转凭证：结账流程生成，posted
```

- 审核人不能是制单人（与现有经办复核分离一致）。
- 记账后不能修改、删除；更正只能冲销（红字凭证）或补录调整凭证。
- 已结账期间不能新增、审核、记账凭证。

### 3.4 余额

| 表 | 关键字段 |
|---|---|
| `gl_balance` | `tenant_id`、`company_id`、`period_id`、`subject_id`、六个辅助核算列、`opening_debit`、`opening_credit`、`debit`、`credit`、`closing_debit`、`closing_credit`、`quantity_*` |

- 记账时在同一事务中更新余额（按唯一键 UPSERT，行别名写法）。
- 加锁顺序：期间（共享）→ 凭证 → 余额（按唯一键排序后逐行），见《00 总体技术设计》2.5。
- 期末余额 = 期初 + 发生；下一期间期初在结账时滚入。
- 对账：新增“总账试算平衡”和“总账与运营账本一致性”两项对账，纳入现有对账任务。

## 4. 期初与启用

1. 创建账套：选准则、启用期间（必须是现有已开放的会计期间）。
2. 系统按启用期间之前的运营余额生成期初建议（应收、应付、库存、资金按辅助核算明细）。
3. 财务补录其他科目期初（固定资产、实收资本、未分配利润等）。
4. 试算平衡：资产 = 负债 + 所有者权益；借贷平衡。不平衡时不能启用，页面列出差额和明细。
5. 启用后期初锁定；需要修改时“反启用”，只在启用期间还没有记账凭证时允许。

## 5. 期末结账

结账与现有业务关账合并为一个向导（会计期间页面）：

```text
① 业务关账检查（现有五项）
② 业务凭证生成完成（运营分录都已生成凭证，没有映射失败）
③ 手工凭证都已记账（没有草稿、待审核、已审核未记账）
④ 执行结转方案（结转损益、结转制造费用等）→ 生成结转凭证并记账
⑤ 试算平衡、总账与运营账本一致
⑥ 关闭期间：业务期间与财务期间一起关闭，余额滚入下期
```

- 结转方案 `gl_closing_scheme`：名称、顺序；模板 `gl_closing_template`：转出科目范围、转入科目、按余额方向结转。预置“结转损益”。
- 反结账：沿用现有“重开最近期间”，同时冲回结转凭证。

## 6. 账簿与报表

### 6.1 账簿

| 账簿 | 接口 | 说明 |
|---|---|---|
| 科目余额表 | `GET /api/v1/gl/reports/subject-balance?periodFrom=&periodTo=&level=` | 期初、发生、期末，支持按级次汇总 |
| 总账 | `GET /api/v1/gl/reports/general-ledger?subjectId=&periodFrom=&periodTo=` | 按期间汇总 |
| 明细账 | `GET /api/v1/gl/reports/detail-ledger?subjectId=&auxType=&auxId=&dateFrom=&dateTo=` | 逐笔，点击跳凭证 |
| 辅助核算余额表 | `GET /api/v1/gl/reports/aux-balance?subjectId=&auxType=` | 例如按客户的应收余额 |
| 多栏账 | `GET /api/v1/gl/reports/multi-column?subjectId=` | 按下级科目分栏，用于费用分析 |
| 序时账 | `GET /api/v1/gl/reports/journal?dateFrom=&dateTo=` | 按凭证日期顺序 |

所有账簿都支持导出（走现有后台导出任务）和打印。

### 6.2 财务报表

- 模板表 `gl_report_template`：`report_type`（balance_sheet / income_statement / cash_flow）、`standard`、行定义 JSON（行号、项目名称、公式、是否加粗、缩进）。
- 公式语法（后端解析，不使用表达式引擎执行任意代码）：

  | 函数 | 含义 |
  |---|---|
  | `QC(科目)` | 期初余额 |
  | `QM(科目)` | 期末余额 |
  | `JF(科目)` / `DF(科目)` | 本期借方 / 贷方发生额 |
  | `LJ(科目)` | 本年累计发生额（损益类） |
  | `XJ(项目编码)` | 现金流量项目发生额 |
  | `R(行号)` | 引用本表其他行 |

  例：货币资金 `QM(1001)+QM(1002)+QM(1012)`；应收账款 `QM(1122,借方)-QM(1231)`。
- 接口：`GET /api/v1/gl/statements/{type}?periodId=`，返回行数组和每行的公式来源；页面点击金额可查看构成。
- 资产负债表检查“资产总计 = 负债和所有者权益总计”，不等时页面标红并显示差额。
- 现金流量表：业务凭证的现金类分录按映射自动带出现金流量项目；手工凭证录入现金类科目时必须选项目。

### 6.3 财务指标

流动比率、速动比率、资产负债率、毛利率、净利率、应收账款周转天数、存货周转天数；接口 `GET /api/v1/gl/indicators?periodId=`，用于工作台和 2.0 驾驶舱。

## 7. 应收应付增强

### 7.1 账龄

- 基于现有 `partner_open_item` 计算，账龄区间可配置（默认 0—30、31—60、61—90、91—180、180 天以上）。
- 现有十类报表中已有应收、应付账龄，本版只增加**区间配置**和**按业务员、部门汇总**。

### 7.2 信用额度

| 表 | 关键字段 |
|---|---|
| `ar_credit_limit` | `tenant_id`、`company_id`、`partner_id`、`limit_amount`、`overdue_days_limit`（超期天数上限，0 不控制）、`policy`（warn / approval / block）、`valid_from`、`valid_to`、`version` |

- 占用额度 = 未收应收余额 + 已审批未发货的订单金额 − 未核销预收。
- 校验时机：销售订单提交；发货单提交（防止订单审批后欠款增加）。
- 加锁：在“未清项”层取该客户的额度行锁，避免并发提交同时通过。
- 超额处理：`warn` 提示；`approval` 作为工作流条件变量 `overCreditLimit=true`；`block` 拒绝并返回 409 `CREDIT_LIMIT_EXCEEDED`，说明当前占用、额度和差额。
- 临时额度：可录入有效期内的临时调增，审批后生效。

### 7.3 催收计划

- 表 `ar_collection_plan`：客户、负责人、计划日期、计划金额、关联未清项、状态、跟进记录。
- 到期前 3 天、到期当天、逾期每 7 天给负责人发站内信。
- CRM 上线后，催收跟进与 CRM 跟进记录合并展示。

### 7.4 坏账准备

- 按账龄比例法或个别认定法计提；每月生成计提凭证（借：信用减值损失，贷：坏账准备）。
- 核销坏账：生成核销凭证并在现有未清项上做“坏账核销”分配（新增一种分配类型，不改现有类型）。

## 8. 凭证导出

- 导出格式：通用 CSV、Excel；预置用友、金蝶常用凭证导入模板的列映射，可在页面调整映射后保存。
- 走现有后台导出任务，导出前检查科目映射完整性。

## 12. 测试要点

1. 用一个月样例业务：所有运营分录都生成业务凭证，总账余额与运营账本一致。
2. 手工凭证：借贷不平不能提交；制单人不能审核；记账后不能改；冲销生成红字凭证。
3. 并发记账同一科目余额，结果正确无死锁。
4. 结转损益后损益类科目余额为 0；资产负债表平衡；利润表净利润 = 未分配利润本期变动。
5. 现金流量表合计 = 货币资金期末 − 期初。
6. 信用额度：两个订单并发提交、合计超额时只有一个通过（`block` 策略）。
7. 坏账核销后应收账龄报表和总账一致。

## 13. 验收

一个月样例业务 + 10 张手工凭证（费用、工资计提、折旧）→ 结账 → 三大报表平衡；利润表毛利与业务毛利报表一致；信用超限订单按配置被拦截或进入审批。
