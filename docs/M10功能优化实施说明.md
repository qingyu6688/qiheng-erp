## 默认账户

V34 增加结算账户的两种默认用途和生成列唯一索引。每家公司每种用途最多一项，同一账户可以兼任收款和付款。切换先锁公司、再锁目标账户，在一个事务中清除旧默认、设置新默认并增加相关账户版本；并发设置由数据库约束兜底。

设置接口为 `POST /api/v1/cash-accounts/{id}/set-default`，需要公司范围、`cash_account:update` 权限、CSRF、幂等键和账户版本。停用账户会清除两种默认用途。审计不记录银行账号。新增收付款单自动选择启用的默认账户，编辑草稿保留已选账户。

## 工作台金额

接口为 `GET /api/v1/workbench/trade-summary?months=12`，月份范围 1—12。销售沿用报表的签收确认金额，采购沿用过账收货金额，包含退货、费用及已过账冲销的正反向事实。按业务日期统计，以北京时间确定今日、昨日、本月、本年，趋势补齐无业务月份。

权限使用 `report:sales_summary` 和 `report:purchase_summary`，仅返回有权查看的块。公司、租户、仓库范围在查询中限制；部门范围随 1.2.0 的 Y-02 引入，本轮没有提前开放部门功能。Redis 缓存五分钟，键包含租户、公司、用户、仓库范围、权限、月份数和业务日。请求仍由主库即时校验当前身份和范围，撤权后不能读取旧权限缓存。

工作台金额与待办分别加载，金额失败可单独重试。切换公司中止旧请求并清空旧结果。折线图按需注册 ECharts 组件，图表和绘制器拆分构建，金额展示保留十进制字符串。

## 报表只读连接

API 和 Worker 均可配置 `ERP_REPORT_JDBC_URL`、`ERP_REPORT_DB_USER`、`ERP_REPORT_DB_PASSWORD`。配置后，十类报表、导出和工作台金额的事实查询使用独立只读池，最大五个连接；身份、权限、任务状态和业务写入继续使用主库。连接等待三秒、连接建立三秒、网络读取三十秒，备库异常由现有错误处理返回或记录导出失败，不自动转向主库。

未配置 URL 的本机开发与既有部署沿用主库。生产示例已给出备库配置，正式环境需要 MySQL 的 `read_only`、`super_read_only`，以及只有报表相关表 `SELECT` 权限的独立账号，不能只依赖 JDBC 的只读标记。授权生成脚本增加 `erp_report_role`，生成后仍需按原流程审阅执行。

V35 增加全局复制水位表。启用 Worker 的实例每五秒在主库提交 UTC 心跳；该事务经复制到达备库。报表在同一个可重复读事务中读取业务事实及水位，`asOf` 返回最近确认的复制截止时间。复制暂停时水位停止前进。它表示保守的已复制时间，不保证包含当时尚未提交的业务事务。工作台缓存还可能增加最多五分钟的展示延迟，页面始终展示缓存结果对应的 `asOf`。

迁移只在主库执行，API 和 Worker 需要使用相同备库配置。先确认 V35 复制完成、报表账号可读取水位，再放行流量。复制延迟监控、故障切换和目标环境容量验收按《运维手册》和《上线准备清单》执行。
