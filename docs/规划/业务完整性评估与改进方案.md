> 版本：1.0.7　　日期：2026-11-24
> 依据：`main`（含 `v2.0.0-rc.2` 之后的阶段 A 合并，最新迁移 `V103`）的代码与迁移脚本，《业务规则》《用户使用手册》《开发计划》《优化文档》《企业级演进规划》。

## 1. 结论

**主干流程是完整的，正确性底座扎实。** 购销存的单据链、库存预留、应收应付确认时点、核销、冲销、期间屏障和八类对账都有明确规则、代码和测试，按《业务规则》设计的“过账后只能冲销、同一套事实记账”在各模块里一致执行。对商贸、批发和轻制造的中小企业，日常业务可以在系统里闭环。

**发现一处确定的业务缺陷，需要在 2.0.0 正式发布前修复：**

- 应收、应付表有到期日字段，但没有任何代码写入它，客户和供应商也没有账期设置。结果是“应收逾期”预警永远不会触发，经营驾驶舱的“逾期应收”把所有今天以前的未清应收都算成逾期（B-01）。

**有几处日常经营一定会遇到、现在只能绕路处理的缺口：**

- 已签收或已收货后的价格调整与折让（B-02）。
- 采购运费、装卸费不进存货成本，毛利偏高（B-03）。
- 进项发票只能和应付一对一手工关联，没有金额核对和“已收货未到票”统计（B-04）。
- 没有原单的销售退货无法处理（B-05）。
- 补录历史日期单据后，成本不能受控地回溯重算（B-06）。

**文档与代码不一致：** 《业务规则》第 1 节的范围假设和《优化文档》的待办表停留在早期版本，已实现的功能仍写成“不做”或“待修复”（B-09）。

## 4. 改进方案

每项按“规则 → 数据 → 接口与页面 → 账务与对账 → 测试与验收”写。迁移文件从 `V104` 起按实施顺序编号，不修改已有迁移。

### B-01 账期与到期日（P0）

**规则**

- 往来单位按角色设置账期，两种方式：
  - **按天**：到期日 = 业务日期 + N 天（N 取 0—365，0 表示现结）；
  - **月结**：到期日 = 业务日期所在月的次月 N 日（N 取 1—28）。
- 公司参数里有默认账期，往来单位没设置时使用默认值；默认值也没设置时，到期日为空，**到期日为空的往来不算逾期**。
- 销售订单、采购订单在**审批通过时**把账期快照到单据上；之后修改往来单位账期，不影响已批准订单产生的应收应付。
- 应收在签收确认时、应付在收货过账时，按单据快照计算到期日写入；费用行与同单商品行用同一到期日；退货冲减项沿用被冲减项的到期日；期初往来可手填到期日，不填时按账期计算。

**数据**（`V104__partner_payment_terms.sql`）

- `partner_role` 增加 `term_type`（`days` / `monthly`，可空）和 `term_value`（`SMALLINT UNSIGNED`，可空），配 CHECK 约束。
- `company_policy` 增加默认账期两列。
- `sales_order`、`purchase_order` 增加账期快照两列。
- 回填：已审批未完结的订单按当前往来单位账期写快照；**已存在的未清应收应付不回填到期日**，在升级说明里列出，由财务决定是否批量设置（提供一次性脚本，按业务日期 + 账期计算，需管理员确认后执行）。

**接口与页面**

- 往来单位编辑页的客户、供应商设置增加“账期”；公司参数增加“默认账期”。
- 销售、采购订单详情显示账期；应收、应付明细和账龄报表增加“到期日”“逾期天数”列。
- 账龄报表增加口径切换：“按业务日期”（现有）和“按到期日”（新增逾期账龄）。
- 《接口设计》补充字段说明；开放平台的往来单位接口同步增加账期。

**账务与对账**

- 驾驶舱逾期应收改为 `r.due_date IS NOT NULL AND r.due_date < :today`。
- 应收逾期预警沿用现有规则，不需要改；应付侧新增“应付即将到期”预警（提前天数可配），供资金计划使用。
- 到期日只影响提醒和报表，不影响核销顺序和总账，八类对账不变。

**测试与验收**

- 单元测试：两种账期的到期日计算，覆盖月末、闰年、次月 28 日。
- 集成测试：从订单审批到签收、收货，真实写入的应收应付带到期日；修改往来单位账期后，已批准订单不受影响；退货冲减项沿用原到期日。
- 删除 `AlertCenterIT` 里手工插入 `due_date` 的捷径，改为走真实签收流程触发逾期预警。
- 驾驶舱逾期金额：未设账期的客户不计入，设了 30 天账期的客户在第 31 天计入。

### B-02 价格调整单（P1）

**规则**

- 新增“销售价格调整单”和“采购价格调整单”，只能针对**已签收的发货行**或**已过账的收货行**，按行填调整后的含税单价或调整金额，正数为补收（补付），负数为折让（返利）。
- 金额、税额、尾差按 R3 规则计算，调整单本身要审批（接入现有工作流），审批人与制单人不同。
- 过账：销售侧产生一笔应收（正）或应收冲减（负），进入未清项，可在核销工作台处理；采购侧同理产生应付。
- 采购调价对成本的影响：对应入库行**仍在库的部分**调整库存总成本；**已出库的部分**记入成本差异（沿用 `cost_adjustment`）。
- 已开票的行做销售折让时，提示需要开具红字发票，并可从调整单跳转到数电红字开票。
- 调整单过账后只能冲销，冲销生成反向往来和成本调整。

**数据**（`V105__price_adjustments.sql`）

- `price_adjustment`（头）和 `price_adjustment_line`（行，引用 `shipment_line` 或 `goods_receipt_line`，记录原单价、新单价、调整未税额、税额、含税额、成本处理结果）。
- 应收、应付的 `source_type` 增加 `price_adjustment_line`。

**接口与页面**

- 发货单、收货单详情增加“调价”入口；独立的调整单列表和详情页，沿用单据列表模板。
- 销售报表、采购报表、销售毛利按调整后的金额统计，调整单单独可穿透。

**账务与对账**

- 总账业务映射新增：销售调价（收入、销项税、应收），采购调价（存货或成本差异、进项税、应付）。
- 在“应收应付与单据一致”“库存成本与总账一致”两类对账中纳入调整单。

**测试与验收**

- 部分签收后调价、调价后再退货、调价后冲销，往来、成本、总账三方一致，八类对账零差异。
- 采购调价时入库已部分出库：在库部分进成本，已出部分进差异，合计等于调整额。

### B-03 采购运杂费分摊进成本（P1）

**规则**

- 公司参数“采购费用计入存货成本”，默认开启；关闭时保持现在的行为。
- 两种来源：
  - **随单费用**：采购订单上我方承担的运费、装卸费（`purchase_order_fee`），在收货过账时按本次收货分摊；
  - **事后费用**：承运商另开的运费，新增“采购费用单”，引用一张或多张收货单录入。
- 分摊方式可选按金额、按数量、按重量（SKU 已有重量），逐分舍入，尾差落在金额最大的一行，分摊合计等于费用额。
- 被分摊的入库行仍在库的部分进库存成本，已出库的部分进成本差异（与 B-02 采购调价同一套处理）。
- 采购费用单产生对承运商（往来单位，供应商角色）的应付。

**数据**（`V106__purchase_landed_cost.sql`）

- `company_policy` 增加开关和默认分摊方式。
- `purchase_fee_doc`、`purchase_fee_doc_line`（费用行）、`purchase_fee_allocation`（落到收货行的分摊结果和成本处理结果）。

**接口与页面**

- 收货单详情显示每行“货款成本 + 分摊费用 = 入库成本”。
- 采购费用单：选择收货单、填费用、预览分摊、提交审批、过账。

**账务与对账**

- 总账映射：借存货（或成本差异），借进项税，贷应付（承运商）。
- 库存成本对账纳入分摊记录；修改《业务规则》R6-11 为新规则，旧数据不回溯。

**测试与验收**

- 三种分摊方式逐分舍入、合计相等；部分出库后到达的事后运费，在库与已出部分拆分正确。
- 关闭开关时结果与现在完全一致（回归保护）。

### B-04 进项发票核对与暂估（P1）

**规则**

- 进项发票（数电接收或手工登记纸质票）与应付是多对多关系：一张发票可核对多张收货产生的应付，一张应付可被多张发票分批核对。
- 核对时比较未税金额和税额：差异在公司设定的容差内（默认 1.00 元）自动记为尾差；超出容差不允许核对，引导去做采购价格调整（B-02）或退回供应商。
- 应付有“未到票、部分到票、已到票”三种开票状态；新增“已收货未到票”报表，按供应商、收货单列出未到票金额，作为财务月末暂估的数据来源。
- 是否在总账做暂估凭证、暂估是否次月冲回，按公司参数决定，默认不做，只提供报表（需财务确认，见第 6 节）。

**数据**（`V107__inbound_invoice_matching.sql`）

- `einv_inbound_match`（发票、应付、核对未税额、核对税额、差异额）；保留 `einv_inbound.payable_id` 一个版本作兼容，迁移时把已有关联转成 match 记录。
- `einv_inbound` 增加 `source`（`einv` / `manual`），支持手工登记。

**接口与页面**

- 进项发票列表增加“待核对 / 部分核对 / 已核对 / 有差异”状态；核对页左侧发票、右侧候选应付，勾选后显示差额。
- 供应商对账报表增加开票状态。

**测试与验收**

- 一票多单、一单多票、容差内尾差、超容差拒绝；冲销收货后，已核对发票回到待核对并提示。
- 迁移后原有一对一关联数据完整，金额一致。

### B-05 无源销售退货（P2）

- 销售退货单增加“无原单退货”模式，需单独权限 `sales_return:sourceless`，必须审批。
- 退货单价手填，成本按退回仓当前单位成本入库；该 SKU 在该仓当前数量为 0 时取最近一次入库单价，仍取不到的由操作人填写并在审批中显示。
- 产生应收冲减（客户信用余额），沿用现有退款流程。
- 修改 Q11、R5-01；在库存成本对账中标记无源退货，便于审计抽查。

### B-06 受控成本重估（P2）

- 新增成本重估任务：选择公司、仓库、SKU 和起算日，系统按过账时间重放该范围内的出入库，计算新的出库成本。
- 只允许重估**仍在开放期间**内的单据；差额生成成本调整记录，不改写原出库行快照。
- 任务需要审批，执行前出差异预览，执行时持有该 SKU 的成本锁，执行结果写审计。
- 验收：补录一张早于已有出库的入库单后重估，出库成本差额等于理论值，库存成本对账零差异。

### B-07 采购价格表（P2）

- `price_list_target` 增加 `supplier` 目标；价格表带有效期和数量阶梯（沿用现有结构）。
- 采购订单取价顺序：供应商价格表 → 最近一次该供应商采购价 → SKU 默认采购价；页面显示价格来源。
- 采购订单单价高于价格表时提示（可在公司参数中设为需要审批）。

### B-08 销售报价单（P3）

- 报价单引用 CRM 商机（可选），带有效期、价格口径和明细；低于最低售价的报价走现有最低售价审批。
- 报价单可一键转销售订单，转单后报价单关闭；过期自动标记为失效，不自动删除。
- 视客户需求排期，不阻塞 2.x 发布。

### B-09 文档对齐（P1，与 B-01 同批完成）

- 《业务规则》第 1 节按现状重写范围假设：批次、序列号、库位已支持；数电开票功能已实现，真实服务商待对接验收；总账出三大报表；信用额度按客户控制。保留原编号，用“变更记录”说明从何时起不同。
- 《优化文档》删除已完成的 O-30、O-33、O-34，补充完成说明到《更新日志》，升版本号。
- 两份文档是 AI 知识库种子，修改后重新导入知识库并跑一次知识问答评测。

## 6. 需要业务方和财务确认的问题

| 序号 | 问题 | 建议默认 |
|---|---|---|
| 1 | 账期方式是否只需要“按天”和“月结次月 N 日”两种？是否需要按订单单独改账期？ | 两种方式；订单可在审批前修改，审批后锁定 |
| 2 | 升级前已存在的未清应收应付，是否按当前账期批量补到期日？ | 提供脚本，由财务决定是否执行 |
| 3 | 采购运杂费是否计入存货成本？小规模纳税人的公司是否同样处理？ | 计入；小规模纳税人按含税金额计入 |
| 4 | 运杂费默认按金额、数量还是重量分摊？ | 按金额 |
| 5 | 进项发票核对容差多少？是否需要总账暂估凭证，暂估是否次月冲回？ | 容差 1.00 元；暂估只出报表，不做凭证 |
| 6 | 无源退货的成本取数和审批层级？ | 当前单位成本，必须审批 |
| 7 | 销售折让是否必须开红字发票后才能过账？ | 已开票的必须先开红字，未开票的直接过账 |
