# ERP 项目总结

文档维护：maorongkang@gmail.com。

项目已按里程碑完成多租户、多公司和仓库范围控制，基础资料、销售、采购、资金、期初、库存作业、冲销、关账、报表和文件处理。核心事实保存在 MySQL 8.0.46，Redis 负责会话与协作，不作为资金或库存的事实来源。UI 优化沿用用户提供的设计规范和 HTML 设计稿。

## 本阶段交付

M8 将正确性回归扩展到容量、依赖故障、真实备份恢复与部署包。API/Worker 可独立部署，生产使用独立迁移账户、私有对象仓、HTTPS 和受限数据库网络；运行账号对只追加事实表不能更新或删除。节点号配置处理了 CRLF 和空白，既有 PowerShell 脚本统一 UTF-8 BOM，新增运维脚本明确使用 PowerShell 7。

本机演练不覆盖外部生产服务器。生产域名与证书、S3 桶、主备切换和正式期初数据由上线环境提供后，按《运维手册》逐项验收。容量数字、RPO/RTO、数据量和故障结果只引用《测试报告》及演练产物，不以工具生成时间替代真实验证。

恢复演练已在隔离 MySQL 8.0.46 实例完成：86 张项目表、10 个私有对象摘要一致，指定事务末尾前后的标记恢复范围准确。恢复库的三家真实业务公司、67 张凭证通过八类对账，差异为零。运行与迁移账号的允许及拒绝操作已用真实连接验证，本机 HTTPS 网关检查通过。详细边界、排错过程和证据路径见《运维手册》；这些结果不等于已向生产环境发布。

## 实施中解决的问题

1. 业务过账与关闭期间共用明确的锁边界，避免检查通过后又有新事务进入已关闭期间。
2. 盘点应用快照差额，调拨按原成本分批在途，冲销保留原事实并追加反向事实，避免重算破坏历史成本。
3. 导入逐行事务同时提交业务记录和断点；文件指纹防止重复建期初，临时依赖故障可有限重试或原任务续跑。
4. 导出冻结初始授权，执行取当前交集，成品下载重新核对完整范围；附件和导出不直接公开对象仓地址。
5. 数据库备份与私有对象需要在同一停写窗口保存，完整恢复必须同时包含幂等、Outbox、账本与任务，不能只恢复业务头表。
6. Windows 的中文路径、PowerShell 编码和原生命令参数需要实际验证；MySQL 独立实例使用经过核验的英文目录联接，不通过猜测删除或移动目录解决问题。

## 交付限制与后续工作

当前容量以项目确定的规划基线和本机硬件为边界，不把并发用户数等同于 RPS。对账差额容忍值始终为零；外部主备、共享对象仓和服务器资源应在正式环境复测。MySQL 8.0.46 保持用户指定版本，采用私网、TLS、账号分权和定期恢复演练控制运行风险；升级 8.4 的兼容试跑需要具备对应镜像或测试实例，不能写成已验证。

批次、保质期、序列号、库位、先进先出成本、税控开票、银行支付对接、多级审批及自定义打印模板仍属于既定二期范围。新增需求先记录业务规则和数据影响，再进入实现，继续使用真实数据库、浏览器和恢复演练验证。

## 本机容量结论

最终有效轮次的四公司八类对账与超履约、重复账本、退款额度检查均为零。预连接的 1000 业务请求恰好 100 成功、900 库存不足；100 次同键请求仅一组副作用；完整销售预收核销、入库、退款、导出混合及突发回落通过。两次实测死锁已分别修复新建订单空范围锁、已有库存维度重复新主键 UPSERT，并补真实双事务回归。

本机性能目标仍有未达项：20/100 行过账延迟、1000 查询 RPS、Windows 同机冷连接突发。普通聚合 P95 不能掩盖单步骤超标；暖连接正确性不能冒充冷连接入口通过。后续在真实活跃库存矩阵、指定服务器及独立压测发生器上定位锁持有、数据库往返和入口资源，再复测；本次 0.8.0 为本机演练及部署包交付，1.0.0 与正式上线验收保持待办。

## M12 财务总账本机迭代

以独立公司账套承接原运营账本，业务凭证按来源幂等生成，财务手工调整与原库存、资金、未清项事实分开维护。服务端统一执行完整财务范围、独立复核、期间及即时撤权；配置确认摘要、结账快照和原分录对账保留核对依据。同步、查询和控制器分层，补齐真实月度业务、两准则坏账差异、信用流程及浏览器输出验证。

独立升级和仅DML账号演练通过，原541项后端基线及本轮新增形成602项用例，前端207项、浏览器16条分别验证。当前为1.4.0候选增量，生产启用前需完成财务确认和目标环境验收。见[M12验收报告](../测试/验收记录/M12财务总账本机验收报告.md)。
