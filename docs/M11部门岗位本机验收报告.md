## 2. 交付内容

新增 `org` 后端模块和V36五张表。部门支持树、详情、负责人、分页成员、新建编辑、整子树移动排序及启停；岗位定义支持企业内维护；用户支持当前公司多部门、唯一主部门及多岗位配置。前端复用现有维护面板、表格、权限导航及主题，提供部门/岗位页签和用户权限设置入口，窄屏改为单列。

部门树最多20层、每公司1000节点；根上级库内为NULL，接口为字符串 `"0"`。所有ID返回字符串。非空部门集合必须恰有一个主部门，生成列唯一索引限制每公司最多一个。用户每家公司拥有独立组织版本，修改任职不修改用户资料版本。

公司范围撤销通过同步事件在原事务内清理该公司部门、岗位、负责人，递增组织版本并记录审计。即使用户此前未配置任职，也使版本0失效；恢复范围后必须重新加载。其他公司配置保留，组织配置不增加公司或仓库范围。

写操作先取企业管理屏障，和现有角色及范围调整串行，避免两次主部门写入、互相移动部门或撤权与分配交错。所有组织写操作具有CSRF、幂等、版本和审计保护，服务层再次核验操作权限。历史幂等结果也核验目标用户的当前公司范围。

## 3. 权限和异常验收

| 场景 | 结果 |
| --- | --- |
| 当前公司读取另一公司部门、上级、成员引用 | 404，不暴露对象 |
| 其他企业的部门、岗位或负责人引用 | 404 |
| 无对应操作权限，或原会话角色权限被撤回后继续请求 | 403 |
| 未提供CSRF或使用无权访问的公司上下文 | 403 |
| 缺幂等键、非法字段、重复部门/岗位或多个主部门 | 400 |
| 同键同内容重试 | 返回原结果，不重复创建或增加版本 |
| 同键异内容、旧组织或部门版本 | 409 |
| 存在子部门/成员的部门、任意公司仍有任职的岗位停用 | 422 |
| 同用户同公司并发保存版本0 | 一次成功、一次409，数据库恰有一个主部门 |
| 同用户跨公司并发保存版本0 | 两次均成功，版本和主部门分别独立 |
| 两个根部门并发互移 | 仅一次成功，树无环，路径和深度一致 |
| 丢失公司范围后读取任职或旧幂等结果 | 404；恢复范围后旧组织版本仍不能写入 |

六项新增权限为部门及岗位各自的查看、新建、修改。迁移只给具备 `user:update`、`role:assign_permission`、`user:assign_scope` 的启用系统管理员角色，以及演示企业的仓管管理员补充权限。自定义角色不自动授予，管理员按业务授权。
