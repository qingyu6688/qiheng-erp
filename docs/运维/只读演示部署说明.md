# 只读演示部署说明

## 版本与范围

演示发布标识：`2.0.0-demo.1`，样例截止日期：2026-11-20。

面向 4 核、4GB 服务器和公开产品展示，复用管理端实际页面，提供工作台、采购订单、采购收货、付款登记、销售订单、发货签收、收款登记、库存和七类报表。浏览无需账号，可筛选、分页、查看单据关联及结算金额。AI、生产、WMS、系统管理、后台任务和实际业务写入不在演示范围内。

列表和报表中的“查看”在右侧抽屉打开详情，不更改主页面路由。关联单据沿用该抽屉，可返回上一张；关闭后保留原列表筛选、分页及浏览位置。直接打开单据链接时进入对应列表并展示抽屉。

所有公司、人员、客户、供应商和业务记录均为人工构造的示例，没有导入本机或服务器业务数据库。单据覆盖 2025-12 至 2026-11，列表默认展示 2026-11。默认保留一组待审核及部分履约样例。库存从期初数量和实际样例收发记录计算；报表与工作台从同一组单据派生。

## 运行方式

使用独立的 `erp-web/src/demo/main.ts`、演示路由和 `vite.demo.config.ts`。正式管理端仍使用原入口、路由和 HTTP 请求。演示只注册已开放页面，运行时安装内存数据适配器，未知请求与写请求直接拒绝，不回退到服务器接口。页面的 CSP 禁止网络数据连接，避免演示页面误访问业务 API。

服务器只需现有 OpenResty 提供静态资源，不新增 Java、MySQL、Redis、Worker、AI 或监控服务。浏览器负责筛选和图表渲染。静态资源使用 `/experience/` 前缀，路由采用 hash，刷新详情页无需修改 Nginx 回退规则。

## 本机检查环境

2026-11-20 在 Windows 11 `10.0.26200`、Node.js `24.9.0`、npm `11.6.0`、pnpm `11.25.0`、Java `21.0.3`、Python `3.12.3`、pip `25.2`、Git `2.47.1.windows.1` 下检查。既有 MySQL 客户端为 `8.0.46`；本次演示不连接数据库。预览监听 `127.0.0.1:5176`。

本机 Node.js `24.9.0` 在重新打包阶段出现进程异常退出；改用本机已有的 `24.21.0` 后构建完成，未更改系统默认 Node 版本。复现演示构建时建议使用本次验证过的 `24.21.0`。

服务器检查：Ubuntu `24.04.4 LTS`，4 核，可见内存约 3723MiB，原服务占用约 1401MiB，可用约 2321MiB，磁盘剩余约 45GB。现有 MySQL `8.4.13` 与 Redis `8.10.3` 由 1Panel 管理，本次部署不使用它们。

## 构建

在 `erp-web` 目录执行：

```powershell
npm ci
npm run lint
npm test
npm run build:demo
npm run preview:demo
```

预览地址为 `http://127.0.0.1:5176/experience/`，构建产物为 `erp-web/dist-demo/`。常规 `npm run build` 继续构建正式管理端，演示数据不会打入正式入口。

在 `qiheng-website` 目录构建已配置演示入口的官网：

```powershell
$env:SITE_BASE = '/'
$env:VITE_DEMO_URL = 'https://qiheng.site/experience/'
$env:VITE_DEMO_NOTE = '只读演示，无需登录。提供采购、销售、库存及资金报表；不含 AI、生产与系统管理。'
npm run lint
npm test
npm run build
```

这些变量是公开构建参数，不含凭据。其他构建若不设置 `VITE_DEMO_URL`，官网保留原先的“筹备中”逻辑。

## 发布与回退

将官网 `dist/` 放入待发布目录，再将演示 `dist-demo/` 放在其中的 `experience/`。压缩包只包含静态产物，不包含 `.env`、数据库文件、日志或依赖目录。通过 1Panel 上传到网站根目录外的发布目录，校验 SHA-256 并解压。

核对官网首页、演示入口和引用脚本后，原子交换当前 `index` 与候选目录；旧目录保留作为回退。HTTPS、自动续签与 HTTP 跳转沿用现有站点配置。后续发布官网时必须同时保留 `experience/`，否则会移除演示入口对应的资源。

## 验收要点

- 单元测试验证写入与未知接口被拒绝、返回数据隔离、查询筛选、分页以及购销存资金口径一致。
- 抽屉测试验证查看及关联单据不会改变列表地址和筛选，直接单据链接仍可打开详情。
- 浏览器检查工作台、采购/销售列表和详情、关联单据、库存、报表与空结果；检查刷新详情和窄屏导航。
- 公网检查两个域名的 HTTPS 访问、HTTP 跳转、官网入口和备案号。
- 确认页面没有业务 API 网络请求、没有新增后台服务、没有提供管理或写入权限。
