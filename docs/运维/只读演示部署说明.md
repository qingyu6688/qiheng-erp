# 只读演示部署说明

## 版本与范围

当前线上标识：`2.1.0-demo.8`，2026-11-24发布；样例截止日期仍为2026-11-20。原线上`2.0.0-demo.5`已保留用于回退，实际检查结果见下文。

第八候选加入销售报价、采购价格表和成本重估，直接复用管理端页面及右侧详情。报价与同组订单的客户、数量、含税金额一致，关联订单继续原位查看；采购协议含指定供应商、有效期及数量阶梯。成本重估为已复核、尚未执行的虚构差异预览：库存成本18870.00至18850.00元，库存差额负20.00元、出库差异正20.00元；原发货成本5355.00至5375.00元按库存方向显示。该预览没有入账，不改变当前库存、资金和总账。

访客新增三个模块的查看权限，不授予创建、修改、审批、执行或转单权限；写请求继续由静态适配器拒绝，CSP继续禁止业务网络连接。服务器沿用OpenResty静态目录，不启动Java、数据库、Worker或模型服务。以下旧版记录保留各阶段当时状态。

此前候选`2.1.0-demo.7`包含“销售退货”和“退款申请”，现随第八版一并发布。历史销售退回2箱复印纸，信用额240.00元、冻结平均成本170.00元；部分退款100.00元后剩余信用额140.00元。详情和退款来源继续在右侧打开，重点金额加粗显示，审批记录明确标为虚构样例。销售净额、库存收发存、资金、账龄及总账均从这组单据计算，不伪造原发货或原收款。第七候选补齐报表、总账列表、凭证详情及明细账的只读来源，不改变父页路由。

第五版把回答样例改为对话界面，左侧选择场景，右侧展示用户与助手消息。默认显示完整预设回答，也可播放逐字呈现，随时显示完整回答；浏览器启用减少动态效果时直接显示全文。查询记录可展开，原文引用与关联单据仍使用右侧抽屉。切换场景不改变路由，不产生实时 AI 请求。

第四版增加“AI 与知识”分组：三篇知识百科、两个示例知识库（三份资料、六个分段）和四组预设回答，覆盖应收查数、库存解释、知识问答与只读边界。内容明确标为样例，查询和引用均在浏览器内完成，不调用模型。所有详情沿用右侧抽屉，引用和相关百科可以在同一抽屉切换，关闭保留列表筛选。知识库仅开放阅读，不开放上传、编辑、重解析和召回测试。

第三版同步 UI 2.1.0：控件 8px、卡片 12px、弹层 16px 圆角、浅阴影及分段筛选。演示侧栏支持展开、收起和浮出菜单；手机端沿用展开导航，页面标题仅在内容区出现。发布前检查展开/收起后的菜单、手机端导航、只读边界与详情抽屉。

面向 4 核、4GB 服务器和公开产品展示，复用管理端实际页面，提供工作台、采购订单、采购收货、付款登记、销售订单、发货签收、收款登记、库存和七类报表。第二版增加客户档案、销售商机、客户合同、仓库库位、物料清单 BOM、生产工单、总账凭证和财务账簿，共增加八个页面。浏览无需账号，可筛选、分页、查看单据关联及结算金额。实时 AI 问答、系统管理、后台任务和实际业务写入不在演示范围内。

客户和合同关联已有销售订单，库位余额直接使用实时库存。生产仅演示未领料的组装计划和用料展开，不生成库存流水。总账从同一组收付款、收发货单及期初余额生成，采购含不可抵扣税额计入成本、销售拆分样例税额，提供科目余额表、总分类账、明细分类账，不演示期末结转、辅助核算和数量账。每张凭证借贷平衡，银行、库存、应收和应付可与业务报表核对。

列表和报表中的“查看”在右侧抽屉打开详情，不更改主页面路由。关联单据沿用该抽屉，可返回上一张；关闭后保留原列表筛选、分页及浏览位置。直接打开单据链接时进入对应列表并展示抽屉。

所有公司、人员、客户、供应商和业务记录均为人工构造的示例，没有导入本机或服务器业务数据库。单据覆盖 2025-12 至 2026-11，列表默认展示 2026-11。默认保留一组待审核及部分履约样例。库存从期初数量和实际样例收发记录计算；报表与工作台从同一组单据派生。

## 运行方式

使用独立的 `erp-web/src/demo/main.ts`、演示路由和 `vite.demo.config.ts`。正式管理端仍使用原入口、路由和 HTTP 请求。演示只注册已开放页面，运行时安装内存数据适配器，未知请求与写请求直接拒绝，不回退到服务器接口。页面的 CSP 禁止网络数据连接，避免演示页面误访问业务 API。

服务器只需现有 OpenResty 提供静态资源，不新增 Java、MySQL、Redis、Worker、AI 或监控服务。浏览器负责筛选和图表渲染。静态资源使用 `/experience/` 前缀，路由采用 hash，刷新详情页无需修改 Nginx 回退规则。

## 构建

在 `erp-web` 目录执行：

```powershell
npm ci
npm run lint
npm test
npm run build:demo
npm run preview:demo
```

预览地址为 `http://127.0.0.1:5176/experience/`，构建产物为 `erp-web/dist-demo/`。常规 `npm run build` 继续构建正式管理端，演示数据不会打入正式入口。

在 `qiheng-website` 目录构建已配置演示入口的官网：

```powershell
$env:SITE_BASE = '/'
$env:VITE_DEMO_URL = 'https://qiheng.site/experience/'
$env:VITE_DEMO_NOTE = '只读演示，无需登录。提供业务模块、知识百科、知识库及预设 AI 回答；不进行实时模型调用。'
npm run lint
npm test
npm run build
```

这些变量是公开构建参数，不含凭据。其他构建若不设置 `VITE_DEMO_URL`，官网保留原先的“筹备中”逻辑。

## 发布与回退

将官网 `dist/` 放入待发布目录，再将演示 `dist-demo/` 放在其中的 `experience/`。压缩包只包含静态产物，不包含 `.env`、数据库文件、日志或依赖目录。上传到网站根目录外的发布目录，校验 SHA-256 并解压。

核对官网首页、演示入口和引用脚本后，原子交换当前 `index` 与候选目录；旧目录保留作为回退。HTTPS、自动续签与 HTTP 跳转沿用现有站点配置。后续发布官网时必须同时保留 `experience/`，否则会移除演示入口对应的资源。
