## Windows 本机测试数据目录

在项目根目录的私有 `.env` 中设置 `ERP_TEST_ROOT=D:/QihengERP-Test`。临时覆盖时以同名进程环境变量为准。测试目录使用实际位于非 C 盘的绝对路径。

| 测试入口 | 输出位置 |
| --- | --- |
| 项目根目录执行 `pwsh -File scripts/project.ps1 verify` 或 `verify-ai` | 测试报告、对象或知识库、JVM 临时文件分别归入 `ERP_TEST_ROOT/erp-server` 和 `ERP_TEST_ROOT/erp-ai` |
| 项目根目录执行 `pwsh -File scripts/project.ps1 e2e` | 浏览器报告和临时目录在 `ERP_TEST_ROOT/erp-web`，前端预览和测试 API 的输出归入各自阶段目录 |
| `erp-web` 下的 `npm test`、`npm run test:a11y`，`erp-mobile` 下的 `npm test` | Vitest、Playwright 和无障碍测试的报告、缓存、截图与临时文件在对应模块目录下 |
| 项目根目录执行 `scripts/load/run-capacity.ps1`、`scripts/recovery-drill.ps1` 或升级自测 | 压测证据在 `ERP_TEST_ROOT/capacity`。恢复副本、日志和升级自测文件在各自演练目录中 |

数据库和缓存服务使用自己的存储设置。启动测试专用 MySQL 时，将 `datadir`、`tmpdir`、启用的 binlog 和输出日志一并放在 D 盘，选用独立库名和回环端口。测试 Redis 也使用独立回环端口，数据与日志目录设在 D 盘，或关闭测试实例的快照与 AOF。通过私有配置向测试入口提供这些地址。当前本机默认 MySQL 的数据目录在 D 盘，但临时目录仍在 C 盘。后端回归及压测入口会在执行前检查本机连接的 MySQL 路径，并拒绝该实例。

本机历史测试归档位于 `D:/QihengERP-Test/archive/codex-upgrade-2.0-20261118/`。下文引用的已归档 `.local/...` 测试证据可在归档中按同名相对路径查找。归档保留原始内容，旧脚本如需复跑，应先将其中的绝对路径、数据库连接和临时目录指向新的隔离运行目录。

## 环境变量约定

仓库提供不含真实凭据的 `.env.example`，实际 `.env` 加入 `.gitignore`。至少说明下列变量：

| 变量 | 含义 |
|---|---|
| APP_ENV | 开发、测试或生产环境 |
| SERVER_PORT | 后端服务端口 |
| DB_HOST / DB_PORT / DB_NAME | 数据库地址、端口和库名 |
| DB_USER / DB_PASSWORD | 最小权限数据库账号及密码 |
| REDIS_HOST / REDIS_PORT / REDIS_PASSWORD | Redis 连接配置 |
| STORAGE_ENDPOINT / STORAGE_BUCKET | 附件对象存储地址和存储桶 |
| STORAGE_ACCESS_KEY / STORAGE_SECRET_KEY | 对象存储凭据 |
| SESSION_SECRET | 如认证方案需要，用于会话签名或加密 |
| OTEL_EXPORTER_OTLP_ENDPOINT | 如启用链路追踪，指定数据接收地址 |

租户、公司、用户和数据权限从经过认证的服务端上下文取得，不能通过环境变量或前端传参冒充。

## UI 2.0 与优化开发环境

2026-11-18 在 Windows（内核 10.0.26200）复核 JDK 21.0.3、Maven 3.8.4、MySQL 8.0.46、Node.js 24.9.0、npm 11.6.0、PowerShell 7.6.9、Python 3.12.3、pip 25.2 和 Git 2.47.1。本轮隔离测试使用回环 MySQL 13329、Redis 16391，浏览器回归继续使用 API 18080 和 Web 15173。开发环境由各工作树的本机配置指定。

一个工作树使用一套开发库和测试库。在各工作树根目录配置私有 `.env`，例如主工作树使用 `erp_dev_main` / `erp_test_main`，2.0 工作树使用 `erp_dev_v2` / `erp_test_v2`。库名由团队统一分配。`scripts/project.ps1` 在启动开发后端或运行后端回归前拒绝当前工作树的开发库和测试库同名，并检测关联工作树在同一 MySQL 地址、端口下的库名冲突。只运行开发后端时可省略测试库。使用 `ERP_PROJECT_SETTINGS_FILE` 的本机演练也应选用独立库，其他工作树的自定义配置文件由维护者登记核对。

2026-11-18 只读核对两个现有工作树的默认配置，开发库和测试库名称仍重合。默认 MySQL 账号均可连接，授权范围限定在现有库，独立库需用有建库和授权权限的账号创建。本轮回归使用工作区下的独立实例和私有配置。

O-36 隔离演练使用旧工作树提交 `f1bd66e` 和当前 V102 源码快照，构建目录在各自快照内。MySQL 8.0.46 和 Redis 分别监听独立回环端口 13336、16396。通过 `project.ps1 verify` 按旧版、当前版、旧版顺序定向运行 `IdsConfigurationTest` 和 `WarehouseIT`，每轮两项单测和四项仓库集成均通过。旧测试库有 32 条迁移和 V33，当前测试库有 93 条迁移和 V102。交替验证前后，两库的 Flyway 迁移校验摘要各自一致。

两套构建包分别在 19336 和 19337 启动真实开发 API，JDBC 使用 `DB_SSL_MODE=REQUIRED` 连接采用 MySQL 默认认证方式的临时账号。各开发库的 Flyway 迁移摘要与同版测试库一致，应用可读写本库的仓库标记，读取另一版本的仓库返回 404。四个数据库账号的 12 项交叉读取均被拒绝。源码快照与演练日志保存在工作区私有目录 `.local/o36-worktree-20261118`，实际默认工作树配置仍需管理员创建和授权独立库后切换。

启动脚本另用 Maven 替身验证配置分流。测试库与另一工作树重合、开发库与本工作树测试库同名时，脚本均在启动 Maven 前退出。独立库配置和只指定开发库的开发入口均进入 Maven。

在本机隔离 MySQL 上由管理员执行以下示例。账号先在私有环境配置中创建，分别为开发和测试库设置授权。MySQL 库级授权中的下划线用反斜杠转义。

```sql
CREATE DATABASE IF NOT EXISTS erp_dev_v2 CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
CREATE DATABASE IF NOT EXISTS erp_test_v2 CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
GRANT ALL PRIVILEGES ON `erp\_dev\_v2`.* TO 'erp_dev_local'@'localhost';
GRANT ALL PRIVILEGES ON `erp\_test\_v2`.* TO 'erp_test_local'@'localhost';
```

将库名填入 `DB_NAME` 和 `TEST_DB_NAME`，分别配置 `DB_USER` / `DB_PASSWORD` 与 `TEST_DB_USER` / `TEST_DB_PASSWORD`。在对应工作树根目录运行 `pwsh -NoProfile -File ./scripts/project.ps1 verify`。Flyway 在各库独立迁移。现有库需要样例数据时，从允许的本机备份恢复到新库。
