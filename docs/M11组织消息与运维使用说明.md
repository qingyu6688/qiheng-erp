# M11 组织消息与运维使用说明

本轮完成目标1.2.0的前半功能，当前软件仍为1.0.0候选构建，未正式发布。沿用JDK21、MySQL8.0.46和Redis。部门、岗位和部门数据范围继续遵守Y-01、Y-02规则。文档维护：maorongkang@gmail.com。

## 业务员与区划

销售订单、发货、销售退货和收款保存销售员；采购订单、收货、采购退货和付款保存采购员。无来源的新单默认当前用户，有来源的下游单继承来源。多个来源业务员不一致时，明确选择本单业务员后再保存。草稿可调整，提交后及已审批订单变更不允许换业务员；停用人员的历史名称保留。业务员与制单人、冻结归属人是不同字段，选择业务员不会增加部门或仓库访问范围。

销售、采购和毛利报表提供业务员筛选及“按业务员”汇总，穿透明细和CSV沿用同一筛选及权限。历史无法确定的业务员为0，显示“未分配”。毛利和成本继续要求成本权限。

往来单位、联系人及销售订单送货地址提供省市区选择，详细地址独立保存。数据版本为民政部2024年县级以上行政区划，共3213条，来源及处理规则见[区划数据来源](区划数据来源.md)。官方没有中间市级节点的区划直接显示下一层，不补造行政代码。为兼容旧客户端，更新时未提供的新地址字段保留原值。

## 数据字典

从“系统管理 → 数据字典”新增业务分类，再进入“字典项”维护值、名称、颜色及排序。审批、过账、签收等业务状态由代码和数据库状态约束管理，不能通过字典更改。

预置客户来源和联系人类型供各企业共享，租户只能对预置项启停；不能改名、改值或删除。自建项编码和值创建后不变，已引用的客户来源只能停用，未引用项可以删除。停用后原有记录继续显示历史文字，新增选择不再出现。浏览器按用户和字典版本缓存，退出清理，实时变更事件触发刷新。

## 公告与消息中心

“系统管理 → 通知公告”提供草稿、定时发布、到期和撤回，支持全部用户、公司、部门、角色或用户对象。部门对象指该部门当前有效成员；跨公司对象仍须在管理员授权范围内。多个类型的组合对象可通过接口提交，管理页维护同一类型的多个对象。系统对正文执行HTML白名单清洗，移除脚本、事件属性和危险链接。

普通公告进入消息中心；重要公告在登录后或到达时要求阅读确认。撤回、到期和失去收件范围后，原消息不能继续读取正文。确认记录按用户及公告保存，不受切换公司或更换登录会话影响。发布后正文不能编辑，需要更正时撤回并新建公告。

右上角铃铛打开消息中心。工作台的业务待办读取消息表，计数、分页和详情重新校验当前公司、仓库、部门及操作权限。单据完成后旧待办失效；再次提交时按新版本生成提醒。已读消息仍可作为待办保留，直到源动作完成。文件任务完成也会产生消息，文件本身仍经过原有权限检查后下载。

个人“消息订阅”只控制短信和邮件；站内消息不能关闭。外部渠道默认未订阅，不会因为新增功能自动向真实收件人发消息。

## 模板、发送日志与企业微信

“消息模板”按编码和渠道维护标题、正文、参数白名单及启停。变量只支持`{变量名}`替换，不执行表达式。系统事件编码如下：

| 编码 | 事件 | 允许的参数 |
| --- | --- | --- |
| business.todo | 业务待办 | title |
| file.import.finished | 导入结束 | 无 |
| file.export.finished | 导出结束 | 无 |
| notice.published | 公告到达 | title |
| system.alert | 系统提醒 | message |

全局预置站内模板只读，企业可以新增同编码、指定渠道的模板覆盖。站内提醒始终保留，禁用企业站内模板时恢复默认提醒。自定义编码用于后续事件接入，不会凭编码自动发送消息。

短信、邮件复用“登录方式设置”的渠道凭据及启用开关；邮件保留TLS及SMTP主机白名单。业务短信必须另填已审核的`SMS_`模板编号，不使用验证码模板代发业务消息。收件目标只来自当前已验证绑定。取消订阅、解除或变更绑定、账号停用及失去来源权限后，待发消息会跳过。

投递由Outbox和发送队列处理。同一消息同一渠道唯一，发送载荷加密，日志仅显示掩码目标和统一错误提示。失败后等待1、5、15分钟重试，第四次失败进入终态；成功、跳过和最终失败都清除投递载荷。平台主密钥缺失时站内消息继续保留，外部投递不会保存明文载荷。外部渠道在发送成功但确认前崩溃时可能重发，不能对第三方网络承诺严格仅发送一次。

“企业微信机器人”填写Webhook中的key，保存后只显示已配置标记，留空保留原值。需`notify_robot:manage`，普通系统参数接口不能替代此入口。请求固定发送到企业微信官方域名，不允许管理员填写任意URL，不跟随重定向。群里仅发送“有新的业务待办，请登录工作台查看”的通用提醒，不包含客户、金额、单号或明细。实际业务试用前，由管理员在自己的目标群配置并启用；本机验收只使用受控模拟端点。

## 登录、在线会话及接口日志

登录日志记录密码、短信、邮箱和微信的认证结果、IP、浏览器及请求号，使用独立事务，不保存口令、验证码、第三方授权码或会话凭据。未知账号显示“未知账户”。在线用户展示有效会话及最后访问时间；关闭浏览器后，会话在原空闲超时前仍可能有效。

强制下线针对选定会话，先写撤销标记再删除Spring Session，并关闭各API节点上该会话的连接。页面上的会话标识是SHA-256摘要，不能用于登录。账号停用和密码版本变化仍由原认证规则逐请求核对。会话空闲超时沿用30分钟，绝对有效期12小时。

系统参数可设置`observability.grafana_url`为Grafana站点根地址（可含部署子路径，不含凭据和查询串），日志页面随即提供“查询日志与链路”。链接使用部署模板中的组织1及Loki数据源`loki`，按请求号查询；日志中的trace_id继续通过现有Tempo关联跳转。URL结构遵循[Grafana Explore官方说明](https://grafana.com/docs/grafana/latest/visualizations/explore/get-started-with-explore/)。真实Grafana站点的登录及权限由其自身控制。

访问日志只保存路由模板、方法、状态、耗时、可信用户及公司、请求号和可用的链路号；不保存请求体、查询值和原始ID路径。5xx异常保存类名、安全摘要及最多20个定位栈帧，不保存原始异常消息。异常处理标记有版本、幂等及审计保护。访问、异常和发送日志按当前公司查看，受限仓库或部门身份不能查看整家公司日志；登录日志和平台配置是有独立权限的企业管理资料。

## 定时任务

“系统管理 → 定时任务”显示当前版本登记的固定任务，包括 Outbox、导入导出、消息投递、工作流超时、延迟节点恢复、公海回收和仓储补货。控制台从固定任务目录选择执行项。

计划支持`interval:1000`至`interval:86400000`，或六段Cron，Cron按北京时间计算。暂停只停止自动执行，明确点击“执行一次”仍会排队；每次触发有独立执行编号。手动请求执行前复核发起账号及权限，撤权后跳过。多个Worker通过企业、任务定义租约和执行请求租约竞争，原有导入、导出和Outbox行租约继续生效。任务崩溃后可恢复，业务动作仍依赖自身幂等保证一致性。

工作流超时、延迟节点恢复、公海回收和仓储补货逐项处理。执行记录显示“部分失败”时，可按执行编号查看运行日志。单项的失败原因及连续失败次数在业务事务回滚后保存，达到 3 次时由预警中心按所属公司生成“任务执行失败”预警。预警沿用该规则的扫描频率、接收人和可见范围。

执行记录保留30天；访问日志30天、异常日志90天、消息及登录日志180天。清理动作分批执行，不删除原业务凭证和审计记录。

API与Worker分离部署时，管理端按固定预置任务目录校验并写入队列，API不需要注册或运行该任务执行器。独立Worker领取请求并执行；没有可用Worker时保持等待，可从执行记录排查，不在API节点临时执行任务。

## 权限与部署

新增权限前缀：`dict`、`notice`、`notify_template`、`notify_log`、`notify_robot`、`login_log`、`online_user`、`sys_config`、`job`、`api_log`、`api_error`。平台配置管理还要求所授权公司的全部部门范围以及至少一个有效公司授权。自定义角色不会自动增加新权限，管理员按岗位职责明确授予。

升级追加V38—V43，不修改V1—V37。先停写、排空API及Worker、最终一致备份，再迁移并校验；报表备库结构及数据追平后再开放业务。大表增加列和索引、历史回填的耗时须在正式副本测量，DDL不能按普通业务事务回滚。回退使用与停写恢复点一致的数据库及应用。

所有节点共享Redis会话命名空间及`ERP_LOGIN_SETTINGS_KEY`，节点的`ERP_NODE_ID`各不相同。现有32字节Base64主密钥用于平台敏感参数、机器人及投递载荷，企业和用途通过AAD隔离；不得直接更换密钥导致存量密文无法读取。

WebSocket入口为`/ws/v1/events`，默认只接受同源。独立前端站点在`ERP_WEBSOCKET_ALLOWED_ORIGINS`填完整Origin，逗号分隔，不允许`*`。Nginx模板已配置Upgrade、100秒超时及关闭缓冲，多实例不要求黏性会话。Redis ACL除原会话权限外，需要在线索引用到的有序集合命令、发布订阅命令，以及当前环境`erp:session:环境:events:*`频道权限。不能给测试环境订阅生产频道。

连接每30秒心跳，90秒无响应关闭；每用户每节点最多4条连接，每节点最多1000条连接，发送缓冲64KB，发送阻塞上限5秒。断线按1、2、4秒逐步退避，最多30秒；恢复后重新拉取消息。Redis订阅失败会重试，不阻止原业务组件启动；广播只传变更摘要，站内消息和任务以数据库记录为准。

日志采集队列最多16384条，每秒最多批量写入2000条。数据库故障会重试，队列满有告警及丢弃计数，文件请求日志仍保留。观测指标为`erp_api_logs_queue_size`、`erp_api_logs_dropped`和`erp_api_logs_write_failures_total`，应与现有磁盘、HTTP和数据库告警一起监控。

实现对应的详细接口、迁移和本机证据分别见[接口设计](接口设计.md)、[数据库设计](数据库设计.md)和本轮本机验收报告。正式域名、真实渠道、生产网络与业务方试运行仍须按上线门槛验收。
