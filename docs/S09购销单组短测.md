# S09 购销单组短测

容量调查的 S09 基线为每日销售 1000 单、采购 200 单，峰时约每秒 0.1 单。该驱动每次只运行五张销售订单、一张采购订单，每单十行。相邻两次起单至少相隔十秒。用于核准业务组合、事件数与核销口径，持续吞吐和十二期历史规模另行测试。

## 隔离夹具

使用本机临时 MySQL、Redis 和 ERP 测试进程。驱动不创建数据库、账号或库存。需要兼容销售与采购浏览器夹具的随机企业、`DEMO-A` 公司、`admin` 经办和 `reviewer` 复核账号，以及夹具的销售商品、销售仓库、客户、供应商和银行账户。企业账套须为启用状态，本期开放，库存足以发货。测试库名必须匹配 `erp_test_s09_*`，MySQL 使用独立端口，以临时账号经只读事务查询。数据库与 HTTP 返回的活动公司和账套应一致。

两位经办人员需具备完整的对应单据和财务范围。样本从有效期初和主数据开始，经现有 HTTP 接口完成订单复核、配送出库和签收、收货、收付款确认与订单核销。库存期初应通过期初库存调整单过账。手工插入的无源单分录会影响运营对账。

| 环境变量 | 取值 |
| --- | --- |
| `S09_ISOLATION_ROOT` | 当前实例的独占隔离根目录。省略时使用 `ERP_TEST_ROOT`。 |
| `S09_OUTPUT` | 隔离根内已创建的证据目录，首次使用空目录。MySQL 数据目录也须在这次隔离根内。Windows 只支持本机非 C 盘，目录联接按实际目标校验。 |
| `S09_BASE` | 随本实例启动的回环 API 根地址，格式为 `http://127.0.0.1:端口/api/v1`。 |
| `S09_DB_NAME`、`S09_DB_PORT` | 独立测试数据库和端口。驱动读取实例实际端口、当前库名及数据目录并核对。 |
| `S09_DB_USER`、`S09_OBSERVER_PASSWORD` | 隔离观察账号与临时口令。账号默认 `root`；也可使用对所需表具有读取权限的账号。 |
| `S09_MYSQL` | 可省略，从 PATH 查找 `mysql`。如有多个版本，可传入指定客户端的可执行路径。 |
| `ERP_E2E_TENANT_CODE`、`ERP_E2E_PASSWORD` | 本次随机的 `E2E-` 企业编码及测试账号临时口令。 |

从仓库根目录运行以下命令。使用 Python 3.10 或以上；环境变量由试验运行器注入。口令不进入进程命令参数、检查点或报告。

```text
python -B scripts/load/s09_trade.py
```

- **暂停和恢复**。在证据目录创建 `pause` 文件。已发出的命令返回后，下一次业务写入前会停止。保持原服务、隔离数据和临时账号，移除标记后重跑同一命令。每一步都有稳定的幂等键和参数摘要；收到成功响应后保存结果，响应丢失时使用同一键重试。公司、账套、人员或请求内容发生变化会拒绝恢复。重新启动一组应使用新的证据目录。
- **定位失败**。`checkpoint.json` 记录当前步骤、请求路径、单据编号、版本和诊断信息。核对接口错误和账本后再恢复，保留原检查点。文件锁防止两个进程写入同一组。
- **核对结果**。`result.json` 包含六张订单的实际起单时间、间隔和单号，以业务来源核对运营分录、`gl.journal.requested` 事件、业务凭证及两个对账任务。应有 5 次销售出库、5 次签收、5 次收款、1 次采购收货、1 次付款。各事件状态为 `done`，业务凭证状态为 `posted`，总账试算及运营对账差异均为 0。按每分钟一组换算为每秒约 0.28333 个总账事件。
- **离线回归**。设置 `ERP_TEST_ROOT` 后在仓库根目录运行 `python -B -m unittest discover -s scripts/load -p test_s09_trade.py`，覆盖节拍、恢复、文件范围、观察凭据、真实端口/库名及重复来源。
