> 版本：1.0.0　　日期：2026-11-16
> 适用范围：《开发计划》1.2.0—2.0.0 的全部新增模块。
> 前提：**已有功能不改**；新模块沿用 0.9.0 / 1.0.0 已经验证过的工程约定，本文只写新增和扩展的部分。

## 1. 总体架构

```text
                 浏览器（管理端）      客户门户（浏览器）      PDA / 手机（uni-app）
                        │                    │                      │
                        └────────── Nginx（HTTPS、静态资源、反向代理）──────────┘
                                   │                         │
                         /api/v1/**、/ws/**             /ai/v1/**
                                   ▼                         ▼
   ┌───────────────────────────── erp-server ─────────┐   ┌──────── erp-ai ────────┐
   │ Spring Boot 4.1.2 · JDK 21 · 模块化单体            │   │ Spring Boot 4.1.2      │
   │ 现有模块：identity catalog reference salesorder …  │◄──┤ Spring AI 2.0.1        │
   │ 新增模块：org sysadmin notify scheduler workflow   │   │ 模型网关 知识库 助手    │
   │          gl crm portal wms mfg dashboard alert …  │   │ 以用户身份调 ERP 只读接口│
   │ 内嵌 Flowable 8.0.0（流程引擎）                     │   └───────────┬────────────┘
   └──────┬──────────────┬─────────────┬───────────────┘               │
          │              │             │                               │
     MySQL 8.0.46     Redis 6/7     对象存储（本机 / S3）            OpenSearch
   （主库 + 只读备库）（会话、限流、                                （搜索、向量检索）
                       WebSocket 广播）
```

- **erp-server** 继续是唯一的业务数据写入方。新模块以 Java 包的形式加入，模块之间只通过公开服务和领域事件交互。
- **erp-ai** 独立部署，不直接连业务库；需要业务数据时，带着当前用户的身份调用 erp-server 的只读接口。
- **Flowable** 以库的形式内嵌在 erp-server 中，和业务单据共用数据源和事务。
- 报表和导出按《优化文档》O-29 走只读备库。

### 2.3 接口约定（沿用现有）

| 项 | 约定 |
|---|---|
| 路径 | `/api/v1/{资源复数}`；模块前缀用于新模块，例如 `/api/v1/crm/contracts`、`/api/v1/gl/vouchers`、`/api/v1/workflow/tasks` |
| 公司上下文 | 请求头 `X-Company-Id`；服务端用 `access.requireCompany(request, "权限码")` 取得 `CompanyAccess` |
| 返回格式 | `ApiResponse{code, message, data, requestId, errorCode, details}` |
| 新建 | `POST /资源`，返回 201 和 `ApiResponse.created` |
| 修改草稿 | `PUT /资源/{id}`，请求体带 `version`，冲突返回 409 `VERSION_CONFLICT` |
| 删除草稿 | `DELETE /资源/{id}?version=` |
| 状态命令 | `POST /资源/{id}/{动作}`，如 `submit`、`approve`、`post`、`cancel`；必须带 `Idempotency-Key` 头，经 `BusinessCommands.execute` 执行 |
| 列表 | 游标分页：`cursor`、`limit`（默认 20，最大 100），返回 `items`、`nextCursor`；需要总数时 `withTotal=true` |
| 时间 | 存 UTC，返回带 `Z` 的 ISO 8601；只有日期的字段返回 `YYYY-MM-DD` |
| 金额数量 | 字符串传输，沿用 `Money`、`Quantity`、`Decimals` |
| 错误码 | 大写下划线，如 `CREDIT_LIMIT_EXCEEDED`、`WORKFLOW_TASK_NOT_ASSIGNED`；文案中文、说明原因和下一步 |
| 权限码 | `资源:动作`，资源用下划线，如 `crm_contract:approve`、`gl_voucher:post` |
| 字段级权限 | 成本、银行账号等沿用现有规则；新模块的敏感字段（客户联系方式、工资类科目）同样按权限遮蔽 |

### 2.4 数据库约定

- 表名按模块前缀：`org_`、`sys_`（已有前缀，继续用于系统管理）、`notify_`、`job_`、`wf_`、`gl_`、`cf_`、`code_`、`open_`、`qc_`、`einv_`、`crm_`、`portal_`、`wms_`、`mfg_`、`dash_`、`print_`、`alert_`。
- 每张业务表带 `id`（`Ids.next()` 生成的 BIGINT）、`tenant_id`、`company_id`（全局主数据除外）、`version`、`created_by`、`created_at`、`updated_by`、`updated_at`。
- 状态字段用 `VARCHAR` + `CHECK` 约束；业务状态不放进字典。
- 唯一键里的可选列用 `NOT NULL DEFAULT ''` 或 `0`，不用 NULL（沿用《数据库设计》2.9）。
- 与现有表保持同一精度：金额 `DECIMAL(24,2)`，单价和单位成本 `DECIMAL(24,8)`，数量（含基础单位数量）`DECIMAL(24,6)`。
- 迁移文件：M10 已使用 V34 默认账户、V35 报表水位，Y-01 从当前分支下一可用编号 V36 追加。并行开发在合并前核对版本号，实际运行的 Flyway 文件必须使用有效数字版本，不能把 `Vxx` 占位文件加入运行资源目录。已合并或已交付迁移不修改，只新增迁移。现有字段先核对再设计新增列。
- Flowable 的 `ACT_*`、`FLW_*` 表不进 Flyway，由 Flowable 自己创建和升级，生产环境关闭自动升级（见 02-工作流）。

### 2.5 一致性与事件

- **加锁顺序**在现有顺序上扩展，新资源排在最后，任何事务都按这个顺序取锁：

  ```text
  期间（共享 / 排他）→ 单据头 → 订单行 → 库存余额 → 成本 → 预留 → 未清项 → 资金
    → 批次 / 序列号 → 质检结果 → 工单 → 总账凭证 → 流程实例 → 消息
  ```

- **跨模块通知**用现有 Outbox（`outbox_event`）+ Inbox 去重：发送方在业务事务内写事件，消费方在独立事务中处理并记录已消费。事件名用 `领域.对象.动作`，例如 `sales.order.submitted`、`workflow.instance.completed`、`crm.contract.approved`。
- **同步调用**只用于“同一事务必须同成同败”的场景，例如提交单据时发起流程实例。
- **期间屏障**：凡是产生库存、往来、资金、总账事实的新单据，提交和过账都先取期间共享锁（沿用 `PeriodService`）。

## 5. AI 服务设计（概要）

详见 04-AI 设计。要点：

- `erp-ai` 独立 Spring Boot 4.1.2 应用，依赖 Spring AI 2.0.1；只连自己的库 `erp_ai`（MySQL）和 OpenSearch。
- 前端经 Nginx 访问 `/ai/v1/**`，`erp-ai` 校验会话后，以**同一用户身份**调用 `erp-server` 的 `/api/v1/ai-tools/**` 只读接口。
- 模型调用经模型网关统一出口，按租户限额、记录用量；境内部署默认使用已备案或私有化模型。

## 6. 安全设计（新增部分）

| 项 | 设计 |
|---|---|
| 部门数据范围 | 与仓库范围取交集；所有新查询必须调用统一的范围拼接函数，不允许在 SQL 中手写范围条件 |
| 工作流 | 审批人只能处理分配给自己的任务；管理员终止、转办全部记审计；流程配置不能减少硬规则要求的复核 |
| 开放平台 | 应用密钥 HMAC-SHA256 签名 + 时间戳（5 分钟窗口）+ 随机数防重放；每个应用独立权限范围和限流 |
| 客户门户 | 门户用户与内部用户分开存储；门户接口路径 `/api/v1/portal/**`，只能访问绑定的往来单位数据 |
| WebSocket | 握手时校验会话或设备令牌和 Origin；只推送事件摘要，详细数据由前端再按权限拉取 |
| AI | 只读工具 + 草稿；工具参数 schema 校验；提示注入防护；全部调用记审计 |
| 密钥 | 新增的第三方密钥（短信模板、开放平台、数电发票、模型 API）都用 O-21 的 HKDF 子密钥加密存储 |
