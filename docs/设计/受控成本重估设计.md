# 受控成本重估设计

状态：本机业务、真实总账、并发、容量及常规回归证据通过，尚未发布。对应 B-06，新增迁移 V111；V110至V113均已执行并冻结，范围及限制见《测试报告》。

## 业务边界

任务记录公司、仓库、SKU、起算日、调整入账日及原因。单任务只处理一个仓库和 SKU。起算日按北京时间的零点转换为 UTC，按实际过账时间和 ID 重放。补填业务日期不调整过账时间，也不修改已冻结的入库事实。

普通出库按移动加权重算，最后一次出尽取全部剩余成本。原价采购退货保留冻结的退货价及既有差异；冲销按原流水重估后的成本反向恢复。原单退货、调拨及生产入库保持其冻结来源成本，不把差额自动传播到另一仓库或生产成品。差额在当前仓库生成库存成本调整，对边记成本差异。

## 记录与并发

`cost_revaluation` 保存状态、库存版本、输入摘要、原库存成本、新库存成本、差额与审批、过账人员；`cost_revaluation_line` 保存原流水、原有效成本、新成本、差额。此前重估的累计差额计入有效成本，重复重估不能重复计价。原单行和原流水禁止回写。

提交时保存预览摘要，审批及执行时重新持锁计算并要求摘要一致。所有受影响流水所属期间及调整日期所属期间必须开放，执行时锁定期间，随后使用现有库存余额和成本锁。预览最多读取单仓 SKU 的 50,000 条成本事件，超过限制要求缩短范围，不截断结果后继续执行。

## 审批与权限

使用 `cost_revaluation:view/create/submit/approve/post/void`，同时要求成本查看及当前公司完整仓库、部门范围。制单人不能审批自己的任务；未绑定流程时安装默认人工审批。审批只批准冻结差异，执行独立进行；库存变化后必须重新预览和重审。

## 页面与待验证项

库存菜单增加成本重估列表，新建、差异预览及详情使用右侧抽屉。显示库存成本前后值、库存调整与出库差异、变更流水及审批状态；网络未知结果保留幂等键，不自动换键重做。
