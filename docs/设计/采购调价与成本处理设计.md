# 采购调价与成本处理设计

版本：1.0.0，2026-11-23。实施范围：B-02 采购侧，后续 B-03 复用成本处理；销售调价在方案规定的后续批次接入。

## 规则与状态

- 仅引用当前企业、公司、可见部门和授权仓库中已过账的收货行，同单供应商、仓库一致。数量采用原行尚未退货的数量，已全退或正处理冲销的收货不可调价。
- 每行选择新的含税单价或含税调整金额，两者二选一。单价沿用收货行的交易单位，按剩余基本数量换算。调整相对于原货款加此前有效调整再减已退货金额计算，不能把已退货数量再次调价。
- 税率沿用原采购行。先算新剩余含税额，再按 R3 分离未税和税额，分别减旧剩余金额；零调整和调整后负数拒绝。小规模纳税人的成本包含税，一般纳税人的成本不包含税。
- 草稿可改；提交后进入待审，另一人审批后才可过账。接入现有工作流与系统默认审批，不允许自动审批替代人工复核。提交、审批、过账均重新核对来源及版本。
- 审批、成本预览和过账需要公司全部仓库、全部门和成本权限；草稿及列表继续执行当前仓库和部门范围。已过账详情、穿透及旧幂等结果还要覆盖实际成本归属仓，不能通过原单所在仓扩大可见范围。
- 过账追加应付货款或应付信用额，保留原往来项到期日，使用既有未清项与核销入口，不自动冲抵或退款。原收货货款与原始单位成本快照保留。
- 冲销沿用统一冲销申请、复核和过账。已核销、已登记发票、已发生后续退货或后续调价时，先处理下游，不能删除原调整事实。

## 成本计算与并发

移动加权下不把当前全仓数量直接当成本行仍在库数量。按 SKU 的实际过账时间与流水 ID 重放数量，追踪来源收货在库存池中的数量份额；普通出库按加权份额移出，关联退回及冲销按原移出份额恢复，已完成调拨随货转到目标仓。在途、已耗用和已售出的份额属于本次调价时的已出库部分，不改原出库快照。

同 SKU 的收货来源一并追踪，只返回本次选中行的结果，保证单独调价与批量调价的归属一致。原价退货或反向入库超过该原来源仍在库的份额时，超出部分按剩余库存池的比例消耗，不能留下超过实际库存数量的来源份额。

原价采购退货移除其来源份额，其他来源的原价退货不按当前平均比例消耗本行份额；出现 `purchase_return_diff` 兜底时才采用实际加权移出。零数量时剩余份额清零。冲销入库按原入库的组成移除，避免把另一张旧收货的反向流水误算成本行出库。

在库份额按尚未退货的来源数量分配调整成本，逐分舍入；合计差额进成本差异。负调价不得把当前库存总成本减为负，超过可减成本的部分归入差异。过账取得开放期间锁、原行锁和涉及 SKU 的库存成本锁，再读取当前流水与计算，预览不保证执行时数量不变，正式结果以持锁重算为准。

`cost_adjustment` 区分影响库存的调整与已出库差异；库存成本对账只累计影响库存的金额。运营账本分别写存货、成本差异、进项税和应付；借贷必须平衡，继续由现有总账同步形成业务凭证。原始出库和收货成本流水不回写。

每张账本凭证最多 1000 行，跨仓明细过多时先形成逐行平衡组，再分成多张凭证；各张均可独立反向处理。输入的调整额绝对值合计也检查金额上限，超限要求拆单，不把数据库溢出直接返回用户。

## 退货与反向处理

收货行增加累计调价金额和当前退货计价基准。每次调价仅冻结当时剩余数量、剩余含税额、税额及退货单位成本；随后退货按该基准累计分摊，最后一次补齐尾差。新一轮调价重新建立剩余数量基准。没有调价的行继续使用原有 R3 累计算法。

调整单保存上一退货基准。只有来源累计退货数量未变且没有更晚有效调整时才允许冲销，恢复上一基准、追加反向往来和成本调整。冲销前检查当前库存是否足以承接反向成本；不足时明确要求先处理后续库存业务，不篡改历史快照。

成本分配记录保存每个仓库与 SKU 的库存流水水位；已发生新的有效流水使用本次在库成本时，先处理后续库存业务再冲销。水位同时使用过账时间及 ID，避免毫秒时间相同时把原流水误认为后续使用。退货业务日期不得早于当前调价日期。

## 数据与接口

新增 V105，保留 V1—V104 校验和。`price_adjustment` 保存类型、日期、供应商、仓库、归属、状态、金额和复核记录；`price_adjustment_line` 保存来源、剩余数量、原新价格、金额差、税差、成本拆分及先前退货基准。类型预留销售侧，但本批接口只接受采购。

接口前缀 `/api/v1/purchase-price-adjustments`：列表、详情、新建、修改、预览，以及提交、审批、驳回、作废、过账。变更请求带幂等键和版本。来源从授权收货行查询；详情从收货单可发起，列表和详情沿用已有单据风格。

## 验证

覆盖含税金额、不同税种、尾差、混合库存、部分出库、调拨、关联退回、部分退货后调价、调价后多次退货、连续调价、冲销依赖、库存成本不足、期间关闭、幂等与跨范围访问。完成服务、页面和总账映射后，执行真实业务闭环及八类对账，保留容量复测证据。
