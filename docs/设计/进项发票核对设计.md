## 1. 业务边界

沿用现有进项台账与服务商同步，不替换销项申请、红冲和文件下载。进项来源分为数电同步 `einv` 与纸质票手工登记 `manual`。公司默认核对容差为 1.00 元，暂估只提供未到票报表，不生成总账凭证；后续如需自动暂估，须另行确认凭证与次月冲回规则。

发票核对与资金核销独立。付款已结清的应付仍可核对到票；核对不更改应付原额、资金余额、存货及出库成本。已作废或红冲的进项不能继续核对。

## 2. 金额及状态

每条核对关系同时记录：

| 字段 | 含义 |
|---|---|
| 发票未税额、发票税额 | 本张票分给该来源的金额，累计不能超过本票对应金额 |
| 应付未税额、应付税额 | 本次覆盖的来源额度，累计不能超过来源的可核对额度 |
| 未税差异、税额差异 | 发票分配额减应付覆盖额，保留方向 |
| 匹配及释放时间、日期、原因 | 用于当前状态、历史截止日查询与审计 |

例如，发票未税 99.99、税额 13.00，对应应付未税 100.00、税额 13.00：应付已到票额度为 113.00，票面分配额为 112.99，未税尾差为 −0.01。不能把 112.99 直接作为已到票额度，留下永远无法消除的 0.01 未到票。

一张票可以保存部分分配。一张应付可以由多张票分次覆盖，但发票和应付的未税、税额额度都分别校验，不能用多分的税额补少分的未税额。

容差按**整张票全部当前分配的未税差异绝对值与税额差异绝对值之和**检查，不能分次保存或正负抵销绕过容差。默认合计最多 1.00 元；超过时返回明确差额，并引导采购调价或退回供应商。差异只记录，不自动追加应付或总账。

发票显示待核对、部分核对、已核对、有差异；另返回是否全部分配，避免“有差异”掩盖尚未分完的事实。应付按覆盖额度显示未到票、部分到票、已到票。零税额发票可以完整核对，不能以税额是否非零判断完成。

## 3. 来源及变更

候选以当前公司、同一供应商的正向采购应付为基础，兼容收货商品、随单费用、承运商费用及采购调价。仓库、部门和费用、调价的当前可见范围沿用既有规则。

商品应付按原收货行归组，将采购退货和负调价计入该行的净可到票额；正调价与原收货应付按各自正向金额分配该额度，未税与税额分别逐分补差，不改写原应付事实。费用按其自身来源计量，不默认随商品退货退还承运费。供应商对账继续保留全部正反向往来。

改变来源额度或有效性的操作须与核对互斥。收货、费用、采购调价或退货发生相关冲销，以及调价、退货改变商品来源额度时，释放受影响发票的整组当前关系，发票回到待核对并显示原因。保留已释放历史，不能删除核对证据；仅申请冲销或审批尚未过账时不释放。

服务商将原票改为红冲、作废，或改变票面金额及销方识别号时，同一事务释放关系。重复同步相同内容不增版、不重复释放。数电来源不能通过手工接口改写。手工票在没有有效关联时可按版本更正；作废需要原因。

## 4. 数据与迁移

新增 V107，实施完成并验证后冻结，不修改 V104—V106。

- `company_policy.invoice_match_tolerance`：非负两位金额，默认 1.00。
- `einv_inbound`：增加来源、绑定供应商、接收日期、备注及待重新核对提示；保留现有 `payable_id` 一个版本。
- `einv_inbound_match`：多对多关系、四个分配金额、两个差异金额、匹配与释放时间及原因；同一发票和应付只有一条有效关系，可保留多条历史。
- 核对与采购来源变更共用公司内的核对锁，锁在财务来源行之前取得；来源行按编号排序加锁，避免核对替换、同步及冲销产生反向锁顺序。
- 现有有效单值关联迁入多对多表；关系金额取原发票及应付金额，不改旧票和旧应付的金额、更新时间与版本。失效来源保留提示供复核，不悄悄当作有效到票。

进项覆盖额度以核对关系为准，不借用销项登记的预留计数。旧单值关联没有独立的精确核对时间，迁移行标记 `legacy_migrated`，保留旧更新时间作为来源时间；涉及迁移前的截止日查询必须提示该时间边界，不能声称已恢复缺失的历史。

旧 `payable_id` 只反映“完整分配到唯一应付”的兼容情形；部分或多来源分配返回空值。旧版单值核对请求转换为新关系，旧版解除请求释放有效关系。新接口以完整分配列表替换当前关系，并检查发票版本与幂等键。

## 5. 接口与页面

进项台账新增来源与核对状态筛选、手工登记、右侧核对抽屉。抽屉左侧票面，右侧候选应付与分配输入，下方突出剩余额度、差异和容差；保存后保留列表筛选及原位置。详情继续在右侧查看。

新增详情、登记、更正、作废、核对预览与完整分配接口。保留原同步、候选与单值核对入口。手工登记、手工作废分别配置权限，现有进项核对权限不隐式取得这些新权限。所有入口、详情及旧幂等结果都检查当前公司和数据范围。

未知网络结果冻结原载荷与幂等键，可重试确认；有未保存或待确认操作时保留离开保护。接口请求只放在 `src/api/`，页面不自行计算业务核对结果。

## 6. 报表

新增已收货未到票报表，按供应商、收货及采购来源列出净可到票、已到票、未到票未税额与税额、到票状态和核对提示。覆盖付款已完成但尚未到票的来源，不能以未清资金余额代替未到票金额。

历史截止日按来源业务事实及匹配、释放日期恢复当日额度，不能因今天解除关系而改写上月已到票状态。供应商对账增加采购应付的到票状态；权限、导出及右侧原单穿透复用现有报表机制。

未到票报表使用 `dateFrom` 筛选采购来源起始日期，以 `dateTo` 同时作为来源结束日和到票截止日。先按截止日计算完整来源组的退货、折让与匹配额度，再筛选来源行，避免漏掉日期范围前后的关联事实。只列出尚有未到票金额的正向采购来源；完全退货或折让的来源无待到票额度。费用一条应付只展示一次，不按成本分摊的收货行复制金额。

往来对账中，原收货、正调价、费用应付的到票状态按报表结束日计算；付款、客户应收等分录不填写到票状态。历史失效或当前范围无法完整读取的来源显示“不适用或来源失效”，不推断已经到票。客户门户对账不追加供应商进项信息。

报表额度读取器接收报表事务的数据库连接，所有来源和核对关系在同一个只读快照中读取；配置备库时不能再从主库补金额。最小权限脚本增加调价、采购费用与 `einv_inbound_match` 的报表查询权限。
