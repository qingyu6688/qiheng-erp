# ERP 接口设计

## 采购费用分摊（2.1.0 开发版）

前缀 `/api/v1/purchase-fee-documents`，查询绑定当前租户、公司、部门和全部来源仓范围，金额与长编号使用字符串。

| 方法与路径 | 用途与参数 |
|---|---|
| `GET /`、`GET /{id}` | 游标列表仅返回摘要；详情含费用明细、来源分摊及逐仓成本；列表参数 `status`、`partnerId`、`cursor`、`limit`（1—100） |
| `GET /metadata` | 承运商、资本化开关和默认分摊方式，需往来单位与收货查看权限 |
| `POST /`、`PUT /{id}` | `partnerId`、`businessDate`、`allocationMethod`、`reason`、`fees`、`receiptLineIds`；修改带 `version` |
| `POST /{id}/preview` | 当前成本归属预览，正式过账持锁重算 |
| `POST /{id}/{submit,approve,reject,post,void}` | 版本及可选意见；提交可带 `workflowAssignees`，驳回须填原因 |

分摊方式为 `amount/quantity/weight`。费用明细为 `feeType`（`freight/loading/other`）、正含税 `amount`、`taxRate` 及可选 `remark`。手工费用最多 50 条、来源最多 100 个且不重复。承运商不用于过滤原收货供应商；来源使用现有 `GET /goods-receipt-lines?returnable=true`。变更带 `Idempotency-Key`，未知结果重试保持原载荷和原键。

`sourceKind=receipt` 为自动随单只读记录，通过原收货冲销；`manual` 使用独立审批和统一冲销，冲销来源为 `purchase_fee_doc`。来源变化返回 `FEE_SOURCE_CHANGED`，纳税人身份变化返回 `FEE_POLICY_CHANGED`。手工费用预览、批准和过账要求完整公司范围及成本权限；自动费用不向仓库经办人增加这些权限要求。

公司参数新增可选 `purchaseFeeCostEnabled`、`purchaseFeeAllocationMethod`，旧客户端省略则保留现值。收货详情及每行新增 `goodsCostAmount`、`purchaseFeeCost`、`landedCostAmount`，相关费用单通过 `feeDocuments` 返回，无成本权限时隐藏。原 `costAmount` 继续表示货款成本。

## 采购调价（2.1.0 开发版）

前缀 `/api/v1/purchase-price-adjustments`，所有请求绑定当前公司；金额及长编号在响应中使用字符串。

| 方法与路径 | 用途 | 主要参数 |
|---|---|---|
| `GET /` | 当前范围的游标列表 | `status`、`partnerId`、`cursor`、`limit`（1—100） |
| `GET /metadata` | 从可见已过账收货中选择供应商、仓库 | 无 |
| `GET /{id}` | 原价、新价、金额税额、成本结果和可用动作 | 无 |
| `POST /`、`PUT /{id}` | 新建或修改草稿 | `partnerId`、`warehouseId`、`businessDate`、`reason`、`lines`，修改时带 `version` |
| `POST /{id}/preview` | 按当前流水预览成本归属，不产生事实 | 无 |
| `POST /{id}/{submit,approve,reject,post,void}` | 提交、批准、驳回、过账、作废 | `version`、可选 `reason`，提交可带 `workflowAssignees` |

每行传 `receiptLineId`，以及 `newUnitPrice` 或 `adjustmentAmount` 中的一项，最多 100 行；税额及成本由服务端计算。变更请求使用 `Idempotency-Key`，网络结果未确认时按原载荷和原键重试。驳回必须填写原因，操作意见最多 500 字并写审计。

来源版本改变返回 `PRICE_SOURCE_CHANGED`；状态或版本冲突要求刷新。批准、预览及过账需要完整仓库与部门范围、成本权限及相应动作权限。详情、财务未清项、报表和旧幂等响应会重新校验当前权限及实际成本归属仓。冲销使用既有 `/api/v1/document-reversals`，来源类型为 `price_adjustment`；下游依赖未处理时返回 `DEPENDENCY_EXISTS`。

## B-01 账期与到期日增量字段

账期对象为 `{ "type": "days", "value": 30 }` 或 `{ "type": "monthly", "value": 28 }`。两个字段均为 `null` 表示清空账期。按天范围 0—365，月结日范围 1—28；半空对象、未知类型和越界值返回参数错误。

| 入口 | 增量字段及行为 |
|---|---|
| 往来单位创建、更新、详情及开放平台往来单位接口 | `paymentTerms.customer`、`paymentTerms.supplier`，仅可设置当前已选角色。管理端更新省略整个字段时保留原账期；角色账期为空时继承公司默认值。 |
| 公司业务参数 GET / PUT | `defaultPaymentTerms`。PUT 省略该字段保留原值，传双空对象清空。 |
| 销售、采购订单创建和草稿更新 | `paymentTerms` 指定订单账期；`inheritPaymentTerms: true` 恢复继承。两字段均省略时保留当前设置。继承与指定有效账期不能同时提交。 |
| 销售、采购订单详情 | `termType`、`termValue`、`termOverride`。审批后前两项是冻结的快照；审批后禁止修改账期。 |
| 往来期初创建、更新和详情 | 可选 `dueDate`，日期格式 `YYYY-MM-DD`；未填写时过账根据账期计算。资金期初不使用该字段。 |
| 应收、应付账龄报表与报表导出 | `agingBasis=business`（默认）或 `due`；返回 `dueDate`、`overdueDays`。按到期日统计时排除没有到期日的项，尚未逾期的天数记为 0。查询与导出保持同一口径。 |
| 核销工作台未清项查询 | 返回 `dueDate`、`overdueDays`，空到期日的逾期天数为空。 |
| 预警规则 | 新增 `payable_due`，提前天数可配置，默认 7 天；查看应付预警需 `report:payable_aging`，应收权限不授予应付访问。 |

逾期金额仅统计到期日早于统计日的未清正常借方应收。未设到期日和当日到期均不计逾期。所有规则均保留原租户、公司、部门及权限边界。

工作区按单号搜索使用 `GET /api/v1/document-browser/{kind}?documentNo=…&withTotal=false`。单号精确匹配，长度为 1 至 100 个字符。接口沿用单据列表的公司、仓库、部门及单据类型权限。

销售订单、采购订单和收款单使用 `POST /api/v1/document-browser/{kind}/selected.csv` 导出勾选项。请求体 `ids` 接受 1 至 100 个不重复的单据 ID，前端以字符串提交原始 ID。返回单号、业务日期、状态和金额。请求中有任何单据超出当前公司、仓库或部门范围时，整批返回 404。

批量审核和收款确认逐张调用现有单据详情及命令接口，核对所选版本和 `allowedActions` 后提交，显示每张未完成单据的原因。批量打印沿用打印模板和后台 PDF 任务，一次最多 50 张。

## 生产工单短交关闭

| 接口 | 权限与参数 |
|---|---|
| `POST /api/v1/mfg/work-orders/{id}/short-close` | `mfg_work_order:short_close`。提交 `version`、`businessDate`、`reason`、`costDisposition`（`expense` 或 `allocate`）和材料数组。材料项包含 `materialId`、`consumedQty`、`scrappedQty`，有报废时附 `scrapReason`。数量沿用十进制字符串。 |
| `POST /api/v1/mfg/work-orders/{id}/approve-short-close` | `mfg_work_order:approve_short_close`。提交 `version`，服务端核实复核人、当前工单、期间及材料事实。 |

两个命令也要求 `mfg_work_order:view`、当前公司数据范围和 `Idempotency-Key`。详情按权限返回 `shortClose` 申请及复核信息，页面使用服务端下发的 `allowedActions`。生产成本明细中 `shortCloseExpense` 表示已归集到生产成本差异的短交金额。

## M19 驾驶舱、打印与预警接口（候选）

驾驶舱通过 `GET /api/v1/dashboard/metrics` 读取可用指标，`GET /api/v1/dashboard/data` 按月份和指标编码返回数据及更新时间，`GET|PUT /api/v1/dashboard/layout` 读取与更新个人布局。`dashboard:view` 控制入口，指标另外沿用业务权限与数据范围。

打印模板通过 `/api/v1/print-templates` 列表及维护。预览从原单据接口授权取数，再按单据字段白名单返回；预览、实际打印、批量生成与下载均检查当前公司、来源单据和敏感字段权限。

`GET /api/v1/alerts/unhandled-count` 返回当前公司授权范围内的待处理预警计数。预警列表、处理和规则配置分别使用 `alert:view`、`alert:handle`、`alert:configure`，处理与配置使用版本号。

## M18 生产一期接口（候选）

生产模块位于 `/api/v1/mfg`。BOM、工单、领退料和完工列表支持游标，库存和金额字段使用精确十进制字符串。写入时服务器重新检查权限、公司、部门、涉及仓库、对象版本和业务条件。创建、审核和过账命令沿用 `Idempotency-Key`。

| 资源 | 操作 |
| --- | --- |
| `/boms` | 列表、新建、修改草稿、提交、审核、停用，`/{id}/explode` 可按数量和日期展开。 |
| `/work-orders` | 列表、详情、新建、下达、关闭、取消，以及 `/from-sales-order` 按销售缺货生成工单。 |
| `/issues`、`/receipts` | 创建及修改草稿、提交、复核、过账、驳回、取消。退料行引用原领料行。复核人与经办人分离。 |
| `/cost-periods/{periodId}` | 归集费用 `collect`、填写分摊参数 `allocate`、计算 `calculate`、重算 `recalculate`、过账 `post` 和会计期间已重开后的 `reopen`。需要金额权限和整公司数据范围。 |
| `/reports/progress`、`/reports/material-variance`、`/reports/cost-detail` | 生产进度、标准与实领差异、成本及结转明细。成本明细另外校验 `cost:view`。 |

## M17 仓储作业接口（候选）

接口位于 `/api/v1/wms`，沿用 ERP 会话、当前公司和 CSRF 校验。列表支持按仓库、状态和游标过滤。每次作业确认校验版本、领取人及最新库存。仓库和业务标识、计划数量与已完成数量以字符串返回。

| 方法与路径 | 行为 |
| --- | --- |
| GET /tasks、GET /tasks/{id} | 查看授权范围内的上架任务和明细。 |
| POST /tasks/{id}/claim、POST /tasks/{id}/finish | 提交 `version` 和 `Idempotency-Key`，领取及完成作业。 |
| POST /tasks/{id}/lines/{lineId}/confirm | 提交版本、源与目标库位码、批次、数量和序列号。网络重试复用同一个幂等键。 |
| GET /warehouses、PUT /warehouses/{id}/task-mode | 查询可见仓库、设置 `off`、`optional` 或 `required`。 |
| GET /picks、GET /picks/{id}、POST /picks/{id}/claim 或 /finish | 读取及领取拣货任务，完成时可显式登记短拣。 |
| POST /picks/{id}/lines/{lineId}/confirm | 校验原发货占用，分批登记扫描，整行达到计划后移至发货位。 |
| GET 或 POST /waves、POST /waves/{id}/claim | 同仓合波、按库位排序并整波领取。 |
| GET 或 POST /packs | 按仓库及发货单查询箱记录，提交单张发货单的箱组、明细数量、批次和序列号进行复核。 |
| CRUD /moves、POST /moves/{id}/post | 保存同仓移库、取消草稿及过账。 |
| POST /replenishments/generate、POST /replenishments/{id}/post | 生成并执行补货。 |
| GET /count-tasks、GET /count-tasks/{id}、POST /count-tasks/{id}/claim 或 /confirm | 盘点作业返回来源盘点单的 `snapshotAt`（带时区的 ISO 8601）。领取后提交该快照时点的实盘数量及差异序列号。 |
| GET 或 PUT /location-rules、GET /task-admin/statistics | 维护库位规则，查询人员作业数和时效，并返回当前用户当天创建且待处理的作业数 `myPendingToday`。 |
| GET /task-admin，POST /task-admin/{id}/assign 或 /cancel | 读取、分配或取消作业。拣货作废经来源发货单释放占用。 |
| GET /scan/resolve | 解析商品条码、库位、批次、序列号和箱码。库位、批次与箱码需指定仓库。 |

`required` 模式要求在服务端完成拣货和复核后发货。标签使用 `POST /api/v1/labels/print-jobs` 返回 PDF、ZPL 或 TSPL。设备使用 `POST /api/v1/auth/devices` 生成配对码，`POST /api/v1/auth/devices/activate` 一次性兑换 Bearer 令牌，`DELETE /api/v1/auth/devices/current` 退出。设备只访问仓储、查询和审批相关的允许列表，沿用各业务接口授权。

## M16 CRM 与客户门户接口（候选）

以下路径以 `/api/v1` 为前缀。内部 CRM、价格和客服接口使用 ERP 登录态、`X-Company-Id` 及原写入保护。读取按操作权限和部门、客户团队、仓库等原有范围过滤。门户独立使用 `ERPPORTALSESSION` Cookie，写操作发送从 `/portal/auth/csrf` 获取的 `X-PORTAL-XSRF-TOKEN`。门户客户和公司从会话确定。

| 方法与路径 | 行为 |
| --- | --- |
| POST /crm/clues/{id}/convert | 按线索版本转化为共享往来单位，可显式合并到已有客户。 |
| POST /crm/businesses/{id}/advance 或 /win | 推进商机阶段或登记赢单。 |
| POST /crm/contracts/{id}/submit | 按已发布流程开启合同审批。 |
| POST /crm/contracts/{id}/create-sales-order | 按合同明细行和仓库分配数量，使用幂等键生成销售订单草稿。 |
| GET /crm/receivable-plans、GET 或 POST /crm/receivables | 查看计划或关联现有收款单。关联后沿用原资金确认及核销流程。 |
| GET /crm/statistics/{kind} | 按时间和授权数据范围查询统计。 |
| GET /price-lists、GET /pricing/default-price | 按查看权限列出价格表，按销售订单创建权限获取默认单价。 |
| GET /portal/orders、/portal/shipments、/portal/invoices | 查询绑定客户的订单、发货和发票，详情按同一范围校验。 |
| GET /portal/statements、/portal/statements/pdf、POST /portal/statements/confirm | 查询和下载指定期间对账单。确认提交期间和当前对账摘要。 |
| POST /portal/assistant、POST /portal/assistant/feedback | 查询网页客服、提交反馈或转人工。 |
| GET 或 POST /portal/tickets、GET /cs/tickets/{id}/assist | 门户工单和内部坐席辅助分别按各自会话与权限校验。 |

## M14 平台二期接口（候选）

身份由原登录接口扩展，MFA 挑战完成前不能访问业务 API。自定义字段、编码规则和工作流管理沿用 ERP 会话及 CSRF 校验。`/open/v1` 使用独立签名，并按应用和公司校验。接口及签名见 [M14 使用与验收](../使用说明/M14平台二期使用与验收.md)及[开放平台接入手册](../使用说明/M14开放平台接入手册.md)。

## M13 内部 AI 接口（未发布）

浏览器同源调用 `/ai/v1/**`，携带 ERP 会话、`X-Company-Id`，写请求携带 `X-XSRF-TOKEN`。访问规则、路由和 SSE 事件见 [M13 使用与验收](../使用说明/M13人工智能使用与验收.md#接口)。ERP 内网桥接仅接受带时间戳、随机数和会话摘要的签名请求，重放由 ERP Redis 拦截。

## M11 组织消息与运维接口（未发布）

以下路径均以`/api/v1`为前缀。业务员、个人消息和日志的公司范围在后端逐次校验；平台管理权限及全范围约束见[使用说明](../使用说明/M11组织消息与运维使用说明.md)。所有写入经过CSRF；除自然幂等的个人阅读确认外，平台写入带`Idempotency-Key`和对应版本。新增ID继续使用字符串响应。

| GET /reports/{type}、POST /export-jobs | 商业报表新增businessUserId（0为历史未分配）、groupBy=standard/business_user；汇总的detailUrl保留业务员筛选。business_user不与detail=true混用。 |
| GET /dicts?types=customer_source,contact_type&version=版本 | 登录用户；版本相同返回unchanged=true，否则items含停用历史项及enabled。 |
| GET /areas/tree | 登录用户；返回version=MCA-2024及items树。 |
| GET/POST /sys/dict-types；PUT/DELETE /sys/dict-types/{id} | dict:view/create/update/delete；code/name/status/version。预置类型只读。 |

| GET/POST /sys/notices；GET/PUT /sys/notices/{id} | notice:view/create/update；title/content/level、publishAt/expireAt（UTC ISO8601）、targets[{type,id}]、version；编辑限草稿。 |

| GET/PUT /sys/notify-robot | notify_robot:manage；enabled、key（空为保留）、version；不返回密钥。 |

报表类型与权限后缀对应如下，路径中的连字符和 JSON 中的下划线均可解析；返回统一为下划线。

| 报表路径类型 | 中文名称 | 权限后缀 |
|---|---|---|
| `inventory-summary` | 库存汇总 | `inventory_summary` |
| `inventory-flow` | 库存收发存，`detail=true` 查看流水 | `inventory_flow` |
| `unsigned-shipments` | 发出未签收 | `unsigned_shipments` |
| `sales-summary` | 销售汇总 | `sales_summary` |
| `purchase-summary` | 采购汇总 | `purchase_summary` |
| `receivable-aging` | 应收账龄 | `receivable_aging` |
| `payable-aging` | 应付账龄 | `payable_aging` |
| `partner-statement` | 往来对账单 | `partner_statement` |
| `cash-journal` | 资金日记账 | `cash_journal` |
| `gross-margin` | 毛利报表 | `gross_margin` |

以上查询字段按各报表的适用范围使用。权限分别为 `report:<后缀>` 和 `export:<后缀>`；应收账龄、应付账龄、往来对账单、资金日记账要求整家公司范围，拒绝仓库和 SKU 筛选。库存报表拒绝往来单位筛选；资金日记账只按资金账户和日期筛选，不提供 `partnerId`，因为资金分录不记录往来单位。其他报表不接受资金账户筛选。毛利另需 `cost:view`；其他报表无成本权限时省略成本字段。

销售、采购汇总默认按客户或供应商、SKU、业务日期合并，返回汇总数量、金额、税额、成本及 `sourceCount`；同组跨仓时显示“多个仓库”。`detail=true` 返回逐单行，费用组的明细链接追加 `feesOnly=true`，精确筛出无 SKU 的费用来源，避免穿透到同一往来和日期的商品行。

Worker 生成的报表 CSV 使用各报表独立的中文业务列白名单，只包含单号、名称、编码、日期及业务数值，不输出内部 ID、来源 URL 或其他内部字段。没有成本权限时，成本及毛利列连同表头一并省略；精确数字与文本仍保留防公式和防精度截断处理。

附件删除在同一元数据事务内调用 `retire` 登记回收候选，逻辑删除后立即停止下载，一小时后由补偿任务回收物理对象。清理前只检查有效附件引用，有有效引用则保留对象；文件仓暂时不可用时保留候选重试。

导入表头固定如下，列顺序须与模板一致。SKU 的 `productCode` 引用已有商品，其基础单位沿用商品设置，不自动创建商品、分类或单位；往来角色可用 `customer|supplier` 表示双角色。库存期初每个有效数据行创建一张单行 `stock_adjustment` 草稿，后续提交、另一人审核和过账沿用既有业务接口。

```csv
productCode,code,name,spec,defaultTaxRate,purchasePrice,salePrice,status
code,name,shortName,taxNo,roles
skuCode,unitName,qty,totalCost,reason
```

三类导入均需 `import:<jobType>` 和 `sku:create/partner:create/stock_adjustment:create`；SKU 含采购价时及所有库存期初导入另需 `cost:view`。同公司相同文件 SHA-256、类型和业务条件命中同一指纹，原操作人返回已有任务，其他操作人收到冲突且不暴露任务ID。源文件不提供通用附件下载入口。

导入对象仓 503 和瞬态数据库故障按 2、4 秒退避，最多执行 3 次；重试保留已提交的行断点，不把连接故障记为业务错误行。达到上限或撤权导致中断后，修复依赖、恢复授权，再用上述重试接口继续未处理行。所有行都已成功或已判定为错误的任务不允许重跑，错误行应修改 CSV 后另存文件上传。

## M2 接口落地

已实现第 5.1、5.2 节组织、角色权限与基础资料接口，以及会计期间列表和开启接口。租户级资料使用登录租户，公司和仓库范围由服务端验证。公司、公司参数、用户、角色、往来单位、SKU 等编辑请求带 `version`。新增和启停命令带 `Idempotency-Key`，结果可用原操作标识和键在 `GET /command-results` 查询。基础资料列表使用 `items`、`nextCursor`，分类列表的 `items` 内含 `children`，权限目录返回数组。开发环境 OpenAPI 给出逐字段结构。

- 往来单位写入 `roles` 数组，取 `customer`、`supplier`。联系人包含 `name`、`mobile`、`email`、`address`、`isDefault`，更新带版本，删除用查询参数 `version`。无联系方式权限时，电话和地址省略。
- 结算账户创建时同事务生成零余额行，`currency` 固定为 `CNY`，`balance` 是两位小数字符串。无完整账号权限时只返回末四位，编辑省略或提交 null 会保留原值，提交空字符串可在有完整账号权限时清空。
- SKU 使用 `productId`、`code`、`name`、`spec`、`defaultTaxRate`、`purchasePrice`、`salePrice`。编辑时仍提交原 `productId`。采购价仅向拥有 `cost:view` 的用户返回和开放修改，省略采购价时保留原值。
- 账户、联系人及 SKU 的创建或启停响应与幂等缓存使用去除敏感字段的首次结果。完整可见字段通过详情查询按当前权限返回。审计记录同样剔除联系方式、完整账号、采购价和密码。
- 开启期间用 `POST /accounting-periods`，请求为 `{"period":"202611"}`。首个期间可指定年月，此后逐月开启。关账和反关账按 M6 实施。
- 用户管理可以分配当前管理员拥有的角色权限和公司、仓库范围。密码重置后原会话失效，用户下一次登录先改密。组织和权限修改在下一次请求生效。

`POST /pricing/preview` 按 `documentType` 校验销售或采购制单权限，返回计算快照，逐字段说明见第 6.1 节。库存、往来、退款、过账和期间锁以服务公开方法供 M4—M6 在同一事务中调用。

| 往来及资金期初 | `GET/POST /opening-entries`、`GET/PUT /opening-entries/{id}`，列表支持 `status/cursor/limit`；草稿 `{entryType,partnerId?,cashAccountId?,direction,amount,businessDate,remark?,version?}`；类型为 `receivable/payable/cash`，命令 `/approve`、`/post`、`/void` 请求 `{version,reason?}`，草稿直接交另一人审核 |

采购金额使用 `POST /pricing/preview` 的 `documentType="purchase_order"`，服务端保存时重算头、行、优惠、税额与费用快照。订单详情行返回 `progress:{baseQty,closedQty,receivedQty,pendingReceiveQty,returnedQty,receivableQty,closableQty}`；可收、可关闭数量已由服务端扣除关闭量、已收量与待收占用，前端直接使用十进制字符串。采购草稿一旦关联请购行就占用可转基础数量，不能等到采购审批才检查 Q18。

采购审批冻结 `overReceiptPct` 和各行 `receiveLimitBaseQty`，后续公司容差调整不改写已批订单。收货提交才占用可收量，过账才入库并确认应付；采购本身不预留库存。已收或待收行不能变更 SKU、单位、价格、税率及分摊后的单位净额，待收行须先作废对应收货单再调整，避免旧来源按新快照过账。收货过账保存纳税人身份对应的成本含税快照，采购退货沿用原收货成本、税额及身份口径。费用按首次收货规则确认，关联已确认采购预付款在确认应付时自动核销，后付及未分配部分可手工核销。

应付核销只配对应付体系：付款、采购退货信用额与正向应付、供应商退款；即使往来单位同时有客户和供应商角色，也不能与应收体系混核销。应付工作台使用 `side=ap` 的未清项查询，应付来源明细使用 `/payables` 只读查询。转账转出账户扣本金及手续费，转入账户只加本金，手续费记 `TRANSFER_FEE`。资金确认按公司经办复核分离参数执行；期初审核始终要求审核人与制单人不同。

收货草稿保存后，来源采购行的 SKU 或对应单位换算快照发生变化时，提交返回 `409 SOURCE_CHANGED`，且不占用可收量；重新编辑或创建草稿后再提交。仅基础资料换算率后来变动时，仍按原采购及收货草稿保存的合法快照处理。请购、收货和库存期初的数量换算均不得静默舍入。

库存期初逐行保存单位及换算率，数量转换使用价格引擎的严格精度规则，不静默截断；`inputTotalCost` 是整行总成本。资金期初只支持 `cash/D`，客户往来支持 `receivable/D`（欠款）和 `receivable/C`（预收），供应商往来支持 `payable/C`（欠款）和 `payable/D`（预付）。过账生成库存、往来或资金事实及 `OPENING_EQUITY` 对应分录；已过账单据不允许直接修改或作废。

命令结果的 operation 示例：`purchase_requisition.approve`、`purchase_order.close_lines`、`purchase_order.change_approve`、`goods_receipt.post`、`purchase_return.post`、`payment.confirm`、`account_transfer.confirm`、`stock_adjustment.post`、`opening_entry.post`。超时沿用原 operation、键和版本查询或重试。新增操作权限为 `purchase_requisition:*`、`purchase_order:*`、`goods_receipt:*`、`purchase_return:*`、`payment:*`、`account_transfer:*`、`stock_adjustment:*`、`opening_entry:*`；供应商退款沿用 `receipt:*`，应付核销沿用 `settlement:*`。成本字段仍受 `cost:view` 控制，当前只登记实际收付款，不对接银行或支付渠道。

## M6 调拨、盘点、调整、冲销与期间接口

0.6.0 已通过 M6 验收，实际入口如下。路径均以 `/api/v1` 开头；列表返回 `items/nextCursor`，数量、成本、金额为十进制字符串，ID 为字符串。创建和业务命令使用 `Idempotency-Key`，编辑及命令使用各自对象的 `version`；详情按当前权限返回 `allowedActions`。以下说明补充当前实现，M4、M5 的历史入口保留。

| 范围 | 实际入口与请求 |
|---|---|
| 调拨 | `GET/POST /stock-transfers`、`GET/PUT /stock-transfers/{id}`；列表支持 `status/cursor/limit`，草稿 `{fromWarehouseId,toWarehouseId,businessDate,remark?,lines:[{skuId,unitId,qty}],version?}`，最多 200 行，限同一公司内不同仓库，读取及操作均须同时具备两仓范围 |
| 调出与作废 | `POST /stock-transfers/{id}/submit`、`/ship`、`/void` 请求 `{version,businessDate?}`；提交锁原单业务日期的期间，不使用请求日期绕过原期间；调出形成在途并冻结调出成本，未调出前可作废 |
| 调入 | `POST /stock-transfers/{id}/receive` 请求 `{version,businessDate?,finalReceipt?,lines:[{lineId,qty}]}`；这里的 `qty` 为本次实收基础数量，允许 0；`finalReceipt` 默认 true，false 时未收部分保留在途，true 时其余未收量全部转为待处理差异 |
| 调拨差异 | `POST /stock-transfers/{id}/resolve-diff` 请求 `{version,businessDate?,reason,lines:[{lineId,disposition}]}`，方式为 `returned/lost`，每行一次处理全部待处理差异；退回调出仓或确认运输损失 |
| 盘点草稿 | `GET/POST /stock-counts`、`GET/PUT /stock-counts/{id}`；草稿 `{warehouseId,businessDate,countMode:"watermark",remark?,lines:[{skuId}],version?}`，最多 200 行，当前仅开放水位盘点 |
| 盘点实录 | `POST /stock-counts/{id}/start` 开始盘点并记录快照；`PUT /stock-counts/{id}/counts` 请求 `{version,lines:[{lineId,countedQty,inputUnitCost?}]}`，须完整覆盖本单所有行，数量以基础单位填写、可为 0，首次盘盈且没有历史入库价时填写人工单价 |
| 盘点命令 | `POST /stock-counts/{id}/{action}`，动作取 start、submit、approve、reject、post、void，请求 `{version,reason?}`；审核与制单人分离，驳回必填原因并回到盘点中 |
| 库存调整 | 复用 `/stock-adjustments` 的创建、修改及 submit/approve/reject/post/void；`adjustType` 取 `opening/gain/loss/block/unblock/scrap`，创建后不可变；列表新增 `adjustType` 筛选，明细仍为 `{skuId,unitId,qty,inputTotalCost?}`，只有 opening、gain 填整行总成本，其他类型成本由系统计算或不产生成本变动 |
| 冲销来源 | `GET /document-reversal-sources?sourceType=&keyword=&cursor=&limit=`，需要 `reversal:create` 和相应原单查看权限，只列当前公司及仓库范围内可申请的已过账来源 |
| 冲销申请 | `GET/POST /document-reversals`、`GET /document-reversals/{id}`；申请 `{sourceType,sourceId,businessDate,reason}`，来源八类见 6.7；命令 `/approve`、`/reject`、`/post` 请求 `{version,reason?}`，驳回与批准共用 `reversal:approve`，审核人与申请人必须不同 |
| 撤销受阻冲销 | `POST /document-reversals/{id}/cancel` 请求 `{version,reason}`。限原单已确认上架移库的已审批冲销。申请人以外、具备 `reversal:approve` 和原单范围的操作者可用；撤销原因必填，结果为 `rejected`，原审批和库存账务事实保留，审计动作及幂等结果操作名为 `reversal.cancel` |
| 期间 | `POST /accounting-periods/{id}/close-check` 无请求体、只读且不要求幂等键；`/close` 请求 `{version}`，`/reopen` 请求 `{version,reason}`，两者均要求原幂等键、相应动作权限及整家公司数据范围 |

调拨详情保留每行 `baseQty/receivedBaseQty/diffBaseQty/diffStatus/remainingQty` 和 `events` 数组。事实动作 `ship/receive/returned/lost` 各自保存基础数量、实际业务日期与期间；成本字段仅在拥有 `cost:view` 的详情读取中返回，写响应及历史命令结果不缓存成本。分批调入按原调出金额累计分配，最后一笔使用精确剩余成本。

盘点实录对应“开始盘点”快照时点。服务端在同一组排序库存锁内取得账面数与水位，后续过账仅把 `countedQty-bookQty` 加到当时余额，不使用实盘数覆盖期间已经发生的出入库。盘盈优先按过账时移动加权价，零库存沿历史入库价，无历史价才使用审核过的录入价；盘亏按过账时移动加权价出库。

冲销创建与过账均核查下游退货、核销或退款占用、开票等依赖，返回 `DEPENDENCY_EXISTS` 及具体来源。原单、库存流水、往来事实和凭证保留，反向事实指向原事实，原单标记 `reversed`。冲销发货单不恢复已消费预留，需重新预留才能继续发货。冲销产生的抵销核销仅用于结清原事实，不允许单独撤销；需要更正应按原业务链处理。已冲销的原应收、反向应收以及 `sourceType="document_reversal"` 的抵销应收不能登记开票，来源候选排除这些事实，服务端写入也校验，不能靠提交 ID 绕过。

M6 将相关单据提交、期初及退款审核纳入期间共享锁屏障：按原业务日期取得期间共享锁，再锁业务头；实际过账日期沿各自接口校验。关账同步补齐已提交凭证投影，使用相同 Inbox 去重后预检查；取得期间排他锁后复核全部五项及待投影事件，不通过则保持开放。历史结果查询同样检查当前权限、公司、双仓或原单范围。

命令 operation 示例为 `stock_transfer.receive`、`stock_transfer.resolve_diff`、`stock_count.start`、`stock_count.post`、`stock_adjustment.post`、`reversal.create`、`reversal.post`、`period.close`、`period.reopen`；实盘录入为带版本的 PUT，超时先刷新核对，不把它当成幂等命令。新增权限使用 `stock_transfer:*`、`stock_count:*`、`reversal:*`、`period:close/reopen`，库存调整沿用 `stock_adjustment:*`。

## 1. 设计要点

| 要点 | 做法 | 依据 |
|---|---|---|
| 金额只在服务端算 | 前端提交数量、单价、优惠，不提交金额和合计；需要实时预览时调试算接口 | R3-11、方案 5.2 |
| 有业务效果的请求都带幂等键 | 请求头 `Idempotency-Key`；超时后用同一个键查询结果，不换键重发 | 方案 10.2、T05 |
| 防止覆盖别人的修改 | 修改和命令都带 `version`，不一致返回 409 | 方案 7.3、T03 |
| 状态驱动按钮 | 详情返回 `allowedActions`，前端按它显示按钮，不在前端重复写状态判断 | 业务规则第 11 节 |
| 租户不由前端决定 | 租户来自登录会话；公司由请求头选择，服务端校验用户是否有权访问 | 方案 9.2 |
| 无权看到的数据当作不存在 | 越公司、越仓库访问返回 404，不暴露数据是否存在 | T15 |

## 2. 通用约定

### 2.1 地址和命名

- 前缀统一为 `/api/v1`。破坏性变更才升级为 `/api/v2`，新增字段不升级版本。
- 资源路径用复数名词、短横线连接：`/sales-orders`、`/stock-transfers`。
- 命令用资源下的动词子路径：`POST /sales-orders/{id}/approve`。
- JSON 字段用 camelCase，查询参数也用 camelCase。
- 枚举值与数据库保持一致，使用小写加下划线：`"change_pending"`、`"supplier_refund"`。

### 2.2 认证与会话

采用服务端会话，不用 JWT。原因是后台系统要能立即注销会话、立即停用账号；会话放在 Redis（方案第 4 节），API 实例保持无状态。

| 项目 | 约定 |
|---|---|
| 登录 | `POST /api/v1/auth/login`，提交租户编码、用户名、密码 |
| 会话 Cookie | `HttpOnly`、`Secure`、`SameSite=Lax`；登录成功后更换会话 ID |
| 会话时长 | 空闲 30 分钟过期，最长 12 小时，到期需要重新登录 |
| CSRF | 服务端下发 `XSRF-TOKEN` Cookie；除登录外，所有 POST、PUT、DELETE 都要带 `X-XSRF-TOKEN` 请求头 |
| 登录失败 | 连续 5 次失败锁定 15 分钟；未知用户和密码错误返回同样的提示 |
| 重置密码 | 管理员重置后，用户下次登录必须先改密码 |

前端与 API 通过 Nginx 同域部署，Axios 能自动读取 `XSRF-TOKEN` 并带上请求头。

### 2.3 租户与公司上下文

- **租户**：只取自登录会话。请求里出现的任何 `tenantId` 都会被忽略。
- **公司**：公司级接口必须带请求头 `X-Company-Id`。服务端校验当前用户在该公司有数据范围，没有返回 403 `COMPANY_NOT_ALLOWED`。
- **仓库范围**：数据范围限定到仓库的用户，列表只返回这些仓库的数据。访问范围外的单据返回 404。
- 切换公司后，前端丢弃旧公司的页面数据，取消未完成的请求（方案 5.2）。

`GET /api/v1/auth/me` 返回用户可访问的公司和仓库，用于公司切换器。

### 2.4 统一响应

全局规范要求统一的 `{code, message, data}` 结构，方案要求使用有意义的 HTTP 状态码，两者同时满足：响应体的 `code` 等于 HTTP 状态码。

成功：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "id": "7261839450137600001", "status": "approved", "version": 4 },
  "requestId": "9f2c6a1e8b7d4c3a"
}
```

失败：

```json
{
  "code": 422,
  "errorCode": "INVENTORY_INSUFFICIENT",
  "message": "可用库存不足：SKU-A 需要 60，可用 40",
  "rule": "R1-03",
  "details": [
    { "lineId": "7261839450137600011", "lineNo": 1, "skuCode": "SKU-A", "warehouseCode": "W1", "requiredQty": "60.000000", "availableQty": "40.000000" }
  ],
  "data": null,
  "requestId": "9f2c6a1e8b7d4c3a"
}
```

| 字段 | 说明 |
|---|---|
| `code` | 与 HTTP 状态码相同 |
| `errorCode` | 失败时必有，取值见第 3 节，前端按它分支处理，不解析 `message` |
| `message` | 中文提示，可以直接展示给用户 |
| `rule` | 业务规则编号，违反业务规则时提供，方便排查 |
| `details` | 结构化明细，例如字段错误、不足的行、依赖的单据 |
| `requestId` | 与响应头 `X-Request-Id` 相同，用于对照日志 |

HTTP 状态码的使用：

| 状态 | 用途 |
|---|---|
| 200 | 查询成功、命令成功 |
| 201 | 创建成功，响应头 `Location` 指向新资源 |
| 202 | 已受理的异步任务，返回任务 ID |
| 400 | 请求格式错误、字段校验失败、缺少幂等键 |
| 401 | 未登录或会话过期 |
| 403 | 已登录，但没有这个操作的权限 |
| 404 | 资源不存在，或者不在当前用户的数据范围内 |
| 409 | 与资源当前的状态或版本冲突、幂等键冲突、编码重复 |
| 422 | 请求本身合法，但业务规则不允许，例如库存不足、期间已关闭 |
| 429 | 请求过于频繁，响应头 `Retry-After` 给出等待秒数 |
| 500 | 服务端错误，只返回通用提示和 `requestId`，不返回异常堆栈 |
| 503 | 依赖服务不可用，`details.retryable = true` |

409 和 422 的区别：409 表示“你看到的数据已经过时”，刷新后可能就能继续；422 表示“按现在的数据，这件事不能做”。

### 2.5 数据格式

| 类型 | 格式 | 示例 |
|---|---|---|
| ID | 字符串 | `"7261839450137600001"` |
| 金额 | 字符串，2 位小数 | `"1130.00"` |
| 单价、单位成本 | 字符串，8 位小数 | `"115.00000000"` |
| 数量 | 字符串，6 位小数 | `"4.000000"` |
| 税率、换算率 | 字符串，6 位小数 | `"0.130000"` |
| 业务日期 | `YYYY-MM-DD`，业务所在地日期 | `"2026-11-15"` |
| 时间点 | ISO 8601，UTC，响应明确携带 `Z` | `"2026-11-15T02:30:00.000Z"` |
| 布尔 | JSON 布尔 | `true` |

- 响应中的数值按数据库精度原样返回，展示格式（千分位、去尾零）由前端处理。
- 页面按北京时间显示时间点。业务日期只表达某一天，按日期直接展示。
- 请求中的数值可以少写小数位（`"115"`），但不能超过精度（R3-03），超过返回 400，不在服务端悄悄截断。
- 前端用字符串保存数值，不转换成 JavaScript 的 `number` 参与计算（方案 5.2）。
- 字段值为 `null` 表示“有这个字段，当前没有值”；字段**不出现**表示当前用户无权查看（第 2.9 节）。

### 2.6 版本号

- 详情接口返回 `version`。
- `PUT` 修改和所有命令接口的请求体都必须带 `version`。
- 服务端用 `WHERE id = ? AND version = ?` 更新，影响 0 行时返回 409 `VERSION_CONFLICT`，`details.currentVersion` 给出当前版本。前端提示“单据已被他人修改，请刷新后重试”。

### 2.7 幂等

**哪些请求必须带幂等键**：所有产生业务效果的 POST，包括创建单据。不需要带的：登录、价格试算、查询类 POST、`PUT` 修改草稿（由版本号保护）、`DELETE`（重复执行结果相同）。缺少时返回 400 `IDEMPOTENCY_KEY_REQUIRED`。

**键的生成**：前端在用户**发起一次操作时**生成 UUID，例如点击“审批”时。这次操作因超时、网络错误而重试，必须复用同一个键；用户关闭对话框后重新发起，才生成新键。

**服务端的处理**（存储见《数据库设计》9.2 节）：

| 情况 | 响应 |
|---|---|
| 新键 | 正常执行 |
| 同键、同内容、已成功 | 返回首次的结果，HTTP 状态也相同 |
| 同键、同内容、仍在处理 | 409 `REQUEST_IN_PROGRESS`，带 `Retry-After` |
| 同键、内容不同 | 409 `IDEMPOTENCY_KEY_REUSED` |
| 同键、不同操作人 | 403 `FORBIDDEN`，不返回任何内容（T18） |

**超时后确认结果**：

```http
GET /api/v1/command-results?operation=sales_order.approve&key=3f6d2b1c-6e0a-4c55-9d43-2a7f1b8e9c10
```

| 结果 | 含义 | 前端处理 |
|---|---|---|
| 200，`status = succeeded` | 已成功 | 用 `response` 刷新页面 |
| 200，`status = processing` | 仍在处理 | 稍后再查 |
| 404 | 服务端没有收到，或者执行失败已回滚 | 可以用**同一个键**重新提交 |

前端取消等待不代表后端取消了交易。审批、出库、付款、退款超时后，页面显示“结果确认中”，先查结果，再决定是否重试（方案 5.2）。

### 2.8 列表与分页

```http
GET /api/v1/sales-orders?status=approved&customerId=500&dateFrom=2026-11-01&dateTo=2026-11-30&limit=20&cursor=eyJkIjoiMjAyNi0xMS0xNSIsImkiOiI3MjYxIn0
```

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "items": [],
    "nextCursor": null,
    "total": 0,
    "totalExact": true
  },
  "requestId": "9f2c6a1e8b7d4c3a"
}
```

- 用游标分页，不用页码偏移（方案 11.1）。`limit` 默认 20，最大 200。
- 排序只开放有索引支撑的字段，默认按业务日期、ID 倒序。
- `total` 只在请求带 `withTotal=true` 时计算，最多数到 10000；超过时返回 10000，`totalExact = false`，页面显示“10000+”。
- 日期范围最长 1 年，超过返回 400，避免全表扫描。导出走第 2.10 节的异步任务。
- Element Plus 分页组件使用“上一页 / 下一页”模式，前端缓存已经翻过的游标。

### 2.9 字段级权限

| 字段 | 需要的权限 | 无权限时 |
|---|---|---|
| 单位成本、成本金额、毛利 | `cost:view` | 字段不出现 |
| 往来单位联系人的电话、地址 | `partner_contact:view` | 字段不出现 |
| 银行账号 | `cash_account_no:view` | 只返回后 4 位，如 `"****6411"` |
| 用户手机号 | `user:view_mobile` | 字段不出现 |

TypeScript 类型中，这些字段都定义为可选属性。

### 2.10 异步任务

导入、导出、对账、成本重估返回 202：

```json
{
  "code": 202,
  "message": "任务已提交",
  "data": { "taskId": "7261839450137609001", "taskType": "export", "statusUrl": "/api/v1/export-jobs/7261839450137609001" },
  "requestId": "9f2c6a1e8b7d4c3a"
}
```

前端每 2 秒轮询一次 `statusUrl`，最长 10 分钟，之后改为提示用户“任务仍在后台执行，可以稍后到任务列表查看”。

### 2.11 超时与限流

| 项目 | 约定 |
|---|---|
| 前端请求超时 | 查询 15 秒；命令 30 秒 |
| 自动重试 | 只有 GET 允许，最多 2 次；命令一律不自动重试（方案 5.2） |
| 登录限流 | 同一 IP 加用户名，每分钟 5 次 |
| 普通接口限流 | 每个用户每秒 20 次，导出每个用户同时最多 3 个任务 |

具体数值在部署文档中确认，可以按服务器资源调整。

### 2.12 可执行动作

单据详情返回 `allowedActions`，列出当前用户此刻能执行的命令，由服务端根据单据状态、下游依赖和用户权限计算：

```json
{ "allowedActions": ["close_lines", "cancel", "create_change", "reserve"] }
```

前端按它显示按钮。即使前端显示了按钮，服务端执行命令时仍会完整校验，`allowedActions` 只用于展示。

## 4. 单据接口模板

业务单据的接口形状都相同，第 5 节只列各单据特有的命令。

### 4.1 标准接口

以 `/sales-orders` 为例，其他单据替换资源名：

| 方法 | 路径 | 说明 | 权限 | 幂等键 |
|---|---|---|---|:---:|
| GET | `/sales-orders` | 列表 | `sales_order:view` | |
| POST | `/sales-orders` | 新建草稿，返回 201 | `sales_order:create` | ✓ |
| GET | `/sales-orders/{id}` | 详情，含行、费用、进度、`allowedActions` | `sales_order:view` | |
| PUT | `/sales-orders/{id}` | 整单替换草稿，带 `version` | `sales_order:update` | |
| DELETE | `/sales-orders/{id}?version=3` | 删除草稿（R7-01） | `sales_order:delete` | |
| POST | `/sales-orders/{id}/<命令>` | 状态命令，请求体至少有 `version` | `sales_order:<命令>` | ✓ |

- 只有草稿能 `PUT` 和 `DELETE`，其他状态返回 409 `STATE_CONFLICT`。
- `PUT` 是整单替换：行列表里带 `id` 的行是修改，不带 `id` 的是新增，原来有、这次没有的行是删除。
- 单号在创建草稿时由服务端分配（R8-08），请求中不能指定。

### 4.2 命令请求与响应

请求：

```json
{ "version": 3, "comment": "同意" }
```

响应（方案 9.3：返回业务 ID、版本和确定的状态）：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": { "id": "7261839450137600001", "documentNo": "SO-C01-202611-000123", "status": "approved", "version": 4 },
  "requestId": "9f2c6a1e8b7d4c3a"
}
```

部分命令在 `data` 中返回额外结果，例如签收返回确认的应收和自动核销，见第 6 节。

命令成功时，`data` 中可以带 `warnings` 数组，表示操作已经完成、但需要提醒用户的事项，例如提交订单时的库存提示（R1-10）。前端用黄色提示展示，不当作失败处理。

## 6. 核心接口详细说明

样例沿用《业务规则》第 5 节的订单 SO-4，数字可以对照。

### 6.1 价格试算

M3 试算结果使用 `pricingVersion=2`。表头、商品行和费用行均返回 `priceTaxInclusive`。商品行的 `unitPrice`、`amount`、`lineDiscountAmount`、`lineNet` 和 `orderDiscountAlloc` 沿用录价口径，`receivableNet`、`totalAmount` 始终为含税应收或应付。费用 `amount` 沿用录价口径，`totalAmount` 是含税费用，承担方为 seller 的费用仅登记。

例如未税单价 10.00、数量 2、行优惠 10%、税率 13% 时，行金额为 20.00，优惠为 2.00，未税净额为 18.00，税额为 2.34，`receivableNet` 与 `totalAmount` 均为 20.34。表头 `goodsAmount`、行优惠、整单优惠和 `feeAmount` 都按录价口径汇总。含税录价时单据合计等于商品金额减优惠加费用，未税录价时还须加上逐行汇总的税额。

M4 创建和编辑订单应直接保存本次计算快照，包括头部 `pricingVersion`、头行及费用的含税标记和逐行金额。采购行将返回值 `receivableNet` 写为 `payable_net`，其金额语义同为含税。费用表的 `total_amount` 由金额、税额和含税标记生成。既有订单默认 `pricing_version=1`，保持历史金额约束；旧行及费用的新增含税标记默认 true。V11 迁移将两套已定义的快照明确区分。


前端录入订单时，防抖 300 毫秒后调这个接口显示金额，不在前端实现优惠分摊、税额和尾差算法（R3-04 — R3-07）。

```http
POST /api/v1/pricing/preview
```

请求体与创建订单的请求体相同，另加 `documentType`（`sales_order` 或 `purchase_order`）；响应与订单详情中的金额部分相同。不落库，不需要幂等键。

**按金额反算单价**（R3-11）：行上传 `amountInput` 而不传 `unitPrice` 时，服务端按 8 位小数反算单价，再用反算出的单价重新计算行金额。两者不一致时，在 `warnings` 中返回：

```json
{
  "warnings": [
    { "lineNo": 1, "type": "AMOUNT_RECALCULATED", "message": "按反算单价 33.33333333 计算，行金额为 100.00，与录入的 100.00 一致" }
  ]
}
```

用户确认后，前端用反算出的 `unitPrice` 提交，服务端只认单价和数量。

### 6.3 发货单

**新建**

应收在客户签收时确认（R2-01），发货单分三步：过账只出库，签收确认应收，有差异时再处理差异。

**新建**

```json
{
  "customerId": "500",
  "warehouseId": "100",
  "deliveryMethod": "delivery",
  "businessDate": "2026-11-16",
  "lines": [
    { "orderLineId": "7261839450137600012", "unitId": "1", "qty": "3" }
  ]
}
```

- 所有行的订单必须属于同一客户、同一公司，且订单行的仓库与发货单仓库一致（R8-02）。
- 订单处于 `change_pending` 时返回 422 `CHANGE_PENDING`。
- 新建只是草稿，不占用数量；`submit` 时才占用（R4-02），提交后不能修改，只能作废。
- `deliveryMethod`：`delivery` 送货，`pickup` 客户自提。自提时过账即全数签收（R2-12），过账响应同时包含下面签收响应的字段，状态直接为 `signed`。

- `unitCost`、`costAmount` 只对有 `cost:view` 权限的用户返回。
- 期间已关闭返回 422 `PERIOD_CLOSED`；订单行预留已失效且可用量不足返回 422 `INVENTORY_INSUFFICIENT`。

**签收**

```http
POST /api/v1/shipments/7261839450137700001/sign
Idempotency-Key: 6b2e9d4f-8c15-4a73-b0e2-5d1f3c7a9e68
```

```json
{
  "version": 3,
  "signDate": "2026-11-17",
  "lines": [
    { "lineId": "7261839450137700011", "signedQty": "3" }
  ],
  "attachmentIds": ["7261839450139000001"]
}
```

- 一张发货单只签收一次，`lines` 必须包含所有行（R2-10）。`signedQty` 用基础单位，可以为 0（整行拒收），不能超过发货数量，否则返回 422 `SIGN_QTY_EXCEEDED`。
- `signDate` 不能早于发货日期、不能晚于当天，否则返回 422 `SIGN_DATE_INVALID`；所在期间已关闭，返回 422 `PERIOD_CLOSED`。
- `attachmentIds` 是先通过 `POST /attachments` 上传的签收回单，可选。
- 发货单不是 `posted` 状态时返回 409 `STATE_CONFLICT`。

服务端在一个事务里完成：检查签收日期所在期间 → 状态改为 `signed`，有差异时改为 `signed_with_diff` → 逐行记录签收数量和差异数量 → 订单行已签收数量增加，差异数量从已发数量扣回（R2-11）→ 按 R3-08 累计法确认应收 → 首次签收时确认买方运费（R2-06）→ 写分录：确认收入、结转签收部分的成本 → 自动核销关联本订单的预收（R4-07）→ 更新订单进度。

成功响应的 `data`（第 2 行 3 件全数签收；该订单此前有关联预收 300.00）：

```json
{
  "id": "7261839450137700001",
  "documentNo": "SH-C01-202611-000045",
  "status": "signed",
  "version": 4,
  "signDate": "2026-11-17",
  "receivableAmount": "167.50",
  "untaxedAmount": "148.23",
  "taxAmount": "19.27",
  "signedCostAmount": "30.00",
  "lines": [
    { "id": "7261839450137700011", "signedQty": "3.000000", "diffQty": "0.000000", "diffDisposition": "none", "receivableAmount": "137.50", "untaxedAmount": "121.68", "taxAmount": "15.82", "signedCostAmount": "30.00" }
```

- `receivableAmount` = 行应收 137.50 + 运费 30.00；预收 300.00 自动核销 167.50 后还剩 132.50。

**处理签收差异**

```http
POST /api/v1/shipments/7261839450137700001/resolve-diff
Idempotency-Key: 1f7c3a9e-4d26-4b81-9e05-8a6c2d4b7f13
```

```json
{
  "version": 4,
  "businessDate": "2026-11-19",
  "lines": [
    { "lineId": "7261839450137700011", "disposition": "returned", "reason": "客户拒收：外箱破损" }

```

- `disposition`：`returned` 拒收退回，货退回原仓库，进入冻结待检，按原出库单位成本入库；`lost` 运输损失，成本转入损失（R2-11）。

## 9. 与方案 9.3 的差异

| 方案中的写法 | 本文 | 原因 |
|---|---|---|
| `POST /documents/{id}/reverse` | `POST /document-reversals` 及其审核、过账命令 | 冲销单需要单独审核，有自己的状态 |

## M11 工作流与最低售价（目标1.3.0，未发布）

完整接口表和状态口径见[工作流详细设计](详细设计/02-工作流.md#8-rest与前端)。统一前缀`/api/v1/workflow`，要求会话、公司头；写请求还需CSRF、幂等键及版本。个人任务不授予额外来源权限，配置接口由全组织范围和细分管理权限控制。

销售/采购提交Command、退款Version、库存调整Version及冲销Input新增可选`workflowAssignees: { 节点编号: [用户编号] }`，旧请求不变。原`approve/reject/withdraw/cancel/void`在有运行流程时返回409，最终回调继续执行原服务。详情新增`workflowInstanceId/workflowStatus`；无绑定仍为旧单级审批。

商品规格新增可选`minSalePrice`（含税基本单位最低价，非负、最多8位小数，0不控制）；旧更新缺省不覆盖原值。公司政策新增`belowMinPricePolicy: warn|approval|block`。低于最低价且需要审批时，无匹配人工价格节点返回`PRICE_APPROVAL_REQUIRED`，不静默降级。任务版本冲突409、非当前处理人403、跨企业/公司/来源范围404或原权限403，异常响应不暴露引擎堆栈。

## M15 智能查数

- AI 会话的发送消息接口接受可选 `toolCode=auto`。结果沿用 SSE，`tool_result` 包含 `status`、`asOf`、`rows`、可选汇总、候选和来源链接。历史会话不暴露查询结果。
- ERP 内部 `POST /api/v1/ai-tools/query/{code}` 以及 `GET /api/v1/ai-tools/scope/{code}` 分别执行预定义查询和复核权限范围。使用签名和会话，不公开在 OpenAPI。 [智能查数安全与使用说明](../使用说明/M15智能查数使用与验收.md)
- `GET /api/v1/reports/receivable-aging` 与应付账龄支持可选 `agingDate`。销售汇总及毛利报表接受新 `groupBy=customer|sku|department`，并沿用业务员维度。实时库存接口接受精确 `skuId`。
- 智能查数评测集为 `erp-data-m15`，新增 `GET /ai/v1/admin/evals/{setId}/cases`。启动接口接收 `reportBaseline`，以场景编号为键。逐条返回工具选择、参数及是否与报表一致。

## M15 单据解释

- `POST /ai/v1/conversations/{id}/messages` 使用显式 `toolCode: "document_explain"`，`toolArguments` 包含 `documentType` 和字符串 `documentId`。预检结果经 `tool_result` 返回，`summary` 含原状态、页面可用操作和检查结论，`rows` 含原因及已授权关联链接。
- ERP 内部的 `/api/v1/ai-tools/query/document_explain` 和 `/api/v1/ai-tools/scope/document_explain` 均使用签名 `POST`，绑定相同的目标参数，按登录主体实时核验权限。
- `GET /ai/v1/admin/evals/erp-explain-m15/cases` 列出基准所需场景。启动评测发送 `documentBaseline`，复核实际状态、检查原因、来源和安全拒答。 [基准格式](../使用说明/M15单据解释使用与验收.md)
