# M11 后半工作流实施设计

- 日期：2026-11-16；承接M11前半`65aaecb`，分支`codex/m11-workflow`。
- 环境：继续JDK21、Spring Boot4.1.2、MySQL8.0.46、Redis6380及现有Vue3前端。Flowable固定8.0.0；Jackson等公共依赖沿用现有Boot依赖管理，不降级主要组件。
- 范围：Flowable同事务验证、SIMPLE模型发布与绑定、组织审批策略、审批操作、个人审批中心、五类单据及最低售价控制。BPMN编辑器、动态表单及通用HTTP触发器仍属后续阶段。
- 文档维护：maorongkang@gmail.com。

## 先验证事务

在随机独立MySQL演练库中执行现有V1—V43，再让Flowable与真实业务服务使用同一个DataSource和PlatformTransactionManager。验证提交/启动共同回滚、任务完成/业务回调共同回滚、成功提交、事务失败后幂等重试及并发结果。保留原始日志，清理时仅删除本次新建库和专用账号。

验证通过才使用同步业务回调；验证不通过则采用用户指定的Outbox回调。异步方案也保留既有业务待审状态，流程同步状态另存，不能增加未经业务状态机认可的“提交中”状态。

依据：[Flowable8.0.0官方发布说明](https://github.com/flowable/flowable-engine/releases/tag/flowable-8.0.0)与[Spring事务集成说明](https://www.flowable.com/open-source/docs/bpmn/ch05-Spring)。官方已支持Spring7、Boot4及Jackson3，实际兼容性仍由本项目真实事务测试决定。

## 业务边界

新增工作流模块，经共享接口接入业务，不让业务模块直接操作ACT表，不引入模块循环。业务状态及库存、资金、期间、复核和幂等命令继续由原服务负责。运行中的流程冻结模型版本；无绑定保持原单级审批。

退款、冲销和库存调整沿用现有实际待审状态，不强行统一改名为pending。原生审批和驳回入口在流程运行中拒绝执行；最终回调也必须重新执行权限、版本、硬规则及业务事实校验。

原详细设计将最低售价“需要审批”在无流程时降为提示，会绕过用户要求。实施时修正为：提示模式告警、禁止模式拒绝、需要审批模式必须取得有效人工审批；缺少可用流程时明确阻止提交，不静默降级。自动处理不计作有效人工复核。

## 实施顺序

1. 完成真实引擎事务验证并记录结论。
2. 追加官方引擎结构及模型、绑定、实例、任务、动作和抄送迁移；不修改V1—V43。
3. 实现受限SIMPLE节点树及后台编译、组织策略、版本、绑定、任务处理和超时提醒；不接受用户脚本、原始BPMN或手写表达式。
4. 接入五类业务、最低售价、现有消息中心及任务管理，补齐权限交集与旧流程回归。
5. 实现设计器、审批中心和单据进度，完成组件、浏览器、升级及完整回归。
6. 同步开发计划和使用/部署文档，分模块提交、推送、创建承接PR并跟进CI。

## 已执行的技术决定

四项先行真实事务门槛通过，采用同步同库事务回调；正式V44—V46结构下再次通过。保持原业务状态：销售/采购和库存调整pending、退款pending_review、冲销创建即pending。工作流完成只调用原approve/reject，不自动付款或过账。

SIMPLE固定编译、冻结发布版本、组织策略、人工复核和价格hash均在服务器验证。消息事务只持久化Outbox意图，避免在流程事务中逐个锁收件人；Redis在提交后通知，REST即时补齐。抄送按记录ID同步已读。最低价提交/批准以FOR SHARE读取当前公司策略及商品价格，避免重复读事务的旧快照；附已建立旧快照后另一事务更改策略的真实回归。

独立V43→V46演练验证默认回填、自定义角色不提权及原业务样例事实；随机仅DML账号完成真实引擎生命周期，DDL请求被拒绝，演练账号和新库均清理。具体结果与限制见[本机验收报告](../测试/验收记录/M11工作流本机验收报告.md)。
