# 销售调价与红字联动设计

- 对应《业务完整性评估与改进方案》第三批、B-02 销售侧。
- 状态：退货计价兼容基础已回归，手工红字后端及 V108 升级已接入；销售调价单、完整红字联动和页面仍在实施，不作为上线结论。
- 维护：maorongkang@gmail.com。

## 1. 业务范围

调整已签收发货行的含税价格。正数补收、负数折让，产生独立应收或客户信用额，沿原应收到期日；资金核销与退款仍走既有流程。调整单必须提交并由另一人复核，按开放期间过账，过账后只能冲销。

可调数量为该发货行已签收减已过账退货的基本数量。发货单只签收一次，签收差异另行处理；允许调整 `signed_with_diff` 中已经签收的部分，未签数量和后续另开发货不进入本次调价。原订单、签收应收、出库及签收成本快照不改写。

销售调价不改变库存及销售成本，也不要求销售人员取得成本查看权限。毛利变化只来自未税收入的调整。

## 2. 金额和退货

复用采购调价的含税金额、税额及单位换算规则。新含税单价与调整金额二选一，最多 100 行；按原税率快照计算，不允许负的新价格或剩余金额。金额、税额和末次尾差按 R3 处理，字符串和 `BigDecimal` 保留精度。

共享金额算法时，销售不读取或写入采购专用退货单位成本，也不能因该未使用的成本派生值超出范围而拒绝合法售价；仅校验销售实际保存的价格、金额和税额。

剩余金额为原签收金额加已过账调价、减已过账退货；税额独立计算。已退部分不因后续调价重算。每次调价为当前剩余数量建立新的退货货款/税额基准，记录此前已退数量、剩余数量、金额、税额和调价日期。

后续退货按该基准累计舍入，末次退完余额；货款与税额复用 `PricingEngine.recognize`。退货成本仍按原签收成本的累计数量计算，不能采用调整后的售价。退货业务日期不能早于当前计价基准日期。冲销退货恢复原累计数；冲销调价须先处理其后的退货和调价，再恢复上一基准。

## 3. 蓝字、红字与额度

开票额度按发货行归组，包含原正向应收及正调价，扣除退货和负调价。正向来源分摊净可开票额度，已登记或已预留的蓝字继续占用额度；付款结清不影响是否可开票。手工登记与数电预留必须使用同一份净额度，不能在折让后继续按原应收全额开票。

已开票来源做负调价时，须先完成红字处理；申请中、财务待确认、服务商处理中或结果未知都不能当作已红字。复用现有数电整票红字链路：一张票涉及多条来源时显示完整影响范围，冲红成功后按新的净额重新开具。重试保留原请求及幂等键，不在超时后另建红字请求。

手工蓝票增加红字登记与独立财务确认，记录原票、红字票号、日期、金额、税额、原因及两位经手人。确认前不释放蓝字占用；确认后在同一事务释放一次并保留关联。普通作废登记不能伪装为已完成红字。原票、红字登记和真实数电请求均保留历史，不删除实际发票证据。

蓝字预留、释放、红字确认、调价过账及相关退货/冲销统一协调来源额度。锁顺序先公司销项协调锁，再单据头、发货/订单来源，最后按编号锁应收。保存与过账均持锁重算，预览不能代替过账校验。

## 4. 数据及迁移

V105 已预留 `kind='sales'`、`shipment_line_id`、通用金额和来源快照，本批复用头行表，不修改 V104—V107。V108 已实现手工红字与销项锁并通过升级演练，冻结后不再修改；销售发货行及调价权限由后续迁移接入。

- `shipment_line`：增加累计销售调价金额、税额和退货计价基准；扩展已退信用额上限，旧金额、成本、版本和时间保留。
- `price_adjustment_line`：销售行仅填发货行，采购行保持原规则；复用源版本、剩余数量、原/新金额、税率与上一计价基准。销售不写采购成本分摊表。
- 销项协调锁：按公司互斥相关额度写入，不复用进项核对关系或资金核销锁代替。
- 手工红字登记：独立记录原票、红字事实、申请/确认状态、版本、人员与时间；唯一原票关系和公司内红字票号约束，防止重复释放。
- 新增独立销售调价及手工红字权限，沿现有系统管理员的条件授权方式迁移，不让普通查看权限隐式取得过账权限。

## 5. 接口

销售调价使用 `/sales-price-adjustments`，提供列表、详情、来源、创建、更正、预览，以及提交、批准、驳回、过账、作废命令。输入使用 `shipmentLineId`，与旧采购 `receiptLineId` 接口分开；旧采购接口和幂等摘要保持兼容。

来源返回已签收/已退/可调数量、原价、当前剩余金额和税额、税率、版本及开票阻挡原因。详情返回调价行、审批状态、过账事实和相关发票摘要。不得把库存成本作为销售调价请求的必填或返回字段。

开票登记增加手工红字申请、详情及财务确认接口；数电红字复用既有请求、确认、查询和文件接口。禁止通过前端布尔标记声明“已红字”，后端读取当前真实事实。

## 6. 工作流、权限及冲销

复用既有调整单状态机和工作流接入方式；业务类型为 `sales_price_adjustment`，与采购的权限、范围及审核回调区分。复核人不能是制单人，工作流绑定后不能绕过任务直接批准，支持既有自选复核人。

所有列表、详情、财务操作、报表、发票摘要和旧幂等响应重验公司、仓库与部门范围。销售不复用采购的成本权限作为销售价格权限；同一个头行表不能导致跨业务类型读取。

冲销检查核销、退款占用、开票及其后的退货/调价，追加反向往来和分录，恢复前一退货计价基准。原发货冲销先处理已过账销售调价；已冲销来源不能再次过账或出现在候选中。

## 7. 总账及报表

补收：借应收、贷主营业务收入及销项税。折让为相反方向，金额使用绝对值与明确借贷，不生成库存流水或成本差异。

销售、毛利与客户对账纳入调价，数量保持实际签收/退货口径，独立调价不虚增销量。门户只读取绑定客户，单据来源可穿透到右侧详情。业务应收、未清项、运营分录、总账及三大报表均纳入真实过账和冲销对账。

## 8. 页面

销售侧增加调价列表，发货详情提供入口。查看、编辑、预览及发票相关详情均使用右侧抽屉，保留列表筛选、页码和滚动位置。沿用重点金额与原价→新价对比，金额列右对齐，零金额弱化，小屏在抽屉内横向阅读。

抽屉清楚显示可调的已签收数量、未退数量、应收调整、税额和红字进度。存在未保存数据或网络未知结果时有离开保护；未知提交冻结原载荷与键，确认后重新读当前详情。

## 9. 验收

- 部分签收、先退后调价、调价后多次退货、连续调价及末次尾差；原价、已退金额与成本不被改写。
- 先收款后折让、补收后的开票、负调价净额度、已开票先红字、手工与数电两条红字路径；重复/未知结果不能多释放。
- 实际工作流、自选复核人、闭期、源版本变化、越公司/仓库/部门及旧响应权限回归。
- 真实总账、八类业务对账、报表、毛利及门户穿透；调价和原发货的冲销依赖完整。
- V107→V108 红字旧数据升级及后续销售结构升级、后端、前端、知识和真实浏览器；本机容量记录明确受测规模。
- 数电服务商真实沙箱单列证据。本地受控网关只证明接口契约，不能写成真实第三方验收通过。

## 10. 实施顺序

1. 先接入可兼容旧数据的销售退货货款/税额计算，保留原成本算法。
2. 完成手工红字与销项锁的 V108，再通过后续迁移接入销售来源、金额、状态机、往来、总账和冲销。
3. 统一净开票额度、数电红字及手工红字确认，完成并发和权限检查。
4. 接入右侧抽屉、报表、门户和知识，运行完整回归、升级、浏览器及容量验证。

## 11. 退货计价基础验收

`ShipmentReturnPricing` 位于现有定价模块。没有销售调价基准时沿用原签收金额、税额与已签数量；存在基准时只重算剩余退货货款及税额，末次吸收尾差。原签收成本仍由 `SalesReturnService` 的原累计公式计算，不进入新价格算法。

新增 11 项单元测试通过；包含模块边界的全部 158 项单元、销售财务、冲销、月结总账及进项工作流的 45 项实际执行集成测试通过，另有 1 项条件容量测试未启用。旧构造签名及旧数据路径保持兼容。当前尚无写入销售调价基准的业务入口，不能据此认为完整销售调价已交付。

## 12. 手工红字后端验收

V108 旧数据升级及约束演练通过，原有效/已作废票、分配、应收、版本和时间保持不变；应用升级终点已同步为 108，迁移已冻结。手工红字申请不释放占用，另一人确认后原子释放整票；旧作废票的真实红字补录不触碰其他票的已用额度。

最新 158 项单元和 64 项业务集成通过，另有 1 项独立升级用例。包括真实 HTTP 登录及红字接口、重复请求与结果查询、并发登记/确认、与普通作废竞争、二百来源整票、异常来源整体回滚、权限收窄以及数电原流程。旧采购登记仍可查询，不能登记为销项红字。数电 Provider 为测试替身，尚无本批真实服务商沙箱结论。

原票接口提供红字进度，待确认时不再提供普通作废操作。本阶段没有销售调整单、净开票额度或红字右侧页面；下一步继续销售侧来源与过账，不作为 B-02 销售完整交付。
