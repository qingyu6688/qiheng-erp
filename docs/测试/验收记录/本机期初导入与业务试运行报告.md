## 部署与开账基线

用原 JAR 将空库迁至 Flyway V31，确认没有预置租户。沿用包内权限验证脚本分配运行账号和迁移账号，验证运行账号可追加审计，且无权执行 DDL、改审计、删凭证或写权限目录。迁移账号的 DDL 探测通过。

使用新增的独立初始化工具为演练空库创建一套企业、公司、管理员与授权，写入初始化审计，要求管理员首次改密。再次执行被拒绝，企业、公司和管理员各保留一条。初始化后先停写冻结，保存数据库、对象仓和 binlog 水位，再启动业务演练。

## 部署包发现的问题

原始 0.8.1 成品通过库存期初 CSV 导入、错误清单、原文件重传和异人审核，第一次过账返回 500。凭证 SQL 使用 `ON DUPLICATE KEY UPDATE id=id`，MySQL 要求 `journal` 的 UPDATE 权限。生产模板给运行账号的凭证权限为 SELECT 与 INSERT，演练保留了这一约束。失败请求编号为 `7afd2c6e-6127-48f9-a6ec-b2ada764c644`。

修复候选改用普通 INSERT，冲突时按原来源当前读并核对凭证内容。冲销继续锁原单并用共享锁读取追加事实，关账补投影只排他锁待处理的 Outbox 行。原始部署 ZIP 保留供核对。

候选 JAR 的 SHA-256 为 `230d851e805a9e63d2dc285e3a6f35a0821525924bdec3017ebc3b039150e484`。切换前查到原库存单仍为已审核，库存流水与凭证各为 0。切换时沿用同一个库、同一个运行账号和迁移账号，继续使用原包内的前端静态文件。凭证权限保持 SELECT 与 INSERT。

## 试运行与对账

采购 10 件、收货后增加 140.00 元存货成本，实付 175.00 元，核销采购和期初应付。销售 3 件、金额 60.00 元，发货后签收生成应收，实收 110.00 元，核销销售和期初应收。

期末实测库存 27 件、成本 342.00 元、资金余额 935.00 元。应收、应付未清项各为 0。库存余额、库存成本、预留、资金余额、未清项、凭证平衡、库存账本及期间八类对账均为零差异，关账预检查五项均无阻挡。

暂停 Worker 后，另录入 1 件、12.00 元的库存调整，异人审核并冲销。库存回到 27 件、成本 342.00 元。关账 API 在 Worker 停止期间补齐两笔凭证投影，随后重开期间，资金仍为 935.00 元。用同一运行账号直接修改凭证被 MySQL 拒绝。重启 Worker 后待处理或失败 Outbox 事件数为 0。
