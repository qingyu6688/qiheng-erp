## 事务门槛与技术结论

先在随机独立库和随机专用账号上验证，再在正式V44—V46迁移结构下复测。使用真实SalesOrderService、BusinessCommands、Outbox、库存预留和Flowable，没有用模拟流程引擎代替。

| 场景 | 结果 |
| --- | --- |
| 创建、提交和引擎发起后注入故障 | 原单、引擎、幂等及Outbox全部回滚 |
| 完成任务及原approve预留库存后注入故障 | 任务、审核及预留全部回滚，原幂等键重试成功 |
| 原事务未提交时用独立连接读取 | 单据及引擎执行均不可见 |
| 引擎启动失败后重新提交 | 原业务状态及命令键回滚，可重试 |

四项全部通过，因此采用同DataSource、同PlatformTransactionManager、同步业务回调；没有启用Outbox回调业务命令的备用方案。Outbox用于可靠消息投递，不改变审核事实的事务边界。本次是自动化事务门槛验证，没有据此声称完成多日生产稳定性测试。

另以本轮新建随机账号逐表授DML，wf_model_version/wf_task_action等追加表只授SELECT/INSERT，sys_permission等只读；实际完成引擎启动、模型发布、流程发起、任务完成及清理，CREATE TABLE被数据库拒绝。与部署授权脚本使用相同表级策略，兼容官方ACT_*大小写。最后仅清理本轮新库及随机账号。

本次是独立样例升级，不代表生产大库的DDL锁等待、备库追平耗时或真实服务器已验收。V1—V43没有修改；V44—V46校验值已冻结，后续业务变更须继续追加迁移。V44在首次提交前仅将Windows提取时多余回车规范为LF，SQL字符及上游尾随空格保留，规范前后CRC32与成功迁移历史一致，原生Flyway对全部45项迁移validate再次通过。常规差异空白检查排除保留上游空格的V44后通过，未借此改写已发布迁移。
