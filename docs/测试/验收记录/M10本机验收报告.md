## 真实报表主备演练

由容量主库的一致逻辑快照初始化同版本备库，以 GTID 和 TLS 建立限定本轮数据库的复制。报表账号仅有相关事实、标签及水位表的 SELECT，不授予认证表或写权限。API、Worker 使用同一备库配置。

- 十类报表的行、汇总和行数与主库对照一致，均返回 `dataSource=replica`，工作台返回备库数据标识。
- 后台销售报表导出状态为 `succeeded`，截止时间保存到导出任务。
- 本轮短时查询日志中，主库应用账号的商业报表事实 SQL 为 0，备库报表账号为 4；随后关闭临时查询日志再压测。
- 报表账号 UPDATE 水位及 SELECT 认证表均被拒绝。备库两种只读状态均开启。
- 暂停应用复制线程后，主库心跳前进、备库水位及报表截止时间保持；恢复并等待 GTID 追平后，截止时间由 `2026-11-16T04:33:50.942Z` 前进到 `2026-11-16T04:33:55.949Z`。

证据为 `.local/o26/replica-validation.json`、`replica-status.txt`、`reports-primary.json`、`reports-replica.json`、`reports-paused.json`、`reports-resumed.json`。逻辑快照和凭据不提交 Git。
