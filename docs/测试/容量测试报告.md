## O-32 首批容量回归入口（2026-11-18）

新增 `scope-read` 场景，沿用本机 19080、`erp_load_*` 独立容量库、随机运行编号和临时凭据。该场景通过正常登录和 REST API 读取单据与报表。预热和结束复查均验证真实的可见记录、同仓异部门拒绝、同部门异仓拒绝、同企业其他公司拒绝、其他租户拒绝。越权详情必须返回 404，越权关键词列表及其统计必须为空，越权公司请求必须返回 403。对照账号须能读到对应事实。读取报表时核对签收行实际关联同一订单，以及商品、部门和仓库一致。

## O-32 带流程的销售订单提交与审批

`workflow-sales` 场景在一家公司并发完成真实的销售订单新建、提交和审批。每次执行通过目标公司的 `operator` 制单并提交，由同一公司下另一个 `reviewer` 登录后处理待办。其余隔离公司作为权限及账本对照。

1. 从项目根目录使用 `run-capacity.ps1 server` 和私有设置文件单独创建一个 `erp_load_*` 容量库及运行文件。选用容量夹具中的一家公司，建议两家企业样本较大的一家。保持同租户另一家公司和外租户作为对照。本场景保留启用的流程绑定，普通销售写入场景另用隔离库。
2. 使用私有运行文件的口令在所选租户登录 `reviewer`，从 `GET /api/v1/auth/me` 的 `data.id` 获取复核人的编号。另以 `operator` 登录，通过审批中心或 `POST /api/v1/workflow/models` 建立公司级销售订单模型。模型包含发起节点和一个人工复核节点，选择会签、指定用户 `reviewer`、无超时和特殊价格或信用审批。使用 `POST /api/v1/workflow/models/{id}/publish` 发布，再通过 `POST /api/v1/workflow/bindings` 建立同公司无条件销售订单绑定。写请求沿用当前公司头、会话、CSRF、版本和幂等键。绑定生效后保存隔离库快照。
3. 在 `.local/workflow-sales.json` 中记录样本标识、实际公司编号、模型编号、发布版本和复核节点编码。数字编号使用字符串，避免超出 JavaScript 整数精度。节点编码可从 `GET /api/v1/workflow/models/{id}/versions/{version}` 的 `data.simple.child.id` 读取。

```json

  "dataset": "workflow-sales-base01",
  "companyId": "991001",
  "modelId": "991002",
  "modelVersion": 1,
  "nodeKey": "review"
}
```

在项目根目录运行检查与采集。`WorkflowRates` 是每秒并发启动的订单数，默认 2。`LineCounts` 是固定行数档位，同一轮分别记录 1、20 或 100 行样本。`Duration` 使用整秒、整分钟或整小时，例如 `30s` 或 `1m`。

```powershell

```

每个档位先核对发布快照内容摘要及公司绑定，再执行一张暖机订单。暖机核对制单人审批拒绝、同企业异公司和外租户的订单与流程读取拒绝、异公司和异租户的待办写入拒绝，并用原幂等键重放同意确认只有一次审批及业务回调。计时阶段单独记录 `workflow_sales_write_duration` 的 `/sales-orders/:id/submit` 和 `/workflow/tasks/:id/approve`，暖机、建单、详情校验和对账的耗时单独保留在 HTTP 日志中。每张计时订单都核对同一流程发布版本、同一实例、审批证据、订单状态和全部明细的预占库存。压测后重复核对暖机订单的读取隔离，同时逐公司运行现有运营账本对账，要求零差异、零超量履约、零重复过账、零超限退款及 Outbox 和导出任务积压清零。

每个行数和速率档位须完成全部额定订单、无调度丢弃、无校验失败，且提交、审批各自的 P95 小于 1000 ms。基线与候选从同一份兼容快照恢复，记录源码提交、候选包摘要、发布快照内容摘要、样本、运行环境及负载设置。每个版本及档位做三轮，验收比较对应路径 P95 的三轮中位数，候选不得超过基线的 1.2 倍。原始 JSON 和日志仍由 `.local/capacity-results-<运行编号>/<标签>/` 保留。

本机 Node 模块回归 4 项通过，k6 2.4.0 场景配置检查通过。本地 HTTP 替身以每秒 4 张、每张 20 行运行 1 秒，完成 4 次迭代并通过暖机及结束检查。实际 Flowable 与 MySQL 容量结果待专用隔离库采集。

`WmsRate` 是每秒启动的波次数，每波次固定两条并发确认。`wms_pick_write_duration` 按领取、确认和完成三条路径记录单请求的发送、等待和接收时间。权限拒绝、暖机重放与读取核对保留独立 HTTP 阶段标签。额定负载须完成全部波次及两倍确认次数、无迭代丢弃、无校验失败，三条路径各自 P95 小于 1000 ms。基线与候选从同一数据快照开始，保持硬件、库位分布、权限、服务及发生器配置一致。各版本各档做三轮，候选对应路径的 P95 中位数不得超过基线的 1.2 倍。原始记录位于 `.local/capacity-results-<运行编号>/<标签>/`。

首次突发检查发现压测脚本入库/退款键缺少场景名，复用了前一混合轮次的请求键，正确的幂等重放使 3 次额度查询找不到已完成退款的旧额度。原始 `ssd` 结果保留为脚本失败；修复为运行编号、阶段、场景、迭代共同组成请求键，并使用全新 `ssdrefined` 标签重跑，未删除旧事实。
