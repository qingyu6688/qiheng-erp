# M14 工作流二期使用说明

ERP 主库升级到 V56 后，可在流程管理切换 BPMN 画布，配置包容分支、优先路由、内嵌子流程、延迟和触发事件。通用审批使用已发布流程和独立表单，现有业务单据继续由原服务校验确认条件。

## 流程设计与发布

1. 在「流程管理」创建业务单据或「通用申请」模型。在 BPMN 画布点选节点，通过属性面板编辑。用节点树调整环节顺序、添加分支及子流程内部环节。
2. 包容分支执行全部命中的分支，全部已启动分支完成后汇合。优先路由按编辑顺序选择第一个命中的分支。两类节点均配置一个默认分支。
3. 子流程的内部环节随父流程版本发布，完成后继续父流程后续步骤。可在子流程内增加延迟节点，由 Worker 的 `workflow.delay` 统一调度；延迟为 1 秒至 7 天。
4. 触发节点发布 `workflow.trigger` 事件。事件保存公司、实例、节点和预定义事件类型。可以在开放平台订阅事件，待业务事务提交后送达。
5. 保存草稿并发布。服务端只编译允许的节点和条件，发布版本冻结。审批流配置需要每条可达路径至少包含一次人工审批。

## 配置与发起通用审批

- 管理人员以 `workflow_form:manage` 权限进入「通用审批表单」。选择当前公司可用的已发布模型，然后设置文字、数字、日期、单选和布尔控件，预览后启用。
- 节点中填入表单的字段编码，选择只读、可写或隐藏。审批人仅看到节点允许读取的字段，提交同意时只接受节点允许写入的字段。申请创建时冻结表单结构与值。
- 发起人需 `wf_generic_request:create` 和 `wf_generic_request:view`。在「发起通用申请」选择表单，提交后可在待审阶段添加附件。当前任务处理人按公司、部门、角色和节点权限访问申请，原有经办复核分离继续生效。
- 具备 `wf_generic_request:approve` 的合资格审批人在「我的审批待办」中处理，申请人从「我的申请」查看审批轨迹。

## 工作流接口

统一前缀 `/api/v1/workflow`。请求使用 ERP 会话和当前公司头，写请求使用 CSRF 与 `Idempotency-Key`。

| 方法和路径 | 用途 |
| --- | --- |
| `GET /forms?manage=true` | 查询当前公司的表单配置 |
| `GET /forms` | 查询当前公司允许发起的表单 |
| `GET /forms/models` | 可供表单选择的已发布流程 |
| `POST /forms`、`PUT /forms/{id}` | 新建或维护字段、模型与启用状态 |
| `POST /requests` | 填写标题与字段，基于当前表单版本发起申请 |
| `GET /requests/{id}?taskId=…` | 按权限返回申请字段及读写状态 |
| `POST /tasks/{id}/approve` | 在审批命令的 `fields` 中提交当前节点的可写字段 |

前端 BPMN 画布使用 `bpmn-js`，保留 bpmn.io 标识。动态表单使用 FormCreate 的 Element Plus 渲染组件，规则由已校验的字段定义生成。[bpmn-js 许可](https://github.com/bpmn-io/bpmn-js/blob/main/LICENSE) · [FormCreate 组件文档](https://www.form-create.com/en/v3/guide/packages)

本期子流程与父实例共用审批状态，触发器经预定义事件与开放平台订阅触达外部系统。独立异步子流程、任意 HTTP 地址及脚本仍待后续设计。
