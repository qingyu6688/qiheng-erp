## 一、准备目标环境与候选包

- [ ] 确认候选源码的前后端版本均为 1.0.0。在项目根目录运行 `pwsh -NoProfile -File scripts/project.ps1 verify` 和 `pwsh -NoProfile -File scripts/project.ps1 e2e`，并在 `erp-web` 运行 `npm run lint`、`npm test`、`npm run build`。提交候选源码后回到项目根目录执行 `pwsh -NoProfile -File scripts/package-release.ps1 -Version 1.0.0 -Candidate rc.1`。核对清单中的源码提交、JAR、前端与交付包摘要，上机及切换时按清单校验同一份候选产物。[部署说明](部署说明.md)
- [ ] 用独立的运行、迁移、备份账号配置 MySQL 8.0.46，检查 Flyway 版本、运行权限、主备复制、只读备库和切换演练。Redis、MySQL 和对象仓走受控网络，API 和 Worker 指向同库及同一私有桶并各用独立节点号。验证 HTTPS 入口、健康探针、附件及文件任务、备份恢复和告警。按真实用量在目标入口复测容量，记录实测恢复点和用时。[运维手册](运维手册.md)
- [ ] 计划开启多方式登录时，迁移至 V33 后核对登录方式设置的授权范围，再配置服务端加密密钥、SMTP 主机和微信 HTTPS 回调域。用试运行账号逐个核对短信、邮件投递以及微信扫码绑定、回跳和登录。[多方式登录配置](多方式登录配置.md)
- [ ] 完成首个企业与管理员的受控初始化，记录目标企业与操作人，首位管理员首次登录改密。确认各公司纳税人身份、仓库、结算账户和开放期间。授予制单、审核、过账与公司级对账权限，核对异人审核和跨公司访问约束。
- [ ] 对照请求记录与业务约定时区核对导入任务的创建时间。本机演练记录了列表与实际上传时间相差 8 小时的样本，正式切换以带时区的记录及数据库事务水位为准。

## 二、整理期初数据和未完成订单

按公司整理数据，保存原始导出、映射版本、截止日、行数和汇总数。先核对往来单位、商品、SKU、单位换算、仓库和结算账户映射，再由仓库和财务核对库存数量、成本及往来和资金余额。无法映射的项目保留处理记录，核定后再进入正式批次。

| 数据 | 需核对的原始字段 | ERP 录入与校验 |
| --- | --- | --- |
| 库存期初 | 公司、仓库编码、SKU 编码、单位、数量、整行总成本、业务日期和原因。冻结、预留、调拨在途、发出未签收另列清单 | 按公司和仓库填写 UTF-8 CSV，选择业务日期。固定表头为 `skuCode,unitName,qty,totalCost,reason`。每个有效行生成草稿，提交后由另一人审核，再过账。待检、占用、在途等状态按对应业务规则衔接 |
| 客户及供应商期初 | 公司、往来单位编码、客户或供应商角色、原单号或账龄台账、借贷方向、未清金额及业务日期 | 在“往来与资金期初”录入。客户欠款用 `receivable/D`、预收用 `receivable/C`，供应商欠款用 `payable/C`、预付用 `payable/D`。应收、应付分别核对 |
| 资金期初 | 公司、结算账户编码、截止余额、对账日期及银行或现金盘点依据 | `cash/D` 按结算账户录入，异人审核并过账后与截止余额逐户核对 |
| 未完成销售和采购订单 | 公司、旧单号、往来单位、日期、状态及各行的 SKU、仓库、单位、已执行量、剩余量、单价、税率、折扣，并关联在途、退款及预收预付 | 保留旧新单号映射，按业务单据承接剩余履约。先核清已发、已收、占用及结算，再确认新增单据会产生的事实，防止重复入库、出库和立账 |

导入逐批记录文件摘要、任务号、成功及失败行、生成草稿及过账单号。部分成功时只重传修正后的失败行，原成功行继续按已有草稿处理。过账前核对库存和财务余额仍未变化，过账后逐公司、逐仓、逐往来单位、逐账户核对期初。已过账库存期初按库存调整冲销。往来或资金期初发现差异时，暂停该公司开账，由财务复核并确认可用调整流程。[用户使用手册](用户使用手册.md) · [接口设计](接口设计.md)

## 三、停写、迁移和批准

1. 业务与运维确认切换窗口。旧系统停写后记录截止时间及最后一个已提交事务的水位，保存原始导出和附件。采用增量迁移时核对起止水位和补录记录，明确最后纳入的一笔事务。
2. 生成导入前的数据库及对象仓一致备份，记录摘要和恢复位置。在正式数据放量前验证独立目标可恢复，核对对象、Flyway 历史、业务数据以及幂等、任务和 Outbox 水位。[运维手册](运维手册.md)
3. 按已批准的主数据映射、期初批次和未完成订单清单执行迁移。保持新旧系统单一写入点，记录导入错误和处理结果。
4. 财务与仓库负责人核对旧系统截止清单和新系统期初结果，记录两边总数、差异、单据依据和批准时间。逐公司运行库存余额、成本、预留、资金、未清项、凭证平衡、库存账本及期间八类对账。对账差异须为零。期间关账预检查的阻挡单据按业务流程处理后复核。[数据库设计](数据库设计.md) · [用户使用手册](用户使用手册.md)

## 四、试运行与发布

- [ ] 按试运行清单验证采购收货付款、销售发货签收收款、应收应付核销、主要库存作业、报表、导入导出、附件和审计。样本单据在隔离环境执行，正式试运行按批准范围承接真实业务。记录单号、操作角色、库存数量和成本、账户余额及未清项预期值与实测值，复核失败任务和未处理差异。
- [ ] 业务、财务和运维确认试运行结果、期初门槛、剩余问题、回退窗口和联系人。首笔正式业务一经提交即记录水位，并按第五节处理后续回退。核对放量使用的产物摘要与已验收候选包一致。全面放量经批准后记录监控状态和发布时刻，更新版本日志并归档源码版本、交付包摘要与批准记录。[开发计划](开发计划.md)

## 五、回退边界

| 状态 | 处理 |
| --- | --- |
| 新系统尚未产生首笔正式业务事务 | 停止新系统流量及后台写入，保留迁移日志和已过账期初证据。核对旧系统停写水位、对象及任务状态，再确认从该水位恢复旧系统写入 |
| 新系统已经产生正式业务事务 | 立即暂停新写入并标记最后一笔已提交事务。保全新增单据、资金库存事实、对象和幂等/任务记录，逐笔对账并确定可兼容的应用版本、补录、冲销或数据回迁方案。按已批准的方案复核水位后再切换写入点 |

恢复入口前由运维核对数据、对象及队列，财务复核资金、库存及未清项。请求结果不明时查询原幂等键，差异按业务单据修正。保留切换前后水位、批准记录和复核证据。[运维手册](运维手册.md) · [重构设计方案](重构设计方案.md)
