# M11 工作流使用说明

> 目标1.3.0，当前为未发布功能。适用于已执行V44—V46的环境。维护：maorongkang@gmail.com。

## 配置前准备

在“公司与参数”中确认经办复核分离和最低售价策略，在“部门与岗位”维护主部门、负责人及岗位成员。流程选人只筛选现有权限，不给用户增加公司、仓库、部门或单据审核权。配置人员需要全组织管理范围及细分模型/绑定权限；普通用户可进入个人审批中心，仍只能看到来源有权的数据。

## 设计、发布和绑定

1. 打开“审批中心 → 流程模型与绑定”，新建模型，填写编码、名称、业务类型和公司范围。企业共享模型的公司编号为0；公司内模型只能绑定当前公司。
2. 点击画布节点配置。可按用户、角色、岗位、部门负责人、连续多级上级、发起人或单据人员字段选人，也可让发起人提交时自选。连续多级上级固定依次审批。候选仍须拥有来源查看、审核及必要的价格审批权限。
3. 使用“添加下一个环节”增加审批、办理、抄送、条件或并行分支。条件按显示顺序匹配，保留一条默认分支；并行所有分支汇合。每条路径至少一次人工审批，人工审批不能配置“无审批人跳过”或“超时自动同意”。
4. 保存草稿，再发布新版本。发布后可在历史中只读查看该版本。编辑和发布新版本都不改变在途实例。停用模型会阻止匹配到它的新申请；如要恢复原单级审批，应停用对应绑定。
5. 新增单据绑定，选择模型、公司和优先级，可设置匹配条件。同范围优先级不能重复；当前公司优先于企业共享，从高到低匹配第一个满足条件的绑定。没有匹配流程的单据继续使用原单级审批。

示例：销售订单先部门经理审核，后添加条件分支，条件为“单据金额 > 50000”；大额分支增加财务角色会签，默认分支直接汇合。设置财务节点超时24小时提醒、每12小时重复。50000整走默认分支，50000.01走财务分支。先在测试企业验证每个角色的真实权限和选人结果，再启用业务绑定。

## 发起和处理

销售订单、采购订单、退款申请、库存调整在原“提交”入口发起；冲销在创建时即发起。自选节点会在提交表单出现；冲销根据原单和日期预览后选择。没有有效候选时联系管理员调整权限或模型，不能随意填内部用户编号。

在“待我审批”左侧选择任务，右侧核对有权查看的摘要、明细和审批轨迹。底部可同意、驳回、转办，也可在“更多”中处理委派和加减签。办理任务时使用“完成办理”。会签要求所有人完成，或签任意一人完成，依次审批按顺序产生任务。委派人提交意见后，任务返回原处理人。转办后由新的处理人继续。

核对同一流程版本和环节的待办后，可勾选至少两项并批量同意。系统逐条处理并显示结果，仍受来源单据、审批资格和业务规则限制。带字段权限的表单需逐条核对。

前加签须先完成附加任务；后加签在原处理人同意后继续等待附加任务。仅能减少自己添加且未处理的加签，不能删除原人工复核环节。驳回到发起人会结束本轮，修改单据后重新提交；驳回到历史已经过节点会重新执行后续审批，旧同意不计入新一轮。

发起人可在运行中撤销，流程管理员可在授权范围内终止，均需原因并保留轨迹。“我的申请”“我的已办”“抄送我的”可查看进度；来源详情也显示处理人和意见。来源权限撤回后，旧待办和消息会从列表消失，直链接同样拒绝访问。

## 审核与过账

| 单据 | 流程期间 | 流程通过之后 |
| --- | --- | --- |
| 销售/采购订单 | 原待审核pending | 已批准，执行原审核事实 |
| 退款申请 | 原待复核pending_review，保留额度占用 | 待退款pending_payment，仍需原路退款登记 |
| 冲销 | 原待审核pending | 已批准，仍需执行冲销过账 |
| 库存调整 | 原待审核pending | 已批准，仍需库存过账 |

复核分离、两人经手、期间关闭及原单可用量等都继续由服务器执行。流程不能替代资金、库存过账，也不能绕过原单的下游依赖检查。撤销/驳回退款会释放本次占用；冲销驳回后保留原rejected记录。

## 最低售价

在商品规格中配置含税基本单位最低售价，0表示不控制。公司可选择：

- 提示：允许继续，在订单详情提示低价行。
- 需要价格审批：允许保存草稿，但提交时必须匹配带“人工最低售价审批”节点的流程，处理人还须有“审批低于最低售价”权限。没有匹配流程会阻止提交。
- 禁止：拒绝低于最低价的保存、提交和审批。

比较口径为折后整行含税金额与最低价乘基本数量，包含单位换算和折扣。价格证据会绑定当时的行、数量、金额、最低价及公司策略；之后修改最低价、策略或撤回审批权，不能复用旧证据。已批准订单通过原变更入口转为需要新的低价审批时，会要求按新订单重新审批，本期没有接入订单变更流程。

## 提醒和异常恢复

“系统设置 → 定时任务”可查看 `workflow.timeout` 和 `workflow.delay`。任务停用或 Worker 离线时，恢复后再检查积压。审批节点的超时动作可以配置提醒、驳回或终止。办理节点可自动完成，人工复核仍须满足服务端资格和权限校验。

某个任务或延迟节点执行失败后，其他到期项会在同一轮继续处理。连续失败按 5、15、60 分钟退避，第三次起纳入预警中心的“任务执行失败”规则。拥有“查看全部流程”权限的用户可在授权流程中看到“自动处理失败”，并按现有权限处理当前任务或终止流程。修正人员资格或配置后，可等待下次重试。

站内信、铃铛和工作台共用消息中心，WebSocket只推送摘要，页面通过REST重新读取有权数据。当前处理人变更、公司切换或权限撤回时重新校验。短信、邮件和企业微信沿用消息订阅与受控渠道配置，本机演练使用模拟渠道。

遇到“版本变化”，关闭操作窗口刷新后核对；遇到网络超时或请求处理中，保留窗口并使用原请求重试，不修改内容重复发起。已发布版本不可覆盖，配置错误应保存新草稿再发布。不得直接修改ACT_*、wf_*或原单状态处理故障，须保留请求号及审计后通过合法命令恢复。
