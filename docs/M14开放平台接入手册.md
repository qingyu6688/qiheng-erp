# M14 开放平台接入手册

开放平台面向已登记的系统集成。应用使用签名和明确授权的公司、权限码，和 ERP 的网页登录各自认证。通过开放接口创建或提交单据后，由有权 ERP 用户完成审批、确认和过账。

## 创建应用

1. 以具有开放平台管理权限的账号进入「系统管理 → 开放平台」。
2. 创建应用并选择可访问的公司和业务权限。管理员必须拥有每家公司的完整仓库、部门范围以及所授权的业务权限。建议每个外部系统使用独立应用。
3. 填写每分钟调用上限、到期时间和 IPv4、IPv6 或 CIDR 白名单。空白名单不限制调用来源。
4. 保存后立即复制显示的 App Key 和应用密钥。重置密钥后原密钥立即失效。调用日志只保存应用、方法、路由模板、状态、耗时和请求标识，保留 90 天。

部署通过 `ERP_OPEN_SETTINGS_KEY` 提供独立的 32 字节随机主密钥，使用标准 Base64 编码。缺省时从 `ERP_LOGIN_SETTINGS_KEY` 派生独立用途密钥。生产入口使用 HTTPS，反向代理覆盖真实来源 IP 请求头，API 服务仅在受信内网监听。

## 签名

| 请求头 | 内容 |
| --- | --- |
| `X-App-Key` | 创建应用得到的 App Key |
| `X-Timestamp` | Unix 时间戳的秒数字符串，允许前后各 300 秒 |
| `X-Nonce` | 本次请求独立生成的 32 位字母数字串 |
| `X-Company-Id` | 应用授权的公司 ID，使用十进制字符串 |
| `X-Signature` | 规范串的 HMAC-SHA256 摘要，以标准 Base64 编码，保留 `=` 补位 |
| `Idempotency-Key` | POST 必填，1 到 64 位字母、数字、短横线或下划线。GET 省略 |

签名密钥使用拿到的密钥字符串的 UTF-8 字节。按下列顺序用 LF 拼接八项，末尾无换行。JSON 按签名前生成的原始字节发送。

```text
METHOD
PATH
QUERY
TIMESTAMP
NONCE
COMPANY_ID
IDEMPOTENCY_KEY
LOWERCASE_HEX_SHA256_OF_BODY
```

PATH 使用请求的原始路径，例如 `/open/v1/sales-orders`。QUERY 按参数名按字典顺序排序，先按 UTF-8 解码，再按 RFC 3986 编码。其中空格为 `%20`，百分号十六进制大写，不重复使用同名参数。空查询、GET 的幂等键使用空字符串。GET 的正文使用零字节。

网络超时后，使用相同幂等键和相同正文生成新时间戳和随机串再签名。重用已接受的随机串返回 `401 OPEN_REPLAY`。同一应用的限流使用 Redis 滑动窗口，超过额度返回 `429 OPEN_RATE_LIMIT` 和 `Retry-After` 秒数。

### Java 21

```java
import java.net.URLEncoder;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.Base64;
import java.util.HexFormat;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Collectors;
import javax.crypto.Mac;
import javax.crypto.spec.SecretKeySpec;

class OpenSignature {
    static final java.nio.charset.Charset UTF8 = StandardCharsets.UTF_8;

    static String encode(String value) {
        return URLEncoder.encode(value, UTF8).replace("+", "%20").replace("*", "%2A").replace("%7E", "~");
    }

    static String sign(String method, String path, Map<String, String> query, String timestamp,
            String nonce, String company, String idempotencyKey, byte[] body, String applicationSecret) throws Exception {
        String sortedQuery = new TreeMap<>(query).entrySet().stream()
                .map(e -> encode(e.getKey()) + "=" + encode(e.getValue())).collect(Collectors.joining("&"));
        String digest = HexFormat.of().formatHex(MessageDigest.getInstance("SHA-256").digest(body));
        String canonical = String.join("\n", method, path, sortedQuery, timestamp, nonce, company, idempotencyKey, digest);
        var mac = Mac.getInstance("HmacSHA256");
        mac.init(new SecretKeySpec(applicationSecret.getBytes(UTF8), "HmacSHA256"));
        return Base64.getEncoder().encodeToString(mac.doFinal(canonical.getBytes(UTF8)));
    }
}
```

### Python

```python
import base64
import hashlib
import hmac
from urllib.parse import quote

def sign(method, path, query, timestamp, nonce, company, idempotency_key, body, application_secret):
    sorted_query = "&".join(
        f"{quote(name, safe='')}={quote(query[name], safe='')}" for name in sorted(query)
    )
    canonical = "\n".join((
        method, path, sorted_query, timestamp, nonce, company, idempotency_key,
        hashlib.sha256(body).hexdigest(),
    )).encode("utf-8")
    digest = hmac.new(application_secret.encode("utf-8"), canonical, hashlib.sha256).digest()
    return base64.b64encode(digest).decode("ascii")
```

### Node.js

```javascript
import { createHash, createHmac } from 'node:crypto'

const encode = (value) => encodeURIComponent(value).replace(/[!'()*]/g, (symbol) =>
  '%' + symbol.charCodeAt(0).toString(16).toUpperCase()
)

export function sign(method, path, query, timestamp, nonce, company, idempotencyKey, body, applicationSecret) {
  const sortedQuery = Object.keys(query).sort().map((key) => encode(key) + '=' + encode(query[key])).join('&')
  const bodyDigest = createHash('sha256').update(body).digest('hex')
  const canonical = [method, path, sortedQuery, timestamp, nonce, company, idempotencyKey, bodyDigest].join('\n')
  return createHmac('sha256', Buffer.from(applicationSecret, 'utf8')).update(canonical, 'utf8').digest('base64')
}
```

## 业务接口

路径前缀为 `/open/v1`。分页接口返回 `items` 和 `nextCursor`。单据和主数据 ID 按字符串传输，数量和金额按十进制字符串传输。具有 `open_platform:view` 且拥有公司完整范围的用户可从管理页面下载 `open` 分组的 OpenAPI JSON。生产入口通过 `GET /api/v1/open-platform/spec` 提供授权下载，原始 Springdoc 路径由反向代理拦截。

| 路径 | 请求方式 | 权限 |
| --- | --- | --- |
| `/skus`、`/skus/{id}` | GET | `sku:view` |
| `/skus` | POST | `sku:create` |
| `/partners`、`/partners/{id}` | GET | `partner:view` |
| `/partners` | POST | `partner:create` |
| `/warehouses` | GET | `warehouse:view` |
| `/inventory-balances` | GET | `inventory:view` |
| `/sales-orders`、`/sales-orders/{id}` | GET | `sales_order:view` |
| `/sales-orders` | POST | `sales_order:create` |
| `/sales-orders/{id}/submit`、`/sales-orders/{id}/cancel` | POST | `sales_order:submit`、`sales_order:cancel` |
| `/purchase-orders`、`/purchase-orders/{id}` | GET | `purchase_order:view` |
| `/purchase-orders` | POST | `purchase_order:create` |

创建销售订单的正文示例。提交时使用创建返回的 `version`。

```json
{
  "customerId": "123",
  "businessDate": "2026-11-17",
  "priceTaxInclusive": true,
  "lines": [
    {"skuId": "456", "warehouseId": "789", "unitId": "100", "qty": "2"}
  ]

```

销售订单、销售订单行、采购订单、SKU 和往来单位的建档接口支持 `extJson`。填入企业已配置的字段键和值，按 ERP 自定义字段规则校验。SKU 和往来单位可按已启用的编码规则自动取号。

## Webhook

运维先在 `ERP_OPEN_WEBHOOK_HOSTS` 登记接收方域名（逗号分隔，非 443 端口须写 `域名:端口`）。后台保存 HTTPS URL。发送时验证接收地址为公网地址并使用原域名校验 TLS 证书。可先用「测试推送」验证接收端签名。

| 事件 | 所需应用权限 | 业务含义 |
| --- | --- | --- |
| `sales.order.approved` | `sales_order:view` | 销售订单审核通过 |
| `sales.shipment.posted`、`sales.shipment.signed` | `shipment:view` | 发货过账或签收 |
| `purchase.receipt.posted` | `goods_receipt:view` | 收货过账 |
| `finance.receipt.confirmed` | `receipt:view` | 收款确认 |
| `inventory.balance.changed` | `inventory:view` | 公司内 SKU 库存变动，每分钟聚合一次 |
| `workflow.trigger` | `workflow_instance:view_all` | 已发布模型触发的受控事件 |

接收端用请求头 `X-Erp-Timestamp` 的秒数字符串、一个点和原始正文拼接，在 Webhook 密钥下计算 HMAC-SHA256。将标准 Base64 签名与 `X-Erp-Signature` 做恒定时间比较。验证时间范围，并按 `X-Erp-Event-Id` 去重。业务事件正文包含 `eventId`、`eventType`、`companyId` 和最小业务数据 `data`。签名密钥是创建或重置订阅时显示的独立密钥。

HTTP 2xx 表示处理成功。其他状态和连接失败分别在 1 分钟、5 分钟、30 分钟、2 小时、12 小时后重试，共 5 次自动重试。接收端应先持久记录事件再返回 2xx。重试沿用原事件 ID。连续 50 次业务投递失败会停用订阅并通知具备权限的管理员。排查后重新启用订阅，再在「推送记录」重推失败条目。停用、应用过期、撤掉公司或事件权限后，历史待投递记录遵循新权限。
