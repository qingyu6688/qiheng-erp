# ERP 用户使用手册

- 适用版本：0.5.0，销售、采购、付款与期初；M5 最终测试进度见《测试报告》。
- 运行环境：本机 JDK 21、MySQL 8.0.46；启动见《部署说明》。
- 文档维护：maorongkang@gmail.com。

## 登录与准备

本机开发环境打开 http://127.0.0.1:5173，登录页预填企业编码 `DEMO` 和用户名 `admin`。开发默认口令从本机私有配置注入；生产页面不预填。先选择业务公司，切换公司后页面重新取数。

销售前，准备客户角色、商品 SKU、单位换算、公司仓库、结算账户、有效库存和业务日期所在的开放期间。管理员在角色中分别授予订单、发货签收、收款、退货退款、核销、开票权限；成本查看另需 `cost:view`，修改税率另需 `document:change_tax_rate`。

订单审批和收款确认默认要求另一名人员操作，可在公司参数中设置。退款审核始终要求审核人与申请人不同。按钮按当前状态和权限出现；有权限的人员仍须满足库存、余额、额度与期间规则。

## 下单与审批

1. 进入“销售订单”，新建并选择客户、业务日期、商品、仓库、单位、数量和优惠。含税口径默认取客户设置，单价留空时服务端按所选单位换算参考价。更换件、箱等单位后重新使用单位参考价，也可明确填写单价。
2. 页面实时展示服务端试算的商品金额、行优惠、税额和合计。草稿允许暂不指定仓库，审批前每行必须有仓库。
3. 保存后提交。当前库存不足时仍可提交，页面给出提示；待审核需求不占用库存。
4. 复核人员审批。任一行库存不足时整单失败，已尝试的预留一起回滚；成功后生成有效预留。
5. 详情查看履约、结算、售后进度和预留记录。有效期取审批后默认 30 天与交货日后默认 7 天中的较晚日期，参数可由公司设置。

待审核可撤回或驳回到草稿。已批准且无下游发货单时可撤销审批，释放预留后回到草稿。预留到期会释放库存，订单仍保留为已批准，可根据当时库存重新预留。

库存页面展示在库、预留、冻结、可用和待审核需求。可用量等于在库减预留减冻结；待审核需求帮助判断潜在竞争，不参与可用量计算。

## 关闭、取消与变更

关闭剩余数量必须填写原因，数量使用基础单位，不能超过尚未发货及待发占用后的剩余量。关闭释放对应预留，关闭数量不能恢复。

没有已发和待发数量的已批准订单可以取消，取消释放预留。关联的已确认收款仍保留为客户资金，退回款项需要单独走退款申请。

已批准订单从“提交变更”修改。减少数量、改仓库、改交期或备注可直接生效；增加数量、加行、改价格税率或优惠需重新审批，批准前原版本继续有效，不能新建该订单的发货单。变更不能更换客户、公司或含税口径，不能改已发货行的价格，数量不能低于已发、待发及已关闭部分。待发占用的行改仓前先作废对应待发货单。新仓库存不足会回滚原仓释放和整次变更。

## 发货、签收与差异

新建发货单选择同一客户、同一仓库的订单行，可合并多张订单。保存草稿不占用数量，提交后占用可发量。已提交可作废，作废释放占用。

过账减少在库与预留，成本转到“发出商品”，此时不产生销售应收。客户实际签收后登记签收日期和每一行签收量，数量可以为零但不能超过发出量。签收日期不早于发货、不晚于今天，且所在期间必须开放。

签收按原订单价格、优惠与税率快照确认应收、税额和销售成本；买方费用第一次签收时整笔确认。已经确认的关联订单预收按规则自动核销。客户自提在过账时同时全数签收。

少签的数量在签收时恢复订单可发量。差异分别处理为“拒收退回”或“运输损失”：退回按原出库成本入原仓冻结待检，损失从发出商品结转。处理差异不改变已确认应收，原预留不自动恢复。补发需要当时有足够可用库存。“仅签收超期”筛选发货超过默认 7 天仍未签收的记录。

## 收款与核销

收款登记填写客户、结算账户、金额和业务日期，可关联订单。保存、提交均未增加账户余额；复核人员确认到账后才形成资金与客户未清项。关联订单的预收可在签收时自动核销，未关联或未分配部分留待手工核销。

核销工作台选择同一客户、同一币种的借方应收和贷方收款或退货信用额，填写金额后保存。不能超过双方剩余额度。撤销核销填写原因，恢复双方额度并保留历史记录。

## 销售退货与退款

退货必须选择原已签收发货行、退回仓库、单位、数量和质检结果。提交占用可退量，作废释放占用，过账确认退货信用额并按原成本入库。质检“待检”或“不合格”进入冻结量，“合格”进入可用库存。

退款选择客户、原收款、付出账户、金额与原因，可指定退货信用额等贷方未清项。提交同时占用客户可退余额和原收款可退额度；审核人复核后进入待退款。财务实际退款后填写支付日期和银行流水号，登记已退款才扣减账户余额。驳回回到草稿释放额度，待退款可取消释放额度。账户余额不足、原收款额度不足或重复占用均无法登记成功。

当前退款为财务手工登记，不直接向银行或支付渠道发起转账。

## 开票登记

开票选择已确认的正向销售应收，录入发票号、日期、金额、税额及各应收分配金额。分配合计须等于发票金额，各笔累计开票金额不能超过原应收。可分次开票，也可将一张发票关联多笔同客户应收。

开票只记录关联关系、累计开票额与税额分差，不再产生应收、收入或收款。作废登记释放开票额度。税务系统税额与单据逐行税额有分币差异时只记录差额，不回改原业务金额。系统当前不接税控开票。

## 超时与版本冲突

页面显示“结果确认中”时，点击“查询结果”。查询使用最初的请求标识，成功后刷新单据；确认尚无已提交结果时可用原请求重试，避免重复业务效果。变更审批也保留自己的原请求标识和变更版本。

提示版本冲突表示其他人已经修改单据，关闭并刷新后核对新内容。资料停用、期间关闭、库存或资金额度不足时，按提示处理原因后重新发起操作。采购、付款、期初、调拨、盘点、冲销和期间命令同样使用原请求恢复；实盘数量录入属于带版本的修改，超时先关闭刷新核对。税控开票和附件管理仍按后续里程碑实施。

## 期初录入

开始正式业务前，先开启业务日期所属期间。管理员分别授予库存期初、往来与资金期初的创建、修改、审核、过账权限。所有期初单必须由制单人以外的人员审核，审核后再过账；保存和审核本身不改变库存、往来或账户余额。

在“库存调整”新建库存调整单，调整类型选择“期初”，再填写仓库、日期、原因、商品、单位、数量和整行总成本。同一商品在一张单中只录一行，可使用件、箱等有效换算单位；换算到基础单位超过允许精度时会报错，请修正数量或换算，不会自动截断。提交后由另一人审核，过账才增加库存和成本。原库存期初入口自 0.6.0 起整合到该页面。

“往来与资金期初”选择类型和借贷方向，金额填写正数：

| 类型与方向 | 含义 | 必填对象 |
|---|---|---|
| 资金期初，借方 D | 银行或现金账户的现有余额 | 结算账户 |
| 客户往来，借方 D | 客户尚欠我方的金额 | 客户 |
| 客户往来，贷方 C | 已收客户预收款或客户信用余额 | 客户 |
| 供应商往来，贷方 C | 我方尚欠供应商的金额 | 供应商 |
| 供应商往来，借方 D | 已付供应商预付款或供应商信用余额 | 供应商 |

往来期初保存后直接交另一人审核，再过账。客户和供应商期初进入各自未清项，可在对应核销工作台分配；资金期初只增加所选账户余额。已过账期初不能直接修改或作废，正式录入前先核对日期、数量、总成本及余额。

## 请购与采购订单

1. 在“请购管理”新建请购单，填写日期、商品、单位、数量和需求日期。申请人由系统记录为当前用户。提交后由有权限的复核人员批准。
2. 在“采购订单”选择供应商、日期和明细。请购来源可选；选择已批准请购行时保留其商品与录入单位，可用数量提示使用基础单位。采购草稿保存即占用请购可转数量，其他采购单只能使用剩余量；修改、删除草稿或取消会释放相应数量。
3. 填写收货仓库、数量、单价、行优惠、整单优惠和费用。金额与税额由服务端试算；单价留空可使用有权查看的采购参考价，修改单位后重新取对应单位价格。审批前每行必须指定收货仓库。
4. 提交后由复核人员批准。公司超收容差此时冻结到订单上，例如 10 件、5% 容差可收 10.5 件；以后修改公司参数不会扩大这张订单的上限。采购审批不预留或增加库存。

详情显示每行“可收上限 / 已收”的基础数量，收货选行时提示剩余可收量，关闭时提示可关闭量。待审核可撤回或驳回。无下游收货时可撤销审批；已有待收或已收数量时不能取消。取消采购订单不会撤回已经确认的预付款，财务应单独核销或登记供应商退款。

关闭剩余填写原因和基础单位数量，不能超过服务端显示的可关闭量，关闭后不能恢复。已批准订单从“提交变更”修改，增加数量、加行、改价、税率、优惠或费用需要重新审批；批准前原有效版本保留。已收或待收的行不能修改商品、单位、价格、税率或改变分摊后的单位净额；待收行调整这些内容或仓库前，先作废对应收货单。关闭请购后不能再建立新的转单关联，已有采购草稿可以保留或减少原关联量。

## 采购收货与退货

“采购收货”选择同一供应商、同一仓库的可收采购行，可合并多张订单。按来源提示的单位填写数量，系统换算后校验基础单位上限。保存草稿不占数量，提交占用可收量，作废释放；过账才入库、确认应付、税额与移动加权成本。不能靠前端修改金额改变原采购快照。

收货成本按本次过账时的公司纳税人身份处理，系统保存含税成本口径，后改公司参数不重算原收货。关联订单的已确认预付会在本次应付确认时自动核销，未分配部分保留。历史日期补录仍按实际过账顺序更新成本，不回改已过账出库成本。

收货草稿保存后，如果采购变更修改了来源商品或单位换算快照，提交会提示来源变化。重新编辑草稿并核对来源后再提交，失败提交不会占用可收量。

“采购退货”选择同一供应商、同一仓库的原已过账收货行，按来源提示的单位填写数量和原因。提交占用原收货可退量，作废释放；过账扣库存，按原收货金额、税额、成本及税身份快照生成应付信用额，累计分批处理分币尾差。当前库存不足时不能过账；移动加权成本与原退货成本的差额由系统记录，不能手工调整退货单价。退货信用额可核销欠款，或与供应商实际退款核销。

## 付款、供应商退款与应付核销

“付款登记”选择供应商付款或其他支出。供应商付款选择供应商、付出账户、金额和日期，可关联同一供应商的采购订单作为预付；其他支出改选有效支出项目。保存和提交不扣账户余额，确认付款才扣资金并记账；默认由另一位人员确认，账户余额不足会整单失败。

订单关联预付在后续收货确认应付时自动核销；后付、未关联或未分配金额在核销工作台切换“供应商应付”后手工分配。选择同一供应商的借方付款或退货信用额，与贷方应付或供应商退款，金额不能超过双方剩余额度。撤销核销填写原因，恢复额度并保留记录。即使同一单位同时是客户与供应商，应收与应付也不能相互核销。

供应商实际退款到账后，进入“收款登记”选择“供应商退款”，填写供应商、收款账户、金额、日期和银行流水号，提交后确认到账。确认才增加资金，并生成可与采购退货信用额核销的应付贷方未清项。付款和退款均是财务手工登记实际结果，系统不直接向银行发出指令。

## 账户转账

“账户转账”选择不同的转出、转入账户，填写本金、手续费及日期。提交后由复核人员确认，转出账户扣本金加手续费，转入账户只增加本金；手续费单独记入转账手续费。转出余额不足会整体失败，不会只增加一边余额。确认前可退回草稿修改，确认后不能重复执行；转账只登记实际发生的资金划转。

## 库存调整

“库存调整”统一处理六种业务，调整类型在创建后不能修改。填写原因、仓库、日期和商品单位数量，提交后由另一名操作人审核，再过账。草稿、待审核和已批准状态均不改变库存；驳回后按原因修改，未过账可作废。

| 类型 | 过账结果 | 成本录入 |
|---|---|---|
| 期初 | 增加期初库存，记期初权益 | 填整行总成本，可为 0 |
| 其他入库 | 增加库存，记库存调整 | 填整行总成本，可为 0 |
| 其他出库 | 减少可用库存 | 按当时移动加权成本计算 |
| 冻结 | 增加冻结量、减少可用量，在库总数不变 | 不填写成本 |
| 解冻 | 减少冻结量、恢复可用量，在库总数不变 | 不填写成本 |
| 报废 | 减少已经冻结的在库量与成本 | 按当时移动加权成本计算 |

出库不能占用其他订单的预留或冻结量；解冻不能超过当前冻结量，报废从冻结量扣减。数量或余额不足时整单失败，不会只过账部分明细。已过账调整不能直接编辑或作废，需要更正时按“单据冲销”处理。

## 库存调拨

1. 在“库存调拨”新建调拨单，选择同一公司的不同调出、调入仓库，填写业务日期、商品、录入单位和数量。操作人须同时具有两仓的数据范围。
2. 提交后点击“确认调出”，核对本次业务日期。调出扣减来源仓可用库存并形成在途，目标仓尚未增加库存；已调出不能作废。
3. 到货后点击“登记调入”，逐行填写本次实收的**基础数量**。分批到货时取消“本次为最后一批，未收部分转为差异待处理”，剩余部分继续在途；需要一次收完时可用“全部调入”。
4. 最后一批勾选上述选项，未收到的部分转入“调入差异待处理”。可以实收填 0，表示该行全部少收。再点击“处理调拨差异”，选择“退回调出仓”或“确认运输损失”，填写原因；每行一次处理该行全部待处理差异。

本次业务日期不能早于原单或已有调拨记录，且必须属于开放期间。调入和差异都沿用原调出成本，最后一笔包含剩余分币。系统重启后从原单继续处理在途，不要重新创建一张调拨单。只有实际调入的货物才成为目标仓库存。

## 库存盘点

本期采用流水水位方式，盘点期间允许继续收发货。在“库存盘点”选择仓库、业务日期和要盘点的商品，保存后点击“开始盘点”。系统记录开始时点的账面数量和水位；“录入实盘”须完整填写每行的基础单位数量，允许填 0。

实盘数应对应**开始盘点的快照时点**。若实物清点发生在随后时点，应先依据中间收发货还原该快照时点数量，再录入。系统过账只把“实盘数减快照账面数”的差额加到当前库存，期间发生的出入库会保留，不会把当前余额直接覆盖成实盘数。

实录完成后提交，由另一名操作人审批后过账；驳回会回到盘点中，核对后可重新完整录入。盘盈优先使用过账时移动加权成本或历史入库价；从未入库且没有历史价格的商品，须由有相应操作权限的人员填写盘盈单价后提交审核。盘亏按过账时移动加权成本计算，可用库存不足时失败，先处理占用或核对差异原因。

## 单据冲销

“单据冲销”用于更正录入错误，当前支持发货、销售退货、采购收货、采购退货、收款、付款、账户转账和库存调整八类来源。申请人既要有冲销权限，也要能查看原单及其公司、仓库范围。选择原单类型后按单号查找原单，填写开放期间内的冲销日期和原因；审核人必须与申请人不同，批准后再过账。

有下游退货、有效核销、退款占用或开票登记时，系统列出依赖并拒绝申请或过账。先处理相应下游：撤销可撤的业务核销、作废开票登记、处理或冲销下游业务，再回到原单申请。冲销前还会重新检查依赖和当前库存、资金，不能凭审批绕过余额限制。

冲销保留原单、原流水、原往来及凭证，再写入反向记录，原单标为已冲销；不会删除历史。发货冲销会回退订单履约进度，但不会恢复已消费的预留，继续发货前先重新预留。由冲销自动生成的抵销核销不能单独撤销。已关闭原期间的单据应选择当前开放期间冲销，原关闭期间不回改；原履约费用撤回后，新履约单可按规则重新确认费用。已冲销的原应收及冲销抵销应收不能开票，也不会出现在开票来源候选中。

## 关闭与重新打开会计期间

在“会计期间”按行点击“关账预检查”，检查未过账单据、待确认资金、库存对账、资金往来对账和成本尾差五项。任意一项未通过均不能关账；阻挡单据会返回具体单号明细，每类最多 50 条，处理相关单据或差异后重新检查。调拨在途、盘点待处理、已审核未过账调整和冲销等，也要先处理完成。

所有五项通过后点击“关账”并确认。系统会先同步待汇总凭证，再取得期间屏障复核最新事实，检查通过才关闭；并发产生新凭证时可能提示重新执行，刷新核对后使用原请求结果恢复流程。相关单据提交、期初及退款审核也要验证原业务期间，不能在关闭完成后继续提交到旧期间。

关账及重新打开要求相应权限和**整家公司数据范围**，只有单仓范围时不能执行。期间须按时间顺序关闭；需要补录时，仅能“重新打开”最近一个已关闭期间，并填写原因。关闭、重开及操作人均保留审计记录。
