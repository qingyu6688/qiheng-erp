# M14 平台二期使用与验收

本轮对应 1.6.0 候选的 E-04、E-05、E-06、E-08 和工作流二期。主库使用 MySQL 8.0.46，新增 Flyway 迁移覆盖登录身份、流程表单、开放平台、编码规则和自定义字段。回归在 Windows、JDK 21、独立 MySQL 测试库和独立 Redis 中执行。

## 企业登录和安全策略

从「系统管理 → 登录方式设置 → 企业单点登录」配置 OIDC、LDAP / AD、企业微信、钉钉或飞书。系统沿用本地用户、角色、公司、仓库和部门授权。管理员可以在企业安全策略中绑定外部身份、设置按角色强制 MFA、重置其他用户的 MFA。员工在账户安全页绑定验证器，生成的一次性恢复码需自行保管。第一因素通过后，完成 TOTP 或恢复码验证才建立完整会话。

提供方参数、回调和本机覆盖见 [M14 单点登录与 MFA 使用说明](M14单点登录与MFA使用说明.md)。正式接入须使用该企业的真实 IdP、目录和扫码应用做端到端验证。

## 自定义字段

在「自定义字段」选择销售订单、销售订单行、采购订单、SKU 或往来单位创建字段。字段以 `cf_` 开头，每种对象最多 30 项，最多 5 项启用精确筛选。支持文本、多行文本、整数、小数、日期、时间、单选、多选、用户、部门和布尔值。单选和多选可使用自定义选项或启用的字典。列表显示、打印、导入导出按字段配置控制。

字段配置按排序号展示。多行和多选适用于录入和展示。启用索引的字段用精确值过滤。

新建或编辑资料时在「其他信息」录入。订单筛选随列表查询应用，打印取 `print_visible`，CSV 导出当前页取 `import_export`。SKU 和往来单位的现有 CSV 模板自动附带可导入字段，允许旧模板继续提交，由服务端应用默认和必填规则。字段停用后保留历史值。字段只记录附加信息，过账、金额和状态校验继续由各业务服务处理。

| 方法与路径 | 作用 |
| --- | --- |
| `GET /api/v1/custom-fields/{entity}` | 按对象查看权限读取有效字段配置 |
| `GET/PUT /api/v1/sys/custom-fields/{entity}` | 列出并更新定义，权限 `custom_field:manage` |
| 单据与资料原接口中的 `extJson` | 读写扩展值，现有对象范围与版本控制继续生效 |
| `GET /api/v1/document-browser/{kind}` | 用 `cf.cf_project=值` 筛选已启用索引的字段 |
| `GET /api/v1/document-browser/{kind}/custom-fields.csv` | 以当前筛选和分页导出购销订单字段 |

## 编码规则

在「编码规则」选择业务类型、范围和流水重置周期，配置固定字符、公司、部门、物料分类、日期和流水段。可拖动调整段顺序并预览下一号。流水段必须唯一，按月或日重置需日期段包含对应粒度。单据最长 33 位，主数据最长 32 位。

单据优先读取本公司启用的规则，然后读取企业通用规则。没有匹配规则时沿用老编号。企业共享的 SKU 和往来单位使用企业级流水，允许留空自动生成编码。SKU 支持物料分类段。新单号与旧单号一起受原数据库唯一约束保护，已有编号保留。预览不占号，取号在独立短事务中完成。

管理接口为 `GET/PUT /api/v1/sys/code-rules`、`POST /api/v1/sys/code-rules/preview`，需要 `code_rule:manage`。预览和管理只能使用当前公司或企业通用范围。

## 开放平台

为应用选择公司、业务权限、来源 IP、每分钟限额和到期时间。应用密钥和 Webhook 密钥仅在创建或更换时返回。外部业务请求使用签名，接收端校验推送签名。应用身份可以创建、提交有权处理的单据，审批、确认和过账由 ERP 中有权的人员进行。

外部接口的签名规范、Webhook 事件、重试和调用示例见 [M14 开放平台接入手册](M14开放平台接入手册.md)。

## 工作流二期

流程管理保留 SIMPLE 模型，BPMN 画布用于查看和定位节点，由属性编辑器维护受支持的流程拓扑。二期支持包容、优先路由、内嵌子流程、延迟和受控触发。表单版本发布后可绑定通用审批，发起和审批操作由后端分别验证字段可见和可写范围。服务端已有业务规则继续约束业务单据。

配置、字段权限及触发边界见 [M14 工作流二期使用说明](M14工作流二期使用说明.md)。2.0 行为变更单独公告。[2.0 不兼容变更预告](2.0不兼容变更预告.md)

## 回归命令

在仓库根目录执行以下命令。使用 `ERP_PROJECT_SETTINGS_FILE` 指向私有的本机配置文件，可对后端和浏览器选用同一套隔离环境。测试库名使用 `erp_test` 或 `erp_test_用途`，Redis 也需独立配置。

```powershell
pwsh -NoProfile -File ./scripts/project.ps1 verify
npm --prefix erp-web run lint
npm --prefix erp-web test
npm --prefix erp-web run build
pwsh -NoProfile -File ./scripts/project.ps1 e2e
```
