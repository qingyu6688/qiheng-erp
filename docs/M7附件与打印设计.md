## 文件对象仓

开发、测试和端到端验收环境允许使用本机私有文件仓，默认目录为当前用户目录下的 `.erp/private-objects`。可通过 `erp.storage.local-root` 指定专用目录；该目录不能配置为 Web 静态目录，也不能由 Nginx 直接公开。

生产环境必须配置共享的 S3 兼容对象仓。以下四项需要同时设置，不能部分填写：

| 环境变量 | 用途 |
| --- | --- |
| `STORAGE_ENDPOINT` | S3 兼容服务地址 |
| `STORAGE_BUCKET` | 已创建的私有存储桶 |
| `STORAGE_ACCESS_KEY` | 服务端访问标识 |
| `STORAGE_SECRET_KEY` | 服务端访问密钥 |

区域默认 `us-east-1`，需要时通过 `erp.storage.region` 配置。对象仓不创建公开访问策略，存储桶应保持私有。凭据仅通过环境变量传入，不填写到文档和版本记录中。

对象键由租户、公司和随机标识组成，不使用客户端文件名。公共 `ObjectFiles` 提供保存、读取和删除三个操作，权限由所属业务模块核对。导入与导出任务保存自己的附件元数据，通用附件接口拒绝 `import_job` 和 `export_job`，不能通过普通附件下载绕过任务的下载权限。

S3 适配采用 AWS SDK for Java 2.x 的同步客户端和路径式寻址。版本经 Maven Central 核对为 `2.59.1`，地址覆盖和寻址方式参见 [AWS 官方文档](https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/examples-s3.html)。

## 业务附件接口

| 方法与路径 | 请求与行为 |
| --- | --- |
| `POST /api/v1/attachments` | multipart 字段为 `ownerType`、`ownerId`、`file`，必须提供 `Idempotency-Key` |
| `GET /api/v1/attachments?ownerType=...&ownerId=...` | 返回单据当前有效附件数组 |
| `DELETE /api/v1/attachments/{id}` | 必须提供幂等键，标记删除并写入审计 |
| `GET /api/v1/attachments/{id}/download` | 核对当前权限和范围后，302 跳转至五分钟有效的内容链接 |
| `GET /api/v1/attachments/{id}/content?companyId=...&ticket=...` | 登录主体、公司、票据及所属单据权限全部重新校验后返回文件 |

附件元数据返回 `id`、`ownerType`、`ownerId`、`fileName`、`contentType`、`sizeBytes`、`sha256`、`status`、`createdBy`、`createdAt` 等字段，不返回对象键或凭据。列表和下载需要所属单据的查看权限；上传和删除还需要所属单据的修改权限。没有修改动作的开票登记和冲销单使用其创建权限。

单文件最多 20 MiB，每张单据最多保留 20 个有效附件。扩展名仅支持 PDF、JPG、JPEG、PNG、XLSX、CSV，并同时检查文件头、图片解码、工作簿 ZIP 结构或 UTF-8 文本内容。服务端忽略客户端声明的 Content-Type；文件名不能含路径或控制字符。

上传先校验所属单据和文件，再于数据库事务外写入随机候选对象。关联附件的短事务锁定所属单据，原子检查附件数量并写审计。幂等摘要包括所属单据、文件名、字节数和内容 SHA-256；同键不同内容返回 409。同键重放丢弃未被采用的候选对象，并重新校验当前单据范围。

对象写入前将候选键登记至 `object_cleanup`。关联成功时在同一数据库事务内移除登记；失败时立即删除候选对象。删除失败仍保留登记，由后台每分钟重试超过一小时的候选对象，避免进程退出后留下未关联对象。补偿任务先检查有效附件引用，不能误删仍在使用的文件。附件主动删除在同一事务中标记状态并登记待回收对象，后台延后清理物理文件，元数据和审计继续保留；已有下载票据立即因状态检查失效。

下载票据使用安全随机数，数据库仅保存 SHA-256 摘要。票据绑定租户、公司、用户、用途和附件，不会直接公开对象仓 URL。五分钟内重复下载仍重新检查账号、角色、单据存在状态和仓库范围；账号撤权、范围收窄或附件删除后，旧票据不能继续读取。

## 打印数据

`GET /api/v1/print-data/{documentType}/{id}` 同时要求该单据的 `print` 与 `view` 权限，并复用原详情查询的公司、仓库和字段遮蔽规则。响应结构为 `{documentType, company, document, printedAt}`。公司对象仅含名称、地址、电话；`document` 保持原详情接口结构，并补充制单、审核、确认和过账人员姓名，以及 `approvalRecords` 中的动作、版本、意见、操作人和时间。`sourceDocuments` 只返回当前有查看权限且处于可见范围的来源类型与业务单号，打印件不会把内部关联 ID 当作单据编号。读取打印数据会记录 `document.print` 审计。

支持 `sales_order`、`shipment`、`receipt`、`sales_return`、`refund_request`、`purchase_requisition`、`purchase_order`、`goods_receipt`、`purchase_return`、`payment`、`account_transfer`、`stock_adjustment`、`opening_entry`、`stock_count`、`stock_transfer`、`document_reversal`、`invoice_registration`。其中 `document_reversal` 使用 `reversal:print` 与 `reversal:view` 权限。

## 验证范围

`AttachmentFilesTest` 覆盖实际内容和扩展名、伪造 MIME、路径、空文件、尺寸限制；`ObjectFilesTest` 覆盖私有文件仓、目录逃逸、生产配置约束，以及真实本机 HTTP S3 协议端点的 SigV4 签名和存取删除。`DocumentsHttpIT` 使用既有 MySQL 期初夹具，覆盖 multipart 上传、幂等内容冲突、二十个附件并发上限、同键并发、票据过期和身份绑定、撤权、跨公司、仓库范围收窄、删除失效、成本打印遮蔽和对象补偿。运行结果由本阶段统一测试报告记录。
