# 柒衡 ERP 官网方案

- 方案版本：1.6.1
- 编写日期：2026-11-18，Asia/Shanghai
- 定位：开源产品官网，**只做前端页面**（纯静态，无后端），部署在 GitHub Pages；“在线演示”只预留跳转到演示 ERP 系统的入口
- 技术栈：Vue 3 + TypeScript + Vite + vite-ssg（与 `erp-web` 一致），工程在仓库根目录 `qiheng-website/`
- 实现：`qiheng-website/` 下的 Vue 工程（第 6.2 节）。原先的静态 HTML 设计稿已全部移植并删除；ERP 后台界面稿保留在 `design/mockups/`，只作截图来源。本文件放在 `qiheng-website/docs/`，以这一份为准
- 依据：`README.md`、《用户使用手册》《部署说明》《UI 设计规范》2.0.0、`v2.0.0-rc.1` 发布页
- 文档维护：maorongkang@gmail.com

## 1. 目标与受众

### 1.1 目标

1. 让第一次接触柒衡 ERP 的人在 30 秒内知道：它是什么、适合谁、和其他开源 ERP 有什么不同。
2. 让想试用的人一步进入演示系统，或在 10 分钟内找到下载和部署说明。
3. 让开发者找到技术栈、架构、设计文档和代码仓库。

### 1.2 受众

| 受众 | 关心什么 | 官网给什么 |
|---|---|---|
| 商贸、批发、轻制造企业的老板和财务 | 能不能管住库存和账、好不好上手 | 业务闭环、对账能力、界面截图、在线演示 |
| 企业 IT / 实施人员 | 部署难度、资源需求、安全、能否对接 | 部署方式、资源表、安全能力、开放平台 |
| 开发者 | 技术栈、代码质量、二次开发、许可证 | 架构、测试与 CI、设计文档、AGPL 说明 |

### 1.3 范围边界

- **只做前端页面**：不做注册、登录、留言表单、付费和客服；需要用户反馈的地方一律链接到 GitHub Issues。
- **演示系统不在本项目范围**：官网只提供跳转入口（第 5 节），演示 ERP 的部署、演示数据和定时重置另行安排。
- 不承诺未实现的功能、商业服务或授权方式；能力描述以 README 和《用户使用手册》为准。
- 不放客户案例、用户数、评价等无法核实的内容。

## 2. 视觉方向：参考大厂产品官网

参考飞书、阿里云、腾讯云等产品官网的通用做法，结合 ERP 的业务属性：

| 做法 | 柒衡官网的落地 |
|---|---|
| 首屏一句话价值 + 两个主按钮 + 大幅产品截图 | 标题“采购、仓库、销售、财务，记在同一本账上”；按钮“在线演示”“快速开始”；下方是带浏览器外框的工作台截图 |
| 按场景讲价值，不按功能列表讲 | “适合谁”三张场景卡：商贸批发、多仓分销、轻制造 |
| 功能用页签 + 大截图展示 | “界面一览”页签切换工作台、订单、详情、审批、移动端 |
| 用可核实的数字做背书 | 12 个模块、1,000+ 项自动化测试、八类对账零差异、AGPL 开源 |
| 留白大、层级清楚、颜色克制 | 白底与浅灰大圆角面板交替；主色只用于按钮、链接、图标和重点数字 |
| 页面底部固定一个强行动区 | 蓝色渐变圆角行动区（带 logo 水印）：在线演示 / 快速开始 / GitHub |

主色与产品一致（《UI 设计规范》2.0.0）：`#165DFF`，按钮和数据条用 `#2A68FF → #0F55F5` 的轻微纵向渐变。官网比管理端更舒展：

- **水印标志**：`assets/logo.svg`，蓝底圆角方块内的白色「7」和纸箱，用于首页数据条和导航下拉面板的水印。
- **官网图标与吉祥物**：`assets/mascot.svg`，使用从印有「7」的纸箱里探头的橘猫，显示在导航、页脚和浏览器标签页，也用于品牌故事、行动区、演示页、404 页和分享图。
- **圆角四档**：控件 10–12px（按钮、标签、分段控件）、小卡片 16–18px（模块卡、下拉项）、卡片 20–24px（场景卡、对话框）、整块面板 32px（浅灰区块、AI 深色区、行动区，手机端 24px）。
- **字号**：首屏标题 68px（手机 38px）、区块标题 40px（手机 28px）、正文 16px；标题字重统一 700（微软雅黑没有 800），负字距不超过 -0.025em，`text-wrap: balance`。
- **背景**：首屏为淡主色网格加缓慢漂移的光晕；不用 3D 插画和大面积紫色渐变。
- **对比度**：辅助文字 `#636B78`，在白底和 `#F5F7FB` 上都 ≥ 4.5:1；蓝色背景上的文字一律纯白。

### 2.1 动效

| 动效 | 位置 | 说明 |
|---|---|---|
| 逐行入场 | 首屏 | 公告、标题、副标题、按钮、截图依次淡入上移 |
| 浮动卡片 | 首屏截图两侧 | 收款已核销、库存已预留、AI 回答附出处，缓慢上下浮动 |
| 跑马灯 | 技术栈条 | 悬停暂停，两端渐隐 |
| 滚动入场 | 各区块 | 进入视口淡入上移，同组卡片依次出现，只触发一次 |
| 流程光圈 | 业务闭环 | 光圈依次经过每个步骤，示意单据流转 |
| 流光 | AI 流程条 | 一道光沿连线移动 |
| 描边高光 | AI 能力卡 | 边框随鼠标位置发亮 |
| 数字滚动 | 统计条 | 从 0 滚到目标值 |
| 条形图展开、高亮刷入 | 应收示意、Wiki 修订、体检清单 | 进入视口时播放 |
| 探头与眨眼 | 品牌故事、行动区的吉祥物 | 猫和爪子从箱子里上下探头，箱子不动；每 5.5 秒眨一次眼 |
| 截图轮播 | 界面一览 | 每 6 秒切换一张，滑块底部有进度条；悬停、聚焦、离开视口时暂停 |

全部用 CSS 和 `IntersectionObserver` 实现，不引入动画库；只用 `transform` 和 `opacity`；系统开启“减少动态效果”时全部关闭、内容直接显示（已用 Edge `--force-prefers-reduced-motion` 实测）。区块用 `data-anim` 标记，离开视口时暂停其中的循环动画，一次性的入场动画不受影响。

### 4.2 英文首页

内容在 `content/home.en.ts`，区块与中文首页一一对应，另加一个“Get started”区块（`HomeGetStarted.vue`）。写法：

- **改写而不是直译**：首屏标题为 “Orders, stock and accounts / that always reconcile”，突出“账对得上”；中文直译太长，放不下首屏。
- **术语与 README 英文部分一致**：receivables、payables、delivery confirmation、payment matching、reconciliation checks、close or reopen accounting periods、voucher。
- **如实说明语言**：产品界面目前只有简体中文，截图区说明一句，常见问题里专门回答；链到中文文档或中文页面时，链接文字带 “(Chinese)” 并加 `hreflang="zh-CN"`。
- **Get started**：两张卡，“Install the 2.0 preview”（发布页 + SHA-256 校验）和 “Run from source on Windows”（与中文快速开始相同的命令）。
- **公司名用拼音化的虚构名称**（Linjiang Supply、Nanhu Hardware、Qinghe Foods），金额保留人民币符号。
- **结构化数据与分享信息**：`og:locale` 为 `en_US`，`alternateName` 为“柒衡 ERP”；中英文首页互相声明 `hreflang`，`x-default` 指向中文首页。
- 导航、页脚、按钮等公共文案在 `src/content/chrome.ts` 的 `en`；资源路径统一由 Vite 的 `base` 和 `utils/assets.ts` 处理。

### 4.1 AI 能力宣传口径

AI 是 2.0 最有辨识度的部分，首页单独用一个深色区块（`AiBand.vue`），并有独立详情页 `/features/ai`。只写 `erp-ai` 已实现、可在代码里找到的能力：

| 能力 | 官网说法 | 代码依据 |
|---|---|---|
| 混合检索 | 关键词 + 向量（bge-m3）双路召回，RRF 融合；可选 OpenSearch 或内置检索 | 检索服务的 RRF 融合与检索模式配置 |
| 重排 | bge-reranker 重排，低于阈值的片段不进入回答 | 重排模型与最低分配置 |
| 带引用回答 | 结论标注来源；无依据时明确拒答 | 回答引用与拒答逻辑 |
| LLM Wiki | 模型起草或修订主题页，管理员发布、驳回、归档；每周体检数值矛盾、来源失效、断链、孤立页、半年未访问；源文档换版后相关页排队重新起草 | `WikiService` 审核与 lint、`WikiEnrichment` 补充队列 |
| 智能查数 | 只读业务工具，以提问人身份调用，权限照常生效 | 业务只读工具 |
| 单据解释 | 解释不能发货、关账未通过等原因并给处理入口 | 单据解释接口 |
| 门户客服 | 识别客户意图，只答本单位数据，转人工工单 | `/internal/portal-intent` |
| 模型管理 | OpenAI 兼容接口和 Anthropic；路由、限额、调用日志、评测；境外模型需部署开关和管理员确认 | 模型网关、`allow-overseas` 配置 |

不写：AI 录单（尚未实现）、具体准确率数字（评测结果随模型变化）、“替代人工”一类说法。AI 示例对话中的金额和单号均为虚构演示数据。上线前按代码复核一次此表。

## 5. 演示系统跳转（预留接口）

### 5.1 配置

演示地址在**构建时**通过环境变量注入，代码中不写死：

| 变量 | 示例 | 说明 |
|---|---|---|
| `VITE_DEMO_URL` | `https://demo.example.com/` | 演示 ERP 登录页地址，必须是 `https:`；为空表示演示环境未开放 |
| `VITE_DEMO_TENANT` | `DEMO` | 演示企业编码，展示在跳转页上（可选） |
| `VITE_DEMO_NOTE` | `演示数据每天 03:00 重置` | 跳转页上的说明文字（可选） |

- 本地开发写在 `qiheng-website/.env.local`（已被 `.gitignore` 忽略）；GitHub Pages 构建在仓库 Settings → Secrets and variables → **Variables** 中配置（不是 Secrets，因为地址本身会出现在页面上）。
- **不在官网上展示演示账号的密码**。演示系统应提供“访客一键进入”或只读演示账号，由演示系统自己负责；官网只负责跳转。

### 5.2 行为

```ts
// qiheng-website/src/config/demo.ts（实际代码另有 parseDemoConfig 便于单测，并导出 demoTarget 附加 ?from=website）
export interface DemoConfig { url: string | null; tenant: string | null; note: string | null }

export function demoConfig(): DemoConfig {
  const raw = (import.meta.env.VITE_DEMO_URL ?? '').trim()
  let url: string | null = null
  if (raw) {
    const parsed = new URL(raw)          // 构建时校验，格式不对直接构建失败
    if (parsed.protocol !== 'https:') throw new Error('VITE_DEMO_URL 必须使用 https')
    url = parsed.toString()
  }
  return { url, tenant: import.meta.env.VITE_DEMO_TENANT || null, note: import.meta.env.VITE_DEMO_NOTE || null }
}
```

- 所有“在线演示”按钮统一链接到站内 `/demo`，不直接写外部地址，以后换演示地址只改一个变量。
- `/demo` 页面：
  - 已配置：显示“即将前往柒衡 ERP 演示系统”、演示企业编码、说明文字和“立即前往”按钮，3 秒后自动跳转（尊重 `prefers-reduced-motion` 时不自动跳转），外链加 `rel="noopener"`；
  - 未配置：显示“演示环境正在准备中”，提供“查看界面截图”“本地快速体验”两个替代入口；导航和首屏的“在线演示”按钮改为次要样式并带“筹备中”标记。
- 跳转时附带来源参数 `?from=website`，演示系统可据此统计来访，官网本身不做统计。

## 6. 技术方案

### 6.1 选型

| 项 | 选择 | 说明 |
|---|---|---|
| 框架 | Vue 3.5 + TypeScript 5.9（`strict`）+ Vite 7 | 与 `erp-web` 一致，依赖版本对齐 |
| 路由 | vue-router 4 | 页面按路由懒加载；锚点滚动在 `router/scroll.ts` 统一处理 |
| 静态预渲染 | vite-ssg 28 | 构建时把每个路由预渲染成 HTML（`dirStyle: nested`）：搜索引擎能收录；GitHub Pages 刷新子页面不会 404 |
| 页面元信息 | `@unhead/vue`（随 vite-ssg 安装） | `hooks/useSeo.ts` 统一输出标题、描述、规范地址、`hreflang`、Open Graph 和结构化数据 |
| 样式 | 原生 CSS + CSS 变量（令牌同 UI 规范 2.0） | 设计稿样式按原顺序拆成 7 个文件；不引入组件库 |
| 多语言 | 带类型的内容文件 | 没有用 vue-i18n：首页文案是成段的营销内容，中英文是改写而不是逐句对应，按 `HomeContent` 接口各写一份更直观；缺字段时编译期报错，也少一个运行时依赖 |
| 图标 | `AppIcon.vue` + `icons.ts` | 24×24、1.7 描边的线性图标，与产品风格一致 |
| 测试 | Vitest + @vue/test-utils（jsdom） | 演示配置校验、工具函数、入场动效、中英文内容一致性与站内链接、关键组件 |
| 统计 | 不加 | 页脚声明不使用 Cookie 和统计脚本 |

不引入 UI 组件库、动画库、第三方字体和第三方脚本。

### 6.4 SEO 与性能

- 每页设置 `title`、`description`、`canonical`；首页标题“柒衡 ERP — 开源进销存与业财一体化系统”。
- 构建结束时按 `config/site.ts` 的页面列表生成 `sitemap.xml`；中英文首页互相声明 `hreflang`。`robots.txt` 只有放在域名根目录才会被读取，部署在 `qingyu6688.github.io/qiheng-erp/` 时不生效，演示页和 404 页靠页面内的 `noindex` 排除。
- 每页输出 Open Graph 与 Twitter 卡片信息，分享图 `og.png`（1200×630，含标志、标题和吉祥物）；首页加 `SoftwareApplication` 结构化数据。
- 实测（2026-11-18 构建）：首页首屏 JS 压缩后约 79KB（公共包 55.7KB + 首页 23.5KB），在 80KB 目标内；CSS 13KB。首屏截图 `fetchpriority="high"`，其余图片懒加载并用 `srcset` 按屏幕密度选图。
- 社区数据（星标、贡献者）目前数量太少，暂不展示；以后由构建脚本在构建时从 GitHub API 拉取，不在访问者浏览器里请求第三方接口。

### 6.5 可访问性与响应式

- 断点：≥ 1200 三到四列，768—1199 两列，< 768 一列；1200 以下导航收进抽屉。
- 正文对比度 ≥ 4.5:1（6 个页面已用脚本逐个文字节点检查）；图片有替代文字；导航、页签、问答可键盘操作；尊重 `prefers-reduced-motion`；页面顶部有“跳到正文”链接。

## 7. 部署：GitHub Pages

1. 仓库 Settings → Pages → Source 选择 **GitHub Actions**；在 Variables 中配置 `VITE_DEMO_URL` 等（可先留空）。
2. 工作流 `.github/workflows/site.yaml`（官网发布）：
   - 触发：`main` 上 `qiheng-website/**` 或工作流本身变化、指向 `main` 的拉取请求，以及手动触发；
   - 构建：检出 → Node 24.9.0（npm 缓存）→ 在 `qiheng-website/` 下 `npm ci` → `npm run lint` → `npm test` → `npm run build`（读取仓库变量 `VITE_DEMO_URL`、`VITE_DEMO_TENANT`、`VITE_DEMO_NOTE`、`SITE_BASE`）→ `actions/upload-pages-artifact@v5`；
   - 发布：只在 `main` 上运行 `actions/deploy-pages@v5`，权限 `pages: write`、`id-token: write`，环境 `github-pages`；拉取请求只检查和构建，不发布；
   - 同一分支的发布排队执行，不中途取消。
3. 默认地址 `https://qingyu6688.github.io/qiheng-erp/`，构建默认 `base` 为 `/qiheng-erp/`；绑定自有域名时用 `SITE_BASE=/ npm run build`，在 `public/CNAME` 写域名，并修改 `config/site.ts` 的 `SITE_URL`、开启强制 HTTPS。
4. 国内访问：GitHub Pages 在国内访问不稳定。有自有域名并完成 ICP 备案后，把同一份 `dist` 同步到国内对象存储或 CDN，按线路分流；页面不引用国外字体和脚本。
5. 构建只读取 `qiheng-website/`，不读取 `.env`、`.local/` 和部署记录；发布前检查截图与文案中没有真实服务器地址、账号和客户信息（《优化文档》O-35）。
